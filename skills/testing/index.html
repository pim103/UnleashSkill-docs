    Testing a skill¶

    Three ways, from the quickest to the most complete.

    1. The preview in the editor¶

    Preview button of the graph editor. The skill plays next to the graph, in an isolated scene (a separate simulation world, which does not touch your scene), on a caster and dummies.

    Command Effect
    ⏮ Restart from the beginning
    ▶ Play / pause
    ⏭ Advance one tick
    Speed Slow down or speed up the playback
    Frame Recenter the camera on the caster and the targets
    Staging Number, layout and team of the dummies, 2D or 3D plane

    The preview restarts on every change to the graph. The world's bodies and searches are shown as an overlay.

    The Presentation menu has the same preview for a single definition (effect, sound, animation, module visual).

    2. In a scene¶

    Add the SkillTester component on a caster of your scene (see Set up a scene); the Link to scene button of the graph editor puts the open skill in its slot 0. In Play Mode:

    • Space casts slot 0, keys 1 to 9 cast slots 0 to 8;
    • the inspector of the SkillTester has the same commands (Cast skill, one button per slot), plus Reload skill graph, Stop all active skills and, in turn-based mode, Advance turn (one round: the caster, then each registered entity).

    Place enemies, allies and walls around the caster to try the skill in the situations of your game.

    UnleashSkill → Add Skill Preview to Scene creates a Skill Preview object (SkillPreviewController). Give it a Skill Graph: without playing anything, the Scene view draws the reach of the skill's modules from the object (or from its Caster Transform) and in its forward direction: spawn point of the module bodies, areas, beam range. The inspector chooses what is drawn, and Refresh preview redraws it.

    3. Automated tests¶

    A skill is plain data: it can be cast without a scene, in an EditMode test of the Unity Test Framework (Window → General → Test Runner), and its effects checked on the targets' stats. The engine pieces such a test relies on (simulation world, entities registered without colliders, execution without presentation) are described in Technical → Simulation world and Cast cycle.

    A complete test¶

    The skill tested here, Firebolt, is a Spell body (Movement: forward, 10 m/s) whose On hit (enemy, 1 target) deals 10 damage to the health stat with a Simple damage. The test assembly (.asmdef of your EditMode tests) references UnleashSkill.

    using System.Collections.Generic;
using NUnit.Framework;
using UnityEditor;
using UnityEngine;
using UnleashSkill;
using UnleashSkill.Configuration;
using UnleashSkill.Execution;
using UnleashSkill.PersistentDataModel;
using UnleashSkill.Simulation;
using UnleashSkill.SkillUtils;

public class FireboltTests
{
    const string Health = "health";
    const string Template = "test-template";

    SkillWorld world;
    UnleashSkillConfiguration previousConfiguration;
    readonly List<Object> created = new List<Object>();
    readonly List<SkillTarget> entities = new List<SkillTarget>();

    [SetUp]
    public void SetUp()
    {
        // 1. A world of its own, without scenery (a wall: World.AddBody on the Obstacle layer)
        world = new SkillWorld(new SimulationSettings { SceneryBackend = StaticSceneryBackend.None });
        UnleashSkillManager.ResetWorld(world);

        // 2. Active configuration: the stats and the stat template of the entities
        var configuration = Track(ScriptableObject.CreateInstance<UnleashSkillConfiguration>());
        var health = Track(ScriptableObject.CreateInstance<StatAsset>());
        health.Initialize(new CustomStat { uuid = Health, statsName = "Health", hasMaximumValue = true });
        configuration.StatAssets.Add(health);
        var template = new StatTemplate { uuid = Template, templateName = "Test" };
        template.floatStats[Health] = new StatInGame<float>
            { customStatUuid = Health, value = 100f, maxValue = 100f, originalValue = 100f };
        configuration.StatTemplates.Add(template);
        previousConfiguration = ConfigurationManager.ActiveConfiguration;
        ConfigurationManager.ActiveConfiguration = configuration;

        // 3. Pooler of the module bodies: in EditMode, AddComponent does not call Awake
        Track(new GameObject("SkillPooler")).AddComponent<SkillPooler>().Init();
    }

    [TearDown]
    public void TearDown()
    {
        foreach (SkillExecution execution in new List<SkillExecution>(UnleashSkillManager.ActiveSkillExecutions))
        {
            if (!execution.IsCompleted)
                execution.Cancel();
            execution.Cleanup();
            UnleashSkillManager.UnregisterActiveSkillExecution(execution);
        }
        foreach (SkillTarget entity in entities)
        {
            SkillEntityRegistry.Unregister(entity);
            entity.Stats?.StopRegeneration();
        }
        entities.Clear();
        foreach (Object obj in created)
            if (obj != null)
                Object.DestroyImmediate(obj);
        created.Clear();
        ConfigurationManager.ActiveConfiguration = previousConfiguration;
        UnleashSkillManager.ResetWorld(null);
    }

    [Test]
    public void Firebolt_HitsTheEnemyAhead_Deals10Damage()
    {
        SkillCaster caster = CreateEntity("players", Vector3.zero);           // faces +Z
        SkillCaster enemy = CreateEntity("monsters", new Vector3(0f, 0f, 5f));
        var skill = AssetDatabase.LoadAssetAtPath<SkillGraphModel>("Assets/Skills/Firebolt.asset");

        Assert.AreEqual(SkillCastResult.Success, caster.Cast(skill, out SkillExecution execution));
        RunUntilCompleted(execution);

        Assert.AreEqual(90f, enemy.Stats.GetStatValue(Health));
    }

    // Entity without a scene: Start and OnEnable do not run in EditMode
    SkillCaster CreateEntity(string team, Vector3 position)
    {
        var gameObject = Track(new GameObject(team));
        gameObject.transform.position = position;
        var entity = gameObject.AddComponent<SkillCaster>();
        entity.teamUuid = team;
        entity.ResetStats(Template);
        SkillEntityRegistry.Register(entity);
        entities.Add(entity);
        return entity;
    }

    // Without the manager's Update: the world advances one tick, then the execution does its frame
    void RunUntilCompleted(SkillExecution execution, int maxTicks = 1000)
    {
        for (int tick = 0; tick < maxTicks && !execution.IsCompleted; tick++)
        {
            world.Step();
            execution.Update();
        }
        Assert.IsTrue(execution.IsCompleted, "The execution did not end");
        UnleashSkillManager.UnregisterActiveSkillExecution(execution);
    }

    T Track<T>(T obj) where T : Object
    {
        created.Add(obj);
        return obj;
    }
}

    What each step does:

    • World: UnleashSkillManager.ResetWorld(world) makes it the world of the engine. Without scenery (StaticSceneryBackend.None), the colliders of the open scene are not read.
    • Configuration: the entities read their stats in the active configuration: one built by the test, as here, or your project's (AssetDatabase.LoadAssetAtPath<UnleashSkillConfiguration>). Without teams in the configuration, two different teamUuid are enemies.
    • Pooler: a module (Spell body, Area, Beam…) takes its object from the SkillPooler. In a scene, the UnleashSkillManager creates it; in a test, create it and call Init(). Without a pooler, the module logs an error and ends without its outputs.
    • Entities: Start and OnEnable do not run in EditMode. ResetStats(template) gives the stats, SkillEntityRegistry.Register adds the entity to the world. Without a collider, an entity is a capsule of 0.5 m radius and 2 m height.
    • Ticks: each world.Step() advances the simulation by one tick (bodies, hits, persistent nodes); execution.Update() then detects the end of the execution, as the manager does every frame.
    • Cleanup: between two tests, cancel the executions, remove the entities from the registry, destroy the objects, give back the configuration and the world. The statuses, cooldowns and regenerations started by a test stay tracked by the engine until they end: to isolate each test completely, or to test while a game runs in Play Mode, cast the skill in a SimulationSandbox (Technical → Static state and preview).

    The expected values are best read in the skill's nodes (DamageSimpleModel.Damage…) rather than written in the test: the test follows the tuning of the skill.

    Reading the module bodies of an execution¶

    To check where the module bodies of a skill go (directions of a Fork, spawn point, speed), read the bodies still running in the execution: each running module has an instance in SkillExecution.ActiveInstances, whose RuntimeData is a GameObjectRuntimeData (UnleashSkill.Nodes.Modules) and whose Body is the simulated body (ModuleBody).

    // Fork (Spread, 5 branches over 30°) → Spell body (Movement: forward, 10 m/s)
Assert.AreEqual(SkillCastResult.Success, caster.Cast(skill, out SkillExecution execution));
world.Step();

var angles = new List<float>();
foreach (ActiveNodeInstance instance in execution.ActiveInstances)
{
    if (instance.IsCompleted || !(instance.RuntimeData is GameObjectRuntimeData module) || !module.Body.IsAlive)
        continue;
    Vector3 direction = module.Body.Direction;      // unit vector
    Vector3 position = module.Body.WorldPosition;
    angles.Add(Vector3.SignedAngle(Vector3.forward, direction, Vector3.up));
}
angles.Sort();   // -15, -7.5, 0, 7.5, 15
    • WorldPosition and WorldVelocity (units per second) are the body's position and velocity as Vector3, while it lives (IsAlive). Direction is the direction of its velocity, or the module's orientation when it does not move (area, beam, body not yet moved).
    • Position, Velocity and Rotation are the same values in Unity.Mathematics types (float3, quaternion): an assembly that reads them adds Unity.Mathematics to the references of its .asmdef. The Vector3 accessors need only UnleashSkill.
    • A body exists from the module's start until its end: read it between two world.Step(), before RunUntilCompleted.

    To compare the same skill with and without its visual, choose the Visual of a Spell body from code: new GameObjectModel().WithVisual(definition) (or the definition's UUID, null for an invisible body). The definition is looked up in the active presentation library (PresentationLibrary.Active) when the module starts; one created in the test is added with library.Add(definition).

    Walls and variants of a skill¶

    A wall of the test is a body of the Obstacle layer added to the world. Shape.Box(x, y, z) (half-sizes as float), WorldPosition and WorldRotation (Vector3, Quaternion) need only UnleashSkill in the test assembly. Shape.Box(float3) and the Position / Rotation fields are the same values in Unity.Mathematics types; there is no Shape.Box(Vector3), because an overload next to Box(float3) would require Unity.Mathematics to compile the call.

    using UnleashSkill.Simulation.Collision;

// Wall 4 m wide and 0.5 m thick, 3 m in front of the caster, turned by 30°
world.AddBody(new Body
{
    Layer = SimulationLayers.Obstacle,
    Shape = Shape.Box(2f, 2f, 0.25f),   // half-sizes
    WorldPosition = new Vector3(0f, 0f, 3f),
    WorldRotation = Quaternion.Euler(0f, 30f, 0f),
    Active = true
});
    • Whether the wall stops a module body depends on the layer matrix (Skill / Obstacle: Block by default) and on the Blocked By Obstacles of the On hit that listens to the body.
    • A body left without a rotation is not rotated. Shape.WithOffset(x, y, z) moves the shape in the body's frame.

    To try a variant of a skill (stopped by obstacles, more targets, re-hit), change a copy of its graph from code, never the asset: WithHitPolicy and WithTargetFilter replace the Hit Policy and the Target Filter of an On hit (UnleashSkill.Nodes.Conditions).

    SkillGraphModel blocked = Object.Instantiate(skill);   // the asset stays as it is
var onHit = (OnHitModel) blocked.Nodes.Find(node => node is OnHitModel);
HitPolicy policy = onHit.HitPolicy;
onHit.WithHitPolicy(new HitPolicy(policy.MaxTargets, policy.Rehit, policy.RehitCooldown,
    ObstacleBlocking.Yes, policy.RequireLineOfSight));   // Blocked By Obstacles: Yes

Assert.AreEqual(SkillCastResult.Success, caster.Cast(blocked, out SkillExecution execution));

    Destroy the copy at the end of the test (Object.DestroyImmediate, or Track in the complete test above). Other nodes have the same methods for construction from code (AreaModel.WithLineOfSight, GameObjectModel.WithVisual…).

    Reproducible rolls¶

    The random rolls of an execution come from its own generator (SkillExecution.Random): Chance, Random choice, Check condition by chance, random sort of a Target selection or of a Chain, Fork in a random pattern, Random Angle of a Fork, random Direction, wander of a Movement or a Line segment, random range of a Delay, critical hits, Random() in a formula. By default, its seed comes from the execution's identifier, unique to each cast: two casts roll differently.

    To replay the same rolls (a test, a replay), set the seed before the first node, through the cast options:

    var options = new SkillCastOptions
{
    InitializeContext = context => context.Execution.SetRandomSeed(42)
};
skill.TryCompute(caster, out SkillExecution execution, options);

    Two executions with the same seed, the same graph and the same situation roll the same values. The presentation (camera shakes, effects) does not use this generator.
