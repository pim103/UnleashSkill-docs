    Architecture¶

    Assemblies¶

    The whole framework is under Assets/UnleashSkill/, the only folder of the asset.

    Assembly Platform Folder Role
    UnleashSkill All Assets/UnleashSkill/Runtime/ Node models, execution engine, simulation, presentation, configuration, localization
    UnleashSkill.Editor Editor Assets/UnleashSkill/Editor/ Graph window (GraphView), editor nodes, main menu, inspectors, preview, language preference
    UnleashSkill.Cinemachine All Runtime/Presentation/Cinemachine/ Shake through Cinemachine, compiled only if the Cinemachine 3 package is present (versionDefines → UNLEASHSKILL_CINEMACHINE, defineConstraints)

    Dependencies: UnleashSkill.Editor → UnleashSkill. Required packages: Burst, Mathematics, uGUI. Optional packages, detected by the asmdef's versionDefines: Addressables (UNLEASHSKILL_ADDRESSABLES, SkillGraphLoader), Input System (UNLEASHSKILL_INPUT_SYSTEM, SkillTester), Cinemachine 3 (UNLEASHSKILL_CINEMACHINE, separate assembly). An asmdef reference to a missing package is ignored by Unity: the code that uses it is under its define. No render pipeline required. Your own code references UnleashSkill (and UnleashSkill.Editor for editor code) from its asmdef.

    No editor dependency in the runtime: a use of UnityEditor in UnleashSkill is wrapped in #if UNITY_EDITOR.

    No hard-coded Assets/... path in the framework: the asset can be moved in the user's project.

    • The interface files (uxml, uss of Editor/UI/) are found by GUID: UnleashSkillEditorAssets. The translation tables (Editor/Localization/*.po) are found through the GUID of their folder (EditorLocalization.TablesFolderGuid).
    • The user's data goes to the data folder, UnleashSkillDataFolder.Path: project setting (Project Settings → UnleashSkill, file ProjectSettings/UnleashSkillSettings.json), Assets/UnleashSkillData by default. The presentation library is in its Presentation/ subfolder (PresentationLibrary.DefaultFolder).

    Namespaces¶

    Namespaces follow the folders, under the UnleashSkill root:

    Folder Namespace
    Runtime/Core/ UnleashSkill (manager, caster, targets, UnleashSkillVersion, DataFormat); subfolders: UnleashSkill.Conditions, .ListenerData, .PersistentDataModel, .SkillUtils, .Stats, .Utils, .Weapons (SkillPrefab/ stays in UnleashSkill)
    Runtime/Execution/ UnleashSkill.Execution (NodeModel, SkillGraphModel, SkillExecution, context, NodeType, PortType)
    Runtime/Nodes/[Category]/ UnleashSkill.Nodes.[Category] (Actions, Behaviors, Conditions, Modules, Supports, Triggers, Utils), plus UnleashSkill.Nodes.Attributes and UnleashSkill.Nodes.Targeting
    Runtime/Simulation/ UnleashSkill.Simulation (scenery included), UnleashSkill.Simulation.Collision
    Runtime/Presentation/ UnleashSkill.Presentation (backends and Cinemachine included)
    Runtime/Configuration/ UnleashSkill.Configuration
    Runtime/Localization/ UnleashSkill.Localization (Localizer, LocalizationTable, NodeText)
    Runtime/Preview/ UnleashSkill.Preview
    Editor/[Folder]/ UnleashSkill.Editor.[Folder]: Graph (window, EditorNode), Graph.Nodes.[Category] (editor nodes), Graph.Ports, Inspectors, Localization, Migration, Presentation, Preview, PropertyDrawers, UI, Windows, Windows.Modern

    A type that a model needs (enum, struct) goes in Runtime/, never in Editor/.

    In a UnleashSkill.* namespace, a simple name that is also a sibling namespace (Execution, Simulation, Presentation, Localization, Editor…) refers to the namespace: qualify the member (context.Execution) or the type (UnityEditor.Editor). The public API therefore has no type named like a framework namespace, nor like a common UnityEngine type (hence SimulationProfileStage, not SimulationStage). What is public, internal, and the extension points: Extension points.

    What lives where¶

    Assets/UnleashSkill/Runtime/:

    Folder Contents
    Core/ UnleashSkillManager (global singleton), SkillCaster, SkillTarget, SkillSlots, combos; Stats/ (EntityStats), SkillUtils/ (SkillPooler), SkillPrefab/, Conditions/, Weapons/, PersistentDataModel/
    Execution/ NodeModel, SkillGraphModel, SkillExecution, SkillExecutionContext, ValueSource, ValueFormula, StartNode, NodeType, PortType, SkillGraphLoader…
    Nodes/[Category]/ One model per node: Actions, Behaviors, Conditions, Modules, Supports, Triggers, Utils; Targeting/ (aim, anchors, directions, selection); Attributes/ (NodeInfo, ExposedProperty…)
    Simulation/ SkillWorld, clock, entities, statuses, damage pipeline, events, SimulationSandbox; Collision/ (core, Burst CollisionKernel); Scenery/ (static scenery: Physics 3D, 2D, none)
    Presentation/ Commands, library, definitions, PresentationSystem; Backends/: default implementations
    Configuration/ UnleashSkillConfiguration, ConfigurationManager, ConfigurationData, UnleashSkillDataFolder, configurable definitions (statuses, events, reactions…)
    Localization/ Interface language: Localizer (current language, Tr), gettext tables, node texts
    Preview/ Preview (SkillPreviewManager, SkillPreviewEntity), SkillTester

    Assets/UnleashSkill/Editor/:

    Folder Contents
    Graph/ Graph window (NodeEditor), NodeGraphView, EditorNode, DefaultEditorNode; Nodes/[Category]/: editor nodes; Ports/
    UI/ uxml, uss; UnleashSkillEditorAssets
    Localization/ Translation tables (fr.po), table loading, Preferences → UnleashSkill page
    Windows/ Main menu (UnleashSkillMainMenu), configuration panels (Modern/), Project Settings page, default data of a new project (UnleashSkillDefaultData)
    Presentation/, Preview/, PropertyDrawers/, Inspectors/, Migration/ Presentation editing, preview in the editor, drawers, inspectors (SkillCaster, SkillTester), migration menus

    Central objects¶

    Object Role
    UnleashSkillManager Scene singleton and static facade: world (World), presentation (Presentation, PresentationCommands), active executions, legacy data
    SkillGraphModel The skill: nodes, connections ([SerializeReference]), settings (cost, cooldown, cast time, tags). Entry point TryCompute
    SkillExecution One cast: active instances, randomness (ExecutionRandom), cast time, cancellation
    SkillExecutionContext One branch of the execution: targets, aim (Aim), branch data, access to shared data
    SkillAim, SkillAnchor, SkillDirection Aim frozen at cast; single vocabulary of the nodes' positions and directions (Runtime/Nodes/Targeting/)
    SkillWorld Fixed-step simulation world
    PresentationSystem Consumes the presentation commands after the simulation
    Localizer Interface language: English source in the code, other languages from tables, switched without recompiling

    What is serialized with the assembly name¶

    The name UnleashSkill is written into the data:

    • graphs (skill .asset) store their nodes through [SerializeReference], with type: {class: …, ns: …, asm: UnleashSkill};
    • status behaviors (StatusDefinition.behaviors) are also [SerializeReference].

    Consequences:

    • Never rename the UnleashSkill assembly, nor move a serialized type (model, behavior, field struct) to another assembly.
    • Renaming or moving a class serialized by reference (subtype of NodeModel or StatusBehavior): add [MovedFrom(true, sourceNamespace: "…", sourceClassName: "…")] (UnityEngine.Scripting.APIUpdating) with the old name, and never remove it within the same major version.
    • A piece of data whose shape changes goes through the format number (see Data).
    • The rid of the references of a hand-written .asset must fit in a signed int64 (see Data).
    • A node's displayed title and tooltips are not part of its identity: they are translated at display time (NodeText), the class name and field names are what the data stores.
