    Cast cycle¶

    User version: Running a skill. Here, the path in the code.

    Overview¶

    SkillCaster / SkillSlots / game
        │
        ▼
SkillGraphModel.TryCompute(caster, out execution, options)
        │  CheckCast: valid graph, locks, cooldown, cost
        │  new SkillExecution(graph, caster)       ← root context
        │  PayCost, StartCooldown
        │  UnleashSkillManager.RegisterActiveSkillExecution
        ├── cast time? execution.BeginCast / BeginChargedCast
        │              (Start's “During cast” output, IsCastPhase branch)
        └── otherwise: GameEvents.RaiseSkillCast, then ExecuteNodeAndChain(StartNode)

Each world tick (step 6b)                        Each frame (manager Update)
  ExecutionStepper → execution.Step(clock)         execution.Update()
    cast time, hold                                  node.OnRuntime (visual only)
    node.OnSimulationStep(…, clock)                  AreAllNodesCompleted → IsCompleted
                                                     → execution.Cleanup(), removed

    Cast: SkillGraphModel.TryCompute¶

    TryCompute(caster, out execution, options) (Runtime/Execution/SkillGraphModel.cs):

    1. CheckCast returns a SkillCastResult: InvalidGraph (not exactly one StartNode, a node whose type no longer exists, or a graph from before the first release; checked before the cost and the cooldown, logged once per skill), ActionLocked, SkillBlocked (status that blocks a tag of the skill), AttackInProgress (attack in a non-cancelable phase), OnCooldown, InsufficientResource. Only Success casts.
    2. A new action cancels the caster's attacks that can still be canceled (AttackCancellation.CancelAttacks).
    3. new SkillExecution(this, caster) creates the execution and its root context. SkillCastOptions.InitializeContext can write to it before release (imposed target, values).
    4. Cost taken and cooldown started at cast, hence at the start of the cast time (refunded if it is canceled: RefundLaunch).
    5. The execution is registered in the manager, then starts: directly, or through the cast time.

    SkillCastOptions covers the special cases with its flags (PayCost, CheckCooldown, StartCooldown, CheckLocks, Passive): ForPassive() (passive slot: no cost, no cooldown, no lock), free recast, skill cast by another skill (CastSkillModel). Compute(caster) is a shortcut that ignores the reason for a refusal.

    Starting a node: the engine never fires the outputs¶

    ExecuteNodeAndChain (private) registers the instance then calls OnStart, nothing else:

    var instance = new ActiveNodeInstance(node, null, caster, context);
instance.StartTick = UnleashSkillManager.TickInProgress;
execution.AddActiveInstance(instance);          // before OnStart: an instant node can complete inside it
execution.BeginNodeStart();
try { instance.RuntimeData = node.OnStart(caster, context); }
catch (Exception exception) { execution.Fail(exception, instance); }   // see Errors below
finally { execution.EndNodeStart(); }   // end of the outermost start: deferred actions (SkillExecution.Defer)

    Deferred actions serve the instant resolution of turn-based mode: a query on the selection returns its result after the OnStart that queued it, never during it. In turn-based mode, TryCompute ends the execution without waiting for a tick if all its nodes are done (CompleteIfResolved).

    The node fires its outputs:

    Call (SkillExecution) Effect
    CompleteNodeInstance(node, caster) Ends the node's most recent instance and fires all its outputs
    CompleteNodeInstance(node, caster, runtimeData) Same, for the exact instance that carries this runtimeData (several simultaneous instances of the same node)
    CompleteNodeInstanceWithoutOutputs(node, caster) / (node, runtimeData) Ends without firing: failure, false condition, module whose outputs are listeners
    ExecuteChainedNodes(node, caster, context) Fires the outputs without ending: a listener, on each event
    ExecuteChainedNodes(node, caster, context, portType, rank) Fires a single output (true / false of a condition)
    ExecuteChainedNodes(node, caster, context, filter) Fires the outputs whose port passes the filter (the Start leaves out “During cast”)

    A node that does neither blocks the chain: its instance stays active and the execution never ends.

    Branches: SkillExecutionContext¶

    Each time outputs are fired, each chained node receives sourceContext.CreateBranch():

    Copied per branch (the child inherits, sisters do not see each other) Shared by the whole execution (SharedState)
    Targets Caster, Execution
    MainSkillPrefab, MainBody SetData / GetData data
    ImpactPoint, ImpactNormal, Aim StartTime
    Branch data SetBranchData / GetBranchData

    Named branch data: BranchDirection (Fork Spread / Circle, read by modules and the Movement), BranchSpawnPoint, BranchDamageMultiplier (multiplied by Fork, Chain, Multiply damage; applied by the damage nodes), BranchMarks (marks such as “Critical”, applied by Mark branch), IsCastPhase, SpellTargets (targeted skills), the source listeners (listener anti-loop).

    Aim (SkillAim, context.Aim): frozen by the execution at cast (end of the cast time included) from caster.PointedTarget, or given by the caller (SkillCastOptions.Aim, SkillExecution.SetAim: AI, code, server). It carries the aim point (Point, null if nothing is aimed at), the direction from the caster toward this point (Direction), the pointed entity (Entity) and the caster's position (Origin). The Aim node (Targeting) replaces the one of its branch (SetAimPoint).

    Anchors and directions: a position configured on a node is a SkillAnchor (caster, aim point, received target, each received target, module body, impact point, named object; offset in the aim frame, max range), a direction a SkillDirection (toward the aim point, caster forward, toward the received target, away from the caster, random; branch direction takes priority, angle offset). A single resolution: SkillAnchor.Resolve / TryResolve, SkillDirection.Resolve(caster, context, anchor). The field limits the sources offered with [AnchorSources] / [DirectionSources]. A direction defaults to toward the aim point, for a node created in the editor as for one built from code.

    Rules:

    • A node never reads caster.PointedTarget: it reads context.Aim. Only the Aim node and the channeled beam (“Follow the live aim” option) read the mouse again, through SkillAim.Live.
    • A position or a direction configured on a node is a SkillAnchor / SkillDirection, never a new enum.
    • A node reads and filters the targets of its context, never those of another branch.
    • Fire your outputs with the context received (ExecuteChainedNodes(this, caster, context)).
    • An event node adds the event's target to a dedicated branch (context.CreateBranch()), not to its own context (otherwise targets accumulate from one event to the next).
    • A module writes its prefab and its body in its branch (context.MainSkillPrefab, MainBody), which its listeners receive.
    • SetData is for skill variables (Store value) and shared values. Data specific to a branch goes in SetBranchData.

    During the execution¶

    • World tick (SkillWorld, step 6b): ExecutionStepper calls execution.Step(clock) on each active execution. Step advances the cast time and the hold at the caster's pace, then calls OnSimulationStep on each active instance that did not start during this tick (StartTick). This is where persistent nodes outside modules count.
    • Turn (turn-based, SkillCaster.AdvanceTurn): execution.AdvanceTurn() advances a cast started in turn-based mode by one turn (CastInTurns; the world tick no longer advances it) and fires the skill on the turn that reaches its duration, then calls OnTurnAdvanced on each active instance that did not start during this turn.
    • Module bodies: advanced at step 2 of the tick (OnBodyStep, see Writing a node).
    • Frame (UnleashSkillManager.Update): execution.Update() calls OnRuntime (visual only), then marks the execution completed if all its instances are and it is no longer casting.

    End of execution¶

    AreAllNodesCompleted(): no active instance. Listeners (On event, On tick), flying modules and persistent nodes keep it alive. A completed execution is cleaned up (Cleanup: OnEnd of the remaining instances, stop of the tracked presentation) and removed in the same Update.

    The effects applied to a target (status, burn) live in the target's StatusContainer, not in the execution: the Fireball ends on impact, the burn goes on.

    Cancellation¶

    SkillExecution.Cancel():

    1. Marks IsCanceled; during the cast time, refunds the cost and resets the cooldown (RefundLaunch), likewise during an aim.
    2. Marks all instances completed, then calls their OnEnd, most recent first (listeners before their module).
    3. Stops the tracked presentation (StopAllPresentation).

    After Cancel, a late CompleteNodeInstance or ExecuteChainedNodes (callback) is ignored, and ExecuteNodeAndChain no longer starts anything.

    Who cancels:

    Call Case
    SkillCaster.CancelSkill(graph) / UnleashSkillManager.CancelSkillExecutions The game interrupts an aura, a channeling
    SkillCaster.CancelSlot(slot) Cancellation by slot
    SkillCaster.CancelSkillsOnDeath() Death or disabling of the caster; spares the skills whose CancelOnCasterDeath is false (passives are always canceled)
    SkillExecution.Interrupt() Interrupted cast (hit taken, stun depending on InterruptionMode)
    CancelTargeting() Aim canceled: the Targeting node reads the request (ConsumeTargetingCancel), refunds the cost and ends without outputs (it is not a Cancel)

    Hold() / Release() cancel nothing: they change IsHeld, which the nodes that use it read at their step (Beam stopOnRelease, charge).

    The effects already applied remain; modules remove their body in their OnEnd.

    Errors: exceptions and loops¶

    An exception thrown by a node cancels its execution, and only it. The engine catches it around each call into node code: OnStart (in ExecuteNodeAndChain), OnSimulationStep, OnTurnAdvanced and OnRuntime (per instance), a module's body step, impacts and listeners (ModuleBody), the result of a node's query, a deferred action, an On event handler. It then:

    1. logs it (Debug.LogException, with the skill as context);
    2. ends the failing instance without outputs;
    3. cancels the execution (Cancel), which keeps the first exception in SkillExecution.Fault.

    The other executions, the rest of the tick (statuses, cooldowns, regeneration, combos, locks, movements, history) and the turn manager go on: TurnReady is still raised, since a canceled execution is completed. An exception thrown by an OnEnd during a cancellation is logged and does not prevent the other instances from ending.

    The world isolates its own listeners the same way (IBodyStepListener, IQueryListener, IBodyHitListener, IWorldStepListener): an exception goes to SkillWorld.ExceptionHandler (Debug.LogException by default) and the tick goes on with the next listener. The subscribers of GameEventBus, ExecutionStarted, ExecutionEnded and TurnReady are called one by one: one that throws is logged and the others are still called.

    A loop of instant nodes is stopped. A node that starts its outputs during its own OnStart (instant node, Delay of 0, first fire of a Repeat) nests the starts: a loop of such nodes would never end. Beyond SkillGraphModel.MaxStartDepth (256) nested starts, all skills included (Cast skill), the engine logs an error, refuses every start until the outermost one returns, and cancels the executions involved. The flow analysis warns before: W115 on each node of the loop (NodeModel.StartsOutputsDuringStart), and the editor refuses to connect a node to itself.

    A node that never completes (it returns no runtimeData without calling CompleteNodeInstance) keeps its execution alive forever: in the editor and in a Development Build, the execution reports it once after SkillExecution.StuckInstanceDelay seconds.
