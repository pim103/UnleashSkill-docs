    Data¶

    User version: Configuration.

    Active configuration¶

    • UnleashSkillConfiguration (Runtime/Configuration/UnleashSkillConfiguration.cs, ScriptableObject) contains everything configurable: stats (StatAssets), damage types, teams, tags, entity types, stat templates, reactions and reaction profiles, branch marks, statuses and categories, custom events, skill tags, simulation settings (Simulation), GameplayMode.
    • ConfigurationManager.ActiveConfiguration (static) is the configuration read by the engine. At runtime, UnleashSkillManager loads its defaultConfiguration on initialization; without it, the active configuration is reset to null (as in a build): no configured data. In the editor, it is the one chosen in the main menu (failing that, the project's: the first configuration of the data folder, otherwise of the project, which also fills the defaultConfiguration of a manager added by hand in the editor: UnleashSkillDefaultData.AssignProjectData, on ObjectFactory.componentWasAdded; not through Reset(), which Unity also calls for an AddComponent from code).
    • Default data (Editor/Windows/UnleashSkillDefaultData.cs): on the first opening of the editor (once per session, not in batch mode), a project without any configuration receives one in the data folder (UnleashSkillConfiguration.asset: teams Player and Enemy, type Character, stats HP, Mana, Attack under Stats/, template Default); without a presentation library, an empty one is created under Presentation/; without a trajectory library, an empty one is created (TrajectoryLibrary.asset). Nothing is overwritten.
    • PresentationLibrary.Active and TrajectoryLibrary.Active (global, shared by all configurations) are assigned by the manager; when null, the editor takes the library of the data folder (UnleashSkillDefaultData.ProjectPresentationLibrary / ProjectTrajectoryLibrary). The build gives these same libraries to the scene managers whose field is empty (UnleashSkillBuildLibraries, IProcessSceneWithReport, built copy only) and warns if the project has none; a manager that starts without a library warns.

    Skill graphs in a build¶

    • A graph referenced by a serialized field (a SkillGraphModel field of your script, the slots of a SkillCaster) is included in the build by Unity like any referenced asset: nothing to do.
    • A graph looked up by name goes through SkillGraphLoader (SkillGraphLoader.Instance.GetSkillGraph(name), GetAllGraphs()), which loads every graph when it starts:
      • without the Addressables package: the graphs of the Resources folders (Resources.LoadAll), at once;
      • with Addressables installed, the loader switches to the graphs that carry the SkillGraph Addressables label, loaded asynchronously (IsLoaded becomes true at the end). Resources folders are no longer read: installing Addressables in a project that kept its graphs in Resources empties the loader until the graphs are marked Addressable with the SkillGraph label (and the Addressables content built).
    • The configuration and the presentation and trajectory libraries are referenced by the scene's UnleashSkillManager (see above), never loaded by path.

    Read data: ConfigurationData¶

    Always go through ConfigurationData (Runtime/Configuration/ConfigurationData.cs): GetTeam, GetEntityType, GetStat, GetStats, GetDamageType, GetTag, GetStatTemplate, GetReaction(s), GetBranchMark(s), GetEvent(s) (natives included), GetSkillTag(s), GetStatus(es), GetStatusCategory(ies), GetReactionProfile.

    • The active configuration is the only source: a UUID missing from the configuration returns null.
    • Without an active configuration: null and empty lists, except the code's default values (damage formula, reactions, marks, statuses and categories, native events).
    • The legacy JSON database and UnleashSkillManager.GetDataByUuid are removed.

    Compare by UUID¶

    Models and data store UUIDs (strings), not references:

    • teams: SkillTarget.TeamUuid, SkillTarget.SameTeam(a, b) (a SkillPrefab has its caster's team);
    • entity types: EntityType.InheritsFrom(typeUuid, wantedUuid, getType) (hierarchy included);
    • resolve the object (Team, EntityType, CustomStat) only to read its properties.

    In a model, a UUID field is decorated so that the editor shows a list ([DamageTypeUuid], [GameEventUuid]…, in Runtime/Attributes/). Presentation definitions follow the same rule (UUID of the PresentationLibrary).

    Fixed UUIDs: the native events (event-hit…) and a few statuses of a new configuration (StatusDefinition.StunnedUuid = status-stunned, referenced by the Stun reaction) are constants of the code. Never change them.

    The names of the code's default data (statuses, categories, reactions, marks, damage formula steps, native events) are in English since 1.0. Data already created in a configuration keeps its names: only new configurations receive the English names.

    Migrations¶

    The project migrates without breaking existing assets:

    • [Obsolete] on old signatures and old nodes: never deleted while the migration is not complete. Obsolete model classes are hidden from the creation menu, but still open.
    • Migration step: a field whose shape changes is converted by a step of the data format (below), never by a flag stored next to the field: a node built from code or read from JSON (JsonUtility) gets the same values as one loaded from an asset.
    • Renamed serialized field: [FormerlySerializedAs("oldName")] (Unity attribute, not used in the project yet), or keep the old name and migrate on read.
    • Serialized type ([SerializeReference]): do not change its assembly; a changed name or namespace takes a [MovedFrom] (see Architecture).

    Data format¶

    SkillGraphModel, UnleashSkillConfiguration, PresentationLibrary and TrajectoryLibrary carry a format number (formatVersion, hidden in the inspector; CurrentFormatVersion in the code). An asset created in memory takes the current format.

    • On opening (OnEnable), UpgradeFormat() applies the migration steps one by one up to the code's format (DataFormat.Upgrade), then marks the asset modified: it is rewritten at the next save, or right away through UnleashSkill → Migration → Data format.
    • Format newer than the code (asset from a newer version of UnleashSkill): warning in the console, no migration, never written: every save (Ctrl+S, Save Project, AssetDatabase.SaveAssets) leaves it out, so its unknown fields are kept; the Node Editor shows such a graph disabled (read-only).
    • Skill graph older than SkillGraphModel.MinimumFormatVersion (data from before the first release): error in the console, no migration, no write (DataFormatStatus.Unsupported); the skill cannot be cast (InvalidGraph), and the Node Editor shows it read-only. A configuration or a library of format 0 (saved before the format number existed) has the same fields as format 1: it is loaded and brought to format 1.
    • Node identifiers: a node whose identifier is missing or already used by another node of the graph (two versions of a graph merged) receives a new one on load, with a warning; the connections stay on the first node of that identifier (SkillGraphModel.RepairNodeIds).
    • A step only touches the asset's data (no editor API: it can run during a load) and must stay correct on a new asset (created in memory, then brought to the current format).
    Asset Current format
    SkillGraphModel 2 (oldest format read: 2)
    UnleashSkillConfiguration, PresentationLibrary, TrajectoryLibrary 1

    A new format adds its step to the asset's UpgradeFormat.

    Nodes outside an asset. A node has no default specific to the editor: the Node Editor's creation menu, a node built from code (new AreaModel()) and a node read with JsonUtility (missing fields keep the values of the field initializers) are identical. A direction defaults to “toward the aim point”, which falls back to the caster's forward without an aim point.

    The version of the asset and of the public API is UnleashSkillVersion (SemVer): Current, ApiVersion, and IsApiCompatible(version) for a dependent asset.

    Localization tables¶

    The interface texts are not data of the skills: the English text is written in the code, the other languages are gettext files of Editor/Localization/ (fr.po), read by EditorLocalization and registered with Localizer.

    • A msgid is the exact English text of the code (escapes decoded); msgctxt distinguishes two meanings of the same text (event for native event names); msgstr is the translation. A changed English text loses its translation until the table is updated.
    • Formatted texts use {0}, {1} placeholders (TrFormat), kept in the translation.
    • The language is a per-user editor preference (EditorPrefs, key UnleashSkill.Language); in a build, without tables, the texts stay in English.

    Hand-written assets¶

    A skill is a YAML .asset file (Unity's text serialization), which can be written or modified by hand: generation by a tool, merge of two versions. The node reference gives what such a file needs for each node: its serialized type, the type and rank of each port, the serialized name of each field and the numeric value of each choice.

    Skeleton of the file¶

    Line Value
    m_Script {fileID: 11500000, guid: b5e95930826c4e2791b143f79d73fdb8, type: 3}: the SkillGraphModel script, found by this GUID (the one of its .meta, identical in every project)
    m_Name Name of the asset: the name of the file, without .asset
    m_EditorClassIdentifier Informative (the script is found by m_Script): Unity rewrites it on save, empty is accepted
    formatVersion 2, required. Without it, the graph is format 0: refused on load (error in the console), never cast (InvalidGraph), shown read-only (see Data format)
    nodes One - rid: … entry per node, in any order
    connections The links between the nodes' ports (below)
    Skill settings cooldown, costStatUuid, costAmount, castTime, castMode, chargeMinTime, chargeReleaseAtMax, castInterruption, cancelOnCasterDeath, overridesTurnWait, turnWait, spellTagUuids, variables, objectNames (see Skill settings): all optional
    references version: 2, then RefIds: the data of each node

    Nodes¶

    A node is an entry of references.RefIds, designated by its rid in nodes:

    • rid: an integer unique in the file, which only links nodes to RefIds.
    • type: {class: …, ns: …, asm: UnleashSkill}, written as the Serialized type line of the node's page in the reference. A type that does not exist (typo, add-on removed) is loaded as a missing node: warning in the console, skill refused until the node is fixed or deleted.
    • data.id: identifier of the node, unique in the graph, used by the connections; a GUID by convention. A missing identifier, or one already taken by another node, is replaced on load with a warning (the connections stay on the first node of that identifier).
    • data.position: place in the Node Editor (Rect: serializedVersion: 2, x, y, width, height), with no effect on the cast.
    • The fields: under data, with the Serialized name of the reference's field table (endMode, not End Mode). A choice is written as the number given in parentheses in the Type column (targetFilter: 1 for Enemy), a boolean as 0 or 1, a text without quotes (an empty text: nothing after the colon), a Vector3 as {x: 0, y: 0, z: 0}.

    rid below signed int64

    Each rid must stay below 9,223,372,036,854,775,807. Use prefixes in 85…, 87…, 88… (19 digits), never 93… or more: the editor crashes on import (StringToIntCheckedSInt32), on every restart, without a clear message. In case of a crash at startup, read %LOCALAPPDATA%/Unity/Editor/Editor.log (“Failed to convert … in file …”).

    Connections¶

    A connection links an output port (outputPort, the node upstream) to an input port (inputPort, the node downstream). Each end gives:

    Field Value
    nodeId data.id of the node
    hasPortKey 1: without it, the end designates no port
    portType Type of the port, as a number (table below)
    portRank Rank of the port among the ports of the same type and the same direction of the node, from 0: the Rank column of the reference (the Start's second Trigger output, During cast, is portType: 1, portRank: 1)
    portType Type Usage
    0 Module Main flow between modules (Start → Spell body)
    1 Trigger Starts actions (On hit → Damage)
    2 Condition Listeners and conditions of a module (Spell body → On hit)
    3 Support Behavior of a module (Movement → Spell body), modifiers
    4 Selection Configuration, not flow: Target selection → the node that chooses targets

    A connection whose node or port does not exist is not drawn by the Node Editor, which writes Connection ignored in '…' in the console; it stays in the file.

    Dynamic values, anchors and directions¶

    A field of type Dynamic value (ValueSource) is a block of fields; a fixed value only needs mode: 0 and value:

    Field Value
    mode 0 Fixed, 1 Stat, 2 ExecutionValue, 3 Distance, 4 StatusStacks, 5 EventValue, 6 Formula
    value Fixed value (mode: 0)
    holder Stat or stacks read on: 0 Caster, 1 Target
    statUuid Stat read (mode: 1)
    statKind 0 Current, 1 Max, 2 PercentOfMax
    executionValue mode: 2: 0 BranchTargetCount, 1 LastDamageDealt, 2 Variable, 3 StatusStacksRemoved, 4 StatusRemainingDamage, 5 CastElapsed, 6 ChargeRatio, 7 KilledCount, 8 ModuleBlockCount
    variable Skill variable read (executionValue: 2)
    distance mode: 3: 0 CasterToTarget, 1 CasterToImpactPoint, 2 ImpactPointToTarget
    statusUuid Status whose stacks are read (mode: 4)
    formula Expression (mode: 6), for example 0.5 * LastDamage + Stat(Strength)
    multiplier, add Applied to the raw value: value × multiplier + add (1 and 0 by default)
    useMin, min, useMax, max Clamping, if useMin / useMax is 1

    A field of type Anchor (SkillAnchor) has source (the number in parentheses in the reference), objectName (named object), offset (Vector3) and maxRange (aim point). A field of type Direction (SkillDirection) has source, followBranchDirection (1 by default: a Fork's branch direction wins), angleOffset (degrees) and random3D. Another structure (for example HitPolicy) lists its serialized names in the Type column of the reference.

    Missing fields¶

    A field missing from the file keeps the value of its initializer in the code, the Default column of the reference: in a node ([SerializeReference]), in a structure of a node (a dynamic value written with only mode and value keeps multiplier: 1), and in the skill settings. The example above relies on it: the Movement keeps its 50 m range, On hit its single target.

    Check a hand-written graph¶

    1. Open the skill in the Node Editor: every connection must be drawn (otherwise, read the Connection ignored warning in the console), and no node must carry the “!” badge of the graph analysis (a node that reads what it will never receive).
    2. Cast it in the editor preview, or in a test (see Testing a skill).
    3. When Unity saves the asset again (after a change in the Node Editor), it writes it in its complete form, every field included.
