    Extension points and public API¶

    Contract of 1.0 with dependent assets (Server, AI, user add-ons): what they can use without modifying a file of Assets/UnleashSkill/.

    Version and compatibility¶

    • UnleashSkillVersion.Current (1.0.0) is the asset's version; UnleashSkillVersion.ApiVersion (major.minor) the API's.
    • A dependent asset declares the API it requires and checks it on load ([InitializeOnLoad] or first use):
    static readonly System.Version RequiredApi = new System.Version(1, 0);

if (!UnleashSkillVersion.IsApiCompatible(RequiredApi))
    Debug.LogError($"This add-on requires UnleashSkill API {RequiredApi}, installed: {UnleashSkillVersion.Text}");
    • IsApiCompatible: same major, installed minor at least equal. SemVer: a minor only adds compatible things; a break of the public API waits for the next major.
    • The data format (formatVersion of graphs, configuration, library) is independent from the API version (see Data).

    What is public¶

    Every public or protected type and member of the UnleashSkill and UnleashSkill.Editor assemblies is part of the API and follows SemVer. The extension points below are those designed to be extended; the rest of the public API is meant to be used, with no guarantee that it is made to be overridden.

    What is not part of it:

    Element Visibility Why
    Old choice of the Chain's next target (ChainTargetSelection) internal, [Obsolete] Only read without a connected Target selection
    Runtime state of the nodes (*RuntimeData, except GameObjectRuntimeData) and the world steppers of statuses, cooldowns, locks, combos and regeneration internal State of a running node: an implementation detail. A step listener added twice would advance the statuses twice
    The editor's windows, panels, inspectors, property drawers and editor nodes internal Only the editor extension points below are public
    Any internal member — Implementation detail, can change with each version

    [assembly: InternalsVisibleTo] (Runtime/AssemblyInfo.cs, Editor/AssemblyInfo.cs) only opens to the framework's own tests, never to a dependent asset. A public [Obsolete] no longer exists at 1.0: a signature replaced after 1.0 stays [Obsolete] for at least one minor version, then is removed in the next major version.

    Naming decisions of 1.0¶

    • Data definitions keep their lowercase public fields (StatusDefinition.statusName, CustomStat.uuid, StatusDefinition.maxStacks…). They are Unity serialized fields, read by name by the inspectors and written in the assets: renaming them would break both the API and the data. They stay as they are for the whole 1.x line.
    • Skill, not spell: a graph is a skill (SkillCastResult.SkillBlocked, GameEvents.RaiseSkillCast, EventDefinition.SkillCastUuid, ConfigurationData.GetSkillTag). Spell remains in established names of the configuration and of the module bodies (SpellTagDefinition, SpellInstance, the Destroy spell and Modify spell nodes).
    • Received targets: the option that acts on the targets a node receives is ReceivedTargets in every enum (HealRecipient, StatusHolderTarget, TargetSelectionSource…).
    • One global entry point per role: UnleashSkillManager (instance, world, presentation) and ConfigurationManager, a static class (ConfigurationManager.ActiveConfiguration).
    • Controller input: PointedTarget is written through properties (Ally, Enemy, Spell, Position, Selection).

    Rules of a dependent asset¶

    • Its own root folder and its own assemblies, which reference UnleashSkill (and UnleashSkill.Editor for the editor); never the other way around, never a file of the base asset modified.
    • Its own namespace (not UnleashSkill.*): a simple name equal to a sibling namespace of UnleashSkill would be ambiguous (Architecture page).
    • Its types serialized by reference (nodes, status behaviors) are written into the data with the name of its assembly: never rename it, and move a renamed type through [MovedFrom].
    • It follows the node rules (Writing a node): simulation time, collisions through the SkillWorld, presentation through commands, texts in English translated by tables.

    Nodes¶

    Extension point Use
    NodeModel + [NodeInfo] + [Serializable] A third-party node, in any assembly: offered in the creation menu (SearchNodeProvider.GetMenuNodeTypes, all loaded assemblies), executed like ours. Same rules as in Writing a node. A node without its own [NodeInfo] (subclass, test class) is not offered
    [ExposedProperty], [HideIf] / [ShowIf], [FoldedOption], UUID attributes ([StatUuid], [StatusUuid]…), [AnchorSources], [DirectionSources], [TurnAware] Fields shown by the default editor node, with the same drawers
    DefaultEditorNode<TModel> (the add-on's editor assembly) Own editor node: a concrete class derived for the model's exact type, constructor (TModel, SerializedObject), found by EditorNodeFactory. Without it: DefaultEditorNode<NodeModel>
    BehaviorModel.CreateBodyBehavior → IBodyBehavior Module support (simulation step of the body). A movement goes through a trajectory (TrajectoryDefinition, segments), not through a new movement behavior
    DescribeFlow, ReadsTargets, ReadsAimPoint, ReadsParentBody Declared flow, read by the graph analysis and the validator
    StatusBehavior Third-party status behavior, offered by the statuses panel (TypeCache) and serialized by reference in the configuration

    Build and cast a graph from code: SkillGraphModel.CreateNew() (a graph with its Start node; ScriptableObject.CreateInstance<SkillGraphModel>() gives an empty one), graph.Nodes, graph.Connections (SkillGraphConnection, endpoints SkillGraphConnectionPort(nodeId, PortType, rank), or PortKeyResolver.TryCreatePort), then caster.Cast(graph, out execution) or graph.Compute(caster).

    Presentation¶

    Extension point Use
    IEffectPlayer, ISoundPlayer, ICameraShaker, IEntityAnimator, IIndicatorPlayer, IModuleVisualPlayer (+ IPresentationTickable, IDisposable) Backends: one slot of PresentationSystem per kind. Replace a backend: UnleashSkillManager.Presentation.Effects = …, or a whole system with UnleashSkillManager.ResetPresentation(system) (empty slots stay empty: DefaultPresentationBackends.Install fills those you want by default)
    DefaultPresentationBackends.CameraShakerFactory Factory of the default shake (used by the Cinemachine adapter)
    PresentationCommandBuffer.Observer (IPresentationCommandObserver) Receives each accepted command when it is emitted, handle and tick set. Disabled queue: nothing is observed
    PresentationSystem.EntityResolver, EntityCollector, EntityTimeScaleResolver Resolution of anchored entities (by default: SkillEntityRegistry)
    UnleashSkillConfiguration.GeneralSettingsChanged (+ NotifyGeneralSettingsChanged) Raised when the game mode or the presentation setting of a configuration changes (properties, inspector, Undo). UnleashSkillManager.PresentationEnabled follows the setting of the active configuration; a value set from code holds until that setting changes

    Recording mode (server): a system without backends (new PresentationSystem()), queue active and observed. Commands are collected for sending, nothing is materialized:

    var presentation = new PresentationSystem();
presentation.Commands.Observer = replication; // IPresentationCommandObserver
UnleashSkillManager.ResetPresentation(presentation);

    Authority and simulation¶

    Extension point Use
    ISkillAuthority (SkillWorld.Authority, LocalAuthority by default) Who decides on impacts: ResolvesHits, ConfirmHit consulted before an impact counts
    IWorldStepListener (SkillWorld.AddStepListener) Step added to the world tick (after the distribution of impacts): sending a tick's events, validation… An exception goes to SkillWorld.ExceptionHandler (Debug.LogException by default: a server logs it its own way) and the tick goes on
    ISimulationEntity, IMovementDriver World entity (pose read at the start of the tick, requested movements), without a MonoBehaviour
    BodyHistory Snapshots of the bodies per tick (lag compensation)
    SimulationSandbox A second world in the same process (preview, network bench). An add-on keeps its per-world state on the SkillWorld (step listener instance, or a dictionary keyed by world), never in a static read during a tick; an object it creates without a parent while simulating goes through SimulationSandbox.AdoptCreated
    UnleashSkillManager.ResetWorld(world) World with special settings (server, tests)

    Events¶

    Extension point Use
    GameEventBus (UnleashSkillManager.World.Events): Emitted, Subscribe(uuid, handler) Gameplay events (Hit, Death, Kill, statuses, skill cast, cast interrupted, summon, contact, custom events)
    UnleashSkillManager.EmitGameEvent The game emits a custom event (parry, dodge)
    UnleashSkillManager.ExecutionStarted, ExecutionEnded An execution enters the list of active ones (cast, passive, skill cast by a skill), or leaves it (completed or canceled, removed by the manager's Update or by UnregisterActiveSkillExecution). Swapped by SimulationSandbox: the editor preview does not notify the game's subscribers. A subscriber that throws is logged, the others are still called. A canceled execution whose node threw carries the exception in SkillExecution.Fault
    SkillExecution.DamageDealt Damage dealt by an execution
    UnleashSkillManager.WorldChanged The world was replaced (ResetWorld): previous world, then new world (null: recreated on the next access to World). Not raised by the first creation of the world, nor inside a SimulationSandbox. A subscriber that throws is logged, the others are still called

    The bus lives with the world¶

    The event bus belongs to the world: UnleashSkillManager.World.Events is the bus of the current world. Replacing the world (UnleashSkillManager.ResetWorld, a new game) replaces the bus: the subscribers of the old one no longer hear anything, without any error.

    • Subscribe after the manager's Awake: on entering Play Mode, the manager calls ResetWorld() in its Awake, so a subscription taken in another Awake can already be lost. Subscribe in Start (every Awake of the scene has run by then) or later.
    • Subscribe again on WorldChanged: the event is raised after each replacement. Reading UnleashSkillManager.World there gives the new world (or creates it with the active configuration's settings, as the next access would).
    using UnleashSkill;
using UnleashSkill.Configuration;
using UnleashSkill.Simulation;
using UnityEngine;

public class HitFeedback : MonoBehaviour
{
    void Start()
    {
        Subscribe();
        UnleashSkillManager.WorldChanged += OnWorldChanged;
    }

    void OnDestroy()
    {
        UnleashSkillManager.WorldChanged -= OnWorldChanged;
        UnleashSkillManager.CurrentWorld?.Events.Unsubscribe(EventDefinition.HitUuid, OnHit);
    }

    void OnWorldChanged(SkillWorld previous, SkillWorld current) => Subscribe();

    void Subscribe() => UnleashSkillManager.World.Events.Subscribe(EventDefinition.HitUuid, OnHit);

    void OnHit(GameEvent hit) { /* flash, sound, score */ }
}

    The same holds for everything else the world owns (profile, trace, time scales): see Restart a game.

    Editor¶

    Extension point Use
    NodeEditor.GraphViewCreated (+ NodeEditor.Graph, NodeEditor.GraphView) The graph window has just built its interface: an add-on adds its panel to it (rootVisualElement) and reads the open graph
    NodeGraphView: AddNode, AddNodeConnectedTo, ReplaceNode, Reload, SelectedNodes, FlowAnalysis Modify the open graph (Undo included)
    SearchNodeProvider.GetMenuNodeTypes, EditorNodeFactory, NodeFieldReflection List of nodes, editor node of a model, exposed fields (AI catalog)
    FieldLabel (UnleashSkill.Editor.PropertyDrawers) Displayed label of a field (without its Uuid suffix, unit of a [TurnAware] field), as the editor shows it

    InspectorView and SplitView are public only because NodeEditor.uxml instantiates them; they are not extension points. | GraphFlowAnalysis (runtime) | Graph flow and W112 to W116 warnings |

    Localization¶

    The interface is in English in the code; other languages come from tables.

    Extension point Use
    Localizer.RegisterTable(LocalizationTable) / UnregisterTable An add-on adds its own translations (its texts are written in English in its code). Several tables of the same language combine, the last one registered wins
    LocalizationTable.ParsePo(text, language), new LocalizationTable(language) + Set(english, translation, context) Read a gettext .po file, or build a table from code
    Localizer.Tr, TrFormat, TrContext, Translate(text, language), HasTranslation, Languages, LanguageChanged Translate in the current language or in a given one (AI catalog: same tables as the editor), rebuild a window when the language changes
    NodeText.Title, MenuPath, Tooltip, OutputPortLabel (optional language) Displayed texts of a node, translated without changing its identity (class name, field names)
    EditorLocalization.Language Language chosen in Preferences → UnleashSkill (per user, EditorPrefs)

    A new language for the whole editor is a .po file named after its code (de.po) in Editor/Localization/: it appears in the preferences without recompiling.
