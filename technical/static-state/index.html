    Static state and preview¶

    Why it matters¶

    The engine reads a lot of state through statics: UnleashSkillManager.World, the presentation, the active executions, SkillEntityRegistry, the steppers (statuses, locks, combos, cooldowns, regeneration), SpellInstanceRegistry, the running attacks and dodges of each caster, SkillPooler, the wall pool, UnityEngine.Random. It is simple and fast: one game runs per process.

    But the editor preview (Editor/Preview/SkillPreviewSession) simulates a skill while another world may exist (the game in Play Mode, the tests). It does it in a SimulationSandbox (Simulation/SimulationSandbox.cs): for the duration of a scope, each static of the engine is swapped with the sandbox's, then given back.

    Simulate in a sandbox¶

    var world = new SkillWorld(new SimulationSettings { SceneryBackend = StaticSceneryBackend.None });
var sandbox = new SimulationSandbox(world, presentation: null, seed: 0);
var created = new List<GameObject>();

using (sandbox.Enter())
{
    // Here, UnleashSkillManager.World, SkillEntityRegistry, SkillPooler… are the sandbox's

    // The sandbox has no pooler (the game's is swapped out): one for the module bodies, in EditMode without Awake
    var pooler = new GameObject("SkillPooler");
    created.Add(pooler);
    pooler.AddComponent<SkillPooler>().Init();

    SkillCaster caster = CreateEntity("players", Vector3.zero, created);
    SkillCaster enemy = CreateEntity("monsters", new Vector3(0f, 0f, 5f), created);

    caster.Cast(skill, out SkillExecution execution);
    for (int tick = 0; tick < 1000 && !execution.IsCompleted; tick++)
    {
        world.Step();
        execution.Update();
    }
}
// Out of scope: the game gets its state back intact

// Cancels what remains, removes the entities from the registry, then destroys the objects inside the scope
sandbox.Dispose(() =>
{
    foreach (GameObject gameObject in created)
        Object.DestroyImmediate(gameObject);
});

static SkillCaster CreateEntity(string team, Vector3 position, List<GameObject> created)
{
    var gameObject = new GameObject(team);
    created.Add(gameObject);
    gameObject.transform.position = position;
    var entity = gameObject.AddComponent<SkillCaster>();
    entity.teamUuid = team;
    entity.ResetStats("test-template");        // Start does not run in EditMode
    SkillEntityRegistry.Register(entity);      // nor does OnEnable: registered in the sandbox's registry
    return entity;
}

    Everything that touches the sandbox's simulation (placing an entity, casting, advancing a tick, destroying its objects) is done inside a scope. The sandbox calls the engine's step listeners on its own world.

    • Pooler: a sandbox starts without a SkillPooler: a module (Spell body, Area, Beam…) needs one, created and initialized (Init()) inside the scope. Without it, the module logs an error and ends without its outputs.
    • Entities: outside Play Mode, Start and OnEnable do not run: teamUuid, ResetStats(template) (template of the active configuration) and SkillEntityRegistry.Register, inside the scope.
    • Configuration: the sandbox reads the active configuration (ConfigurationManager.ActiveConfiguration), which it does not swap.
    • Cleanup: Dispose(destroyObjects) cancels the executions still active, removes the entities from the sandbox's registry, stops its presentation, then calls destroyObjects inside the scope.
    • Completed executions: without the manager's Update, a completed execution stays in ActiveSkillExecutions (sandbox.Executions) until UnleashSkillManager.UnregisterActiveSkillExecution or Dispose (Diagnose and measure).
    • Restart: UnleashSkillManager.ResetWorld() inside a scope cancels the sandbox's executions and recreates its world at once, with a copy of the replaced world's settings, its scenery, authority, warning and exception handlers (never the configuration's settings, nor its scenery); sandbox.World then returns the new world. To test a restart with a world of your own, call ResetWorld(world) with a world without scenery.
    • Seed: the seed of the constructor is that of UnityEngine.Random inside the scope. The rolls of an execution have their own seed, set with SkillExecution.SetRandomSeed (Skills → Testing a skill).

    The swap covers: world, presentation, active executions (and the ExecutionStarted / ExecutionEnded events: the preview does not notify the game's subscribers), SkillEntityRegistry, the steppers of statuses, locks, combos, cooldowns and regeneration, SpellInstanceRegistry, the running attacks and dodges of each caster (AttackCancellation), the entity walls, SkillPooler, UnityEngine.Random.

    The editor language (Localizer) is also a static state, but it is not read during a tick: the simulation never depends on it.

    State of an add-on¶

    The list of swapped states is internal to the engine: an add-on cannot add its own. So an add-on keeps per-world state on the SkillWorld (an instance of its step listener, or a dictionary keyed by world), never in a static read during a tick. Otherwise the preview writes into the game's state (or the other way around): ghost entities, statuses that advance twice, tests that leak into each other.

    An object the add-on creates without a parent while simulating (a root GameObject) goes through SimulationSandbox.AdoptCreated(gameObject): inside a sandbox, the preview stores it in its scene and destroys it with the sandbox; outside, nothing happens.

    Restart a game¶

    Outside the preview, UnleashSkillManager.ResetWorld() (world recreated on demand) or ResetWorld(world) (world provided, without scenery for a Play Mode test) and ResetPresentation(...) put the engine back in a known state. They do not touch what each entity carries. To restart a game without reloading the scene (game over, retry), call in this order:

    1. UnleashSkillManager.ResetWorld(): cancels every active execution (skills cast, passives, skills that outlive their caster; ExecutionEnded for each), then replaces the world. WorldChanged is raised: the game's subscribers subscribe again to the new bus (Events).
    2. UnleashSkillManager.ResetPresentation(): stops the running effects, sounds and shakes, releases the backends; the presentation is recreated on the next access, according to the active configuration.
    3. caster.ResetEntity() on each caster that stays in the scene: stats recreated from its template, statuses, locks and cooldowns removed, alive again (a caster disabled by its death is re-enabled), passives started again (ResetWorld ended them).
    4. The game puts back what it owns: positions, the entities it spawned (destroyed or returned to its pools), tags, slots (SkillSlots.EndAllReplacements), aim (AimDirectionOverride, PointedTarget).
