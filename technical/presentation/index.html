    Presentation¶

    User version: Presentation.

    Code: Assets/UnleashSkill/Runtime/Presentation/ (assembly UnleashSkill).

    Principle¶

    Nodes emit intentions; reusable definitions (assets) describe the content; a system materializes them after the simulation.

    nodes / modules ──► PresentationCommandBuffer ──(LateUpdate)──► PresentationSystem ──► backends
                    (UnleashSkillManager.PresentationCommands)       IEffectPlayer, ISoundPlayer, ICameraShaker,
                                                                     IEntityAnimator, IIndicatorPlayer

    Two rules: the presentation never modifies the simulation, and gameplay never holds a Unity presentation object (only UUIDs and handles). Disabled (server, tests, preview without visuals), the queue ignores commands and returns PresentationHandle.None: the fight does not change.

    Emit a command¶

    UnleashSkillManager.PresentationCommands (PresentationCommandBuffer):

    Method Command
    SpawnEffect(uuid, anchor, position, …) / StopEffect(handle) Effect (EffectDefinition)
    PlaySound(uuid, anchor, position, …) / StopSound(handle) Sound (SoundDefinition)
    CameraShake(uuid, position, intensity) Shake (CameraShakeDefinition)
    PlayAnimation(uuid, entityId, speed) / StopAnimation / SetAnimationSpeed Animation (AnimationDefinition)
    ShowIndicator(shape, anchor, …) / UpdateIndicator / HideIndicator Ground indicator (IndicatorShape)
    MoveEntity(entityId, from, to, duration, delay) Move of an entity's visual, presentation only (Move an entity)

    Flags and variations: PresentationCommand.Flags (PresentationCommandFlags, one byte, None by default) carries options read by the presentation alone. RandomSpin on a SpawnEffect (last parameter of SpawnEffect, or field of a command of your own) turns the effect by a random angle around its forward axis (local +Z), after the command's rotation. The ScaleVariance of the EffectDefinition (± percent, at most EffectDefinition.MaxScaleVariance) multiplies the command's scale by a random factor, for every spawn of that effect. Both are rolled by the PresentationSystem with UnityEngine.Random when it plays the command, never by the simulation's randomness (SkillExecution.Random): the fight stays identical, and a replicated command keeps its flags while each viewer rolls its own values. The varied pose is the instance's for its whole life (an attached effect keeps its spin). A Play effect with Orient computes its rotation itself, from its Direction (SkillDirection.Resolve at each emission point in the world, up along the play plane's normal), before emitting.

    Indicators are continuous shapes (IndicatorShapeKind: circle, ring, cone, rectangle, line, path), designed for real-time mode: one shape, one tint. They are presentation commands: with the presentation disabled, nothing is shown. In a game on a grid, range and area in cells belong to your game's interface, not to ShowIndicator.

    IndicatorShape.Fill (0 to 1) is the filled part of a shape: an announced attack fills up until the hit. FilledPart() gives its shape, grown from the center (radius × fill for a circle or a cone, length × fill for a line, length and width × fill for a rectangle, a circle between the two radii for a ring); LineIndicatorPlayer draws its outline as a second line (BuildFillOutline for a backend of yours), not over a library effect. The Show indicator node raises Fill with UpdateIndicator until the end of its duration.

    A path (IndicatorShapeKind.Path, IndicatorShape.ForPath(path, color, plane)) is a polyline: the points of an IndicatorPath, in the command's local frame, drawn solid up to DashedFrom, then dotted. It is the predicted trajectory of the Aim node. The path is a reference read when the presentation executes the command: keep your own instances and do not change one before the next presentation frame (the Aim node alternates two). The default backend (LineIndicatorPlayer) draws the dotted part with a repeated dash texture; LineIndicatorPlayer.BuildPath and BuildDashes give the same lines to a backend of yours.

    // Predicted trajectory of a definition, cut at the first obstacle, shown as a path
var points = new List<TrajectoryPreviewPoint>();
TrajectoryPreview.Sample(definition, start, forward, aimPoint,
    new TrajectoryPreviewSettings { Caster = caster, Plane = plane, Step = world.TickDuration }, points);
cut.Submit(world, points, bodyShape, rotation, filter);   // TrajectoryObstacleCut, kept between ticks
cut.Apply(points);                                         // last answered sweep: one tick late
TrajectoryPreview.ToIndicatorPath(points, start, path);
commands.UpdateIndicator(handle, IndicatorShape.ForPath(path, color, plane), start, quaternion.identity);

    TrajectoryPreview.Sample is pure (no world, no tick, never a roll of the execution): it plays the definition with the game's TrajectoryRunner, so without obstacles the predicted positions are the simulated ones. A point is Uncertain from the first Pursuit, Return or wandering Line on. TrajectoryObstacleCut sweeps the world along the polyline (ModuleQuery.Sweep, at most MaxSweeps straight chords), never a physics query; a new batch leaves once the previous one has answered. The turn-based replay can sample a trajectory the same way to animate a visual.

    Anchor (PresentationAnchor): InWorld, OnEntity(entityId, bone), OnEntity(entityId, bone, socket) (a socket, which takes precedence over the bone; WithPositionOnly(): only the position is followed, the offset along the world axes and the rotation in world space, as for a ground indicator), OnBody(bodyId) (interpolated position of the body). An UpdateIndicator of an anchored indicator gives its new offset in the anchor's frame. To choose a node's points (impact, received targets, caster, module body), PresentationPoints.Collect does the work shared by the Play effect / Play sound nodes.

    Travel(from, to, duration) moves the instance in a straight line from from to to (world space), turned toward the arrival. It is not reserved to the turn-based replay: a node can emit it in real-time mode too, for anything that goes from one point to another without a body in the world (a lightning arc between two targets, a trail toward the caster). The duration is counted in presentation time (sum of the Process steps, the frame time; neither the simulation's tick nor the time zones of the world apply), from the moment the instance is played, after its delay if it has one. At the arrival, the anchor disappears and the instance is stopped like one whose entity is gone: a particle effect stops emitting, then ends once its particles are done; a looping sound stops. A one-shot effect shorter than the travel ends on its own before.

    // Effect that travels from the previous target to the current one in 0.1 s (real-time mode)
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
if (commands.Enabled)
    commands.SpawnEffect(trailUuid, PresentationAnchor.Travel(from, to, 0.1f), float3.zero, quaternion.identity, 1f,
        caster.EntityId);

    Recipe: an effect that travels from one point to another¶

    Without code, the Play effect node does it: check Travel, choose the arrival with Emit At and the start with Travel From (one Travel command per emission point, start resolved once). Behind a Chain, Travel From = Previous bounce draws a trail from each target to the next: each bounce's branch carries its index and the entity and point it jumps from (SkillExecutionContext.ChainBounceIndexKey, ChainPreviousTargetKey, ChainPreviousPointKey), read by the SkillAnchorSource.PreviousBounce anchor (SkillAnchor.TryGetPreviousBounce). Without a Chain upstream, the anchor falls back to the caster and the flow analysis warns (W118, GraphFlowCodes.PreviousBounceNeverReceived).

    From a node of your own, read the two points in the branch, then emit the command:

    // In OnStart of a node behind a Chain: trail from the previous bounce to the received target
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
SkillTarget target = context.GetPrimaryTarget();
if (commands.Enabled && target != null && SkillAnchor.TryGetPreviousBounce(context, out Vector3 from))
    commands.SpawnEffect(trailUuid, PresentationAnchor.Travel(from, target.transform.position, 0.1f),
        float3.zero, quaternion.identity, 1f, caster.EntityId, target.EntityId);
context.Execution.CompleteNodeInstance(this, caster);
    • The effect: give it something that stays visible on the way (a Trail Renderer, particles simulated in world space); its own position is only the head of the travel.
    • Duration: presentation time, so a hitstop or a time zone does not slow it; 0 puts the instance at the arrival and ends it at once.
    • Gameplay: nothing reads the travel, and with the presentation disabled no command is emitted. A trail that must hit something is a module with a body (a projectile), not a presentation.

    A beam drawn up to the wall is the other two-point visual: a Beam module whose visual has Stretch To Length (ModuleVisualDefinition.StretchToLength) gets the Z of its body prefab's scale set to the effective length of its last shot (GameObjectRuntimeData.PresentedLength: up to the first obstacle that stops it, otherwise its range), applied every frame by the pooler in real-time mode and by SpawnModuleVisual (AxisScale) in turn-based mode. Model the prefab one meter long along +Z from its pivot. A visual of your own can read GameObjectRuntimeData.VisualScale.

    The handle is used to stop later: context.Execution.TrackPresentation(key, handle) tracks it in the execution, StopPresentation(key) stops it (Stop effect node), an indicator tracked with TrackPresentation(key, handle, PresentationCommandType.HideIndicator) included (Show indicator node), and Cancel / Cleanup stop everything tracked. A one-shot effect does not need to be tracked: it plays until the end.

    Model: PlaySoundModel.OnStart (checks commands.Enabled, emits per point, tracks the handle if the sound loops or has a key, then CompleteNodeInstance whatever happens).

    Library¶

    PresentationLibrary (single global asset, PresentationLibrary.Active): lists of effects, sounds, shakes, module visuals, animations, trails. Each definition (PresentationDefinition) has a stable UUID; models store the UUID (string), never the Unity reference. Resolution: TryGet<T>(uuid, out definition), GetEffect, GetSound… Editing: Presentation section of the main menu.

    From a graph built from code. A graph refers to a definition by its UUID. Two ways to get it, both at construction:

    PresentationLibrary library = PresentationLibrary.Active;

// By the name of an asset of the library: exact, first of the type (a name is not unique). Null if there is none
var visual = library.FindByName<ModuleVisualDefinition>("Fireball");
var body = new GameObjectModel().WithVisual(visual);

// With a UUID chosen by the game, like the identifiers of teams, stats and statuses
var impact = PresentationDefinition.Create<EffectDefinition>("my-game.fireball.impact", "Fireball impact");
library.Add(impact);   // false if the UUID is taken

    A definition is resolved in the active library when the module starts: one created from code must be there by then. Create makes a definition in memory: it is not saved with the project, and the game creates it again on each launch. FindByName goes through the lists: call it when building the graph, not on each tick.

    ModuleVisualDefinition describes a module's visual: body prefab (with SkillPrefab: pooled, interpolated, no logic) and launch, loop, impact and expiration effects / sounds (ModuleVisualPresenter). A module without a visual stays valid. Who carries the body prefab depends on the mode: in real-time mode, the module's SkillPrefab, taken from the SkillPooler (counters: SkillPooler.Current.ActiveVisualCount…); in turn-based mode, for a module replayed by the presentation (resolved on the selection, area or beam in turns), the IModuleVisualPlayer (ModuleVisualPlayer.ActiveCount, which stays at 0 in real-time mode). See Diagnose and measure.

    System and backends¶

    PresentationSystem (UnleashSkillManager.Presentation) consumes the queue in LateUpdate (Process(world, deltaTime)), associates each handle with the live instance, follows anchors and entity time (hitstop: animation at speed 0).

    Interface Default (Backends/) Replace for
    IEffectPlayer ParticleEffectPlayer (pools per definition) VFX Graph (planned)
    ISoundPlayer AudioSourceSoundPlayer (pool of AudioSources) FMOD, Wwise
    ICameraShaker SimpleCameraShaker; Cinemachine 3 if present (UnleashSkill.Cinemachine, DefaultPresentationBackends.CameraShakerFactory) The game's camera
    IEntityAnimator PlayablesEntityAnimator (Playables on the Animator, blended with the Animator Controller) The game's animation system
    IIndicatorPlayer LineIndicatorPlayer (LineRenderer outline) Decals, shaders
    IModuleVisualPlayer ModuleVisualPlayer (body prefab of a ModuleVisualDefinition, pool per prefab, colliders disabled) Visual replayed separately
    IEntityMover TransformEntityMover (visual transform of the entity, the root stays still) The game's movement presentation (path, jump)
    ISocketResolver DefaultSocketResolver (PresentationSockets component, humanoid bone, bone names; see Sockets) The game's equipment system
    ITrailRenderer MeshTrailRenderer (generated mesh per trail, pooled; see Trails) The game's trail system

    DefaultPresentationBackends.Install(system, library) connects the defaults to the empty slots; a game assigns before (or replaces) a property of the system (Effects, Sounds, CameraShaker, Animator, Indicators, ModuleVisuals, Movers, Sockets, Trails). The resolvers EntityResolver, EntityTimeScaleResolver, EntityCollector link entity identifiers to transforms.

    Sockets¶

    A socket is a named point of an entity (hand, weapon tip, muzzle) that presentation follows. Sockets are a closed list configured by the game in the library (Main Menu → Presentation → Sockets, PresentationLibrary.Sockets, SocketDefinition), referenced by a stable UUID: renaming one breaks nothing. A new library has eight default sockets with fixed UUIDs (SocketDefinition.HeadUuid = socket-head, ChestUuid, RightHandUuid, LeftHandUuid, FeetUuid, WeaponBaseUuid, WeaponTipUuid, MuzzleUuid); Head, Chest, RightHand and LeftHand carry their humanoid bone. Add the missing default sockets (or library.AddDefaultSockets()) puts back the ones you deleted.

    Field of SocketDefinition Role
    Socket Name Name shown in the Socket menus of the nodes
    Human Bone Bone of a Humanoid rig, found automatically (Animator.GetBoneTransform); None by default
    Bone Names Fallback bone names, searched in order in the hierarchy (hand_r, mixamorig:RightHand…)

    Declaring where the sockets are: the PresentationSockets component (Add Component → UnleashSkill → Presentation Sockets), on the entity or on any object of its hierarchy (weapon prefab, shield): one entry per socket, a transform (empty: the object of the component) and a local position and rotation. An entry set outside the root (equipment) takes precedence over the root's (body): the sword's WeaponTip wins over the body's. Two pieces of equipment declaring the same socket: the first in the hierarchy, with a warning in the editor.

    Resolution (ISocketResolver, PresentationSystem.Sockets; default DefaultSocketResolver), in order:

    1. the PresentationSockets components of the entity;
    2. the socket's Human Bone, if the entity's Animator is Humanoid;
    3. its Bone Names, then its name, searched in the hierarchy (BoneLocator);
    4. otherwise the root, with a warning once per entity and socket, in the editor only.

    The result is cached per (entity, socket). It is read again when a PresentationSockets component is enabled, disabled or moved in a hierarchy (weapon equipped, put away, swapped), when the cached transform is destroyed or leaves the entity, and on Invalidate(entity) (Invalidate(null): everything) for an equipment system that does not use the component. The anchored instances resolve their socket every frame, so an effect on the tip of a swapped weapon moves to the new one.

    // Equipment of the game, without the component: tell the presentation that the weapon changed
UnleashSkillManager.Presentation.Sockets?.Invalidate(character.transform);

// From code: an effect that follows the muzzle of the entity
commands.SpawnEffect(flashUuid, PresentationAnchor.OnEntity(entityId, null, SocketDefinition.MuzzleUuid),
    float3.zero, quaternion.identity);

    A resolver of your own (ISocketResolver: TryResolve(entity, socketUuid, out transform, out localPosition, out localRotation), Invalidate(entity)) replaces the default one: it is called every frame for each instance that follows a socket, so cache what is costly. Sockets are presentation only: gameplay never reads them (a socket's pose depends on the animation played, and a server without rendering has none). They work in 2D (a socket is a transform); only the humanoid bones do not apply.

    Trails¶

    A trail (TrailDefinition, list PresentationLibrary.Trails, Main Menu → Presentation → Trails) is the motion trail of an entity's gesture: sword swing, punch, dash. It is played by the Play trail node, or from code by the StartTrail / StopTrail commands:

    PresentationHandle trail = commands.StartTrail(swordTrailUuid, entityId);
// ...
commands.StopTrail(trail);   // no more samples, it fades out (Fade Out)
    Field Role
    Mode Ribbon: a ribbon between two sockets (blade base and tip); Point: one socket, with a width (fist, foot)
    Base Socket / Tip Socket Ribbon: the two sockets (default WeaponBase, WeaponTip)
    Socket Point: the followed socket; empty: the socket of the command (Socket of the node), otherwise the root
    Material Default: the shipped UnleashSkill/Trail material
    Lifetime Lifetime of a sample (length of the trail in time), 0.15 s by default
    Fade Out Fade-out after the stop, in seconds (0: the samples just age out)
    Width / Width Curve Point mode; in Ribbon mode the width is the distance between the sockets
    Color Gradient From the head (left) to the tail (right)
    Min Distance A sample is only added beyond it (no jitter when the gesture stops)
    Sorting Layer Name / Order 2D

    The sockets are in the definition: a sword's trail is the same everywhere, the command only carries the entity. The PresentationSystem resolves them into transforms (ISocketResolver) and resolves them again after an invalidation (weapon swapped).

    Backend ITrailRenderer (PresentationSystem.Trails, default MeshTrailRenderer): Resolve(definitionUuid), Play(command, definition, first, second) (the followed points, TrailAttachment: transform and offset), SetAttachments, Stop (fade-out), IsPlaying, SetTimeScale(handle, scale); implement IPresentationTickable and IPresentationStoppable too. The default generates one mesh per trail (pooled, MeshRenderer without shadows), samples once per frame in LateUpdate (after the animation has been evaluated) and subdivides between two samples along a Catmull-Rom curve according to the angle traveled (at most 8 segments), so that a fast gesture draws no breaks. A Point trail faces MeshTrailRenderer.ViewPoint (default: the main camera).

    • Entity time: the samples age at the entity's time (EntityTimeScaleResolver): during a hitstop the trail freezes instead of shortening.
    • Stop: StopTrail, the node's key or duration, the end of the execution, the entity disappearing (the trail finishes its fade-out in the world), StopAll (immediate).
    • Shader: UnleashSkill/Trail is unlit, vertex color × texture × tint, additive or alpha blending (Blend Mode of the material), one pass without a LightMode tag: drawn by the built-in render pipeline and by URP. In HDRP, check that the material renders; otherwise give the definitions a material of your own (Sprites/Default, or an HDRP unlit material). A definition without a material uses the shipped one; in a build, the shader is included as long as a definition references the material (a definition created in the editor does).
    • A game's TrailRenderer goes through Play effect (persistent, attached to a socket): it ages at global time, the entity's time does not apply to it. That is what TrailDefinition is for. A projectile's trail is the loop effect of its module visual.

    Camera shakes with Cinemachine¶

    With Cinemachine 3 in the project, the UnleashSkill.Cinemachine assembly compiles (versionDefines, UNLEASHSKILL_CINEMACHINE) and registers itself before the first scene loads (RuntimeInitializeLoadType.SubsystemRegistration): DefaultPresentationBackends.CameraShakerFactory then creates a CinemachineCameraShaker, which Install puts in the CameraShaker slot if it is empty. Nothing to call from the game.

    On each Shake, the shaker looks for an active CinemachineImpulseListener in the loaded scenes (FindAnyObjectByType):

    • found: it emits an impulse through its own CinemachineImpulseSource (pooled object Camera Impulse): Bump shape, ImpulseDuration = CameraShakeDefinition.Duration, velocity in a random direction of length Amplitude × intensity of the command (0 = 1). A Range above 0 gives a Dissipating impulse with DissipationDistance = Range; 0, a Uniform impulse. The impulse is on the source's default channel: a listener whose Channel Mask excludes it does not react. Frequency is not used;
    • none: it falls back to a SimpleCameraShaker (offset of Camera.main, frequency used) and logs one warning per shaker (the first fallback), so the missing listener does not go unnoticed.

    The game adds the listener to its cameras: Add Extension → CinemachineImpulseListener on each CinemachineCamera that should shake. StopAll cancels only the impulses this shaker emitted, never those of the game.

    To shape the shake yourself (frequency, noise profile, channel), replace the backend: UnleashSkillManager.Presentation.CameraShaker = myShaker (an ICameraShaker, optionally IPresentationStoppable and IDisposable), or set DefaultPresentationBackends.CameraShakerFactory after SubsystemRegistration and before the first access to UnleashSkillManager.Presentation, which creates the system with its backends (for example in RuntimeInitializeLoadType.BeforeSceneLoad).

    Hidden effects (visibility per team)¶

    A trap, an invisible unit: an effect shown to one team and not to the other. The Play effect, Play sound and Camera shake nodes have a Visible To field (PresentationVisibility): Everyone (default), Caster team (only the viewers of the caster's team), Other teams. A module visual (ModuleVisualDefinition.VisibleTo, section Visibility) restricts all its commands the same way: body prefab played by the presentation (turn-based mode), launch, loop, impact, expiration. The rule is relative to the caster's team (SkillTarget.TeamUuid), read when the node runs.

    The visibility travels with the command (PresentationCommand.Audience, a PresentationAudience: visibility and team UUID), and the filter is applied when it is played:

    Where What
    PresentationSystem.ViewerTeamUuid Team UUID of the local player. A launching command whose audience does not include it is skipped (never played, never delayed). Null or empty (default): the viewer sees everything (spectator, replay, single player). A change refreshes the persistent effects already launched
    PresentationSystem.RefreshVisibility() Applies the viewer and the filter again to the persistent effects and looping sounds still running: stops those now hidden, starts those now visible
    PresentationSystem.CommandFilter Filter of the game, after the audience (Func<PresentationCommand, bool>, false = skipped): an invisible unit's effects and animations (SourceEntityId, TargetEntityId), a fog of war
    PresentationCommand.IsVisibleTo(teamUuid) Same rule, for what replicates the commands: a server sends each client only what its team sees
    PresentationCommandBuffer.Audience / AudienceScope(audience) (using) Ambient audience of the queue, given to each command emitted in the scope whose own audience is everyone: what the nodes use. A command of your own can also set Audience itself 
    // Local player: the traps of the other teams are not shown
UnleashSkillManager.Presentation.ViewerTeamUuid = localPlayer.TeamUuid;

// An effect of your own, shown only to the caster's team
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
using (commands.AudienceScope(PresentationAudience.For(PresentationVisibility.CasterTeam, caster.TeamUuid)))
    commands.SpawnEffect(markUuid, PresentationAnchor.InWorld, point, quaternion.identity, 1f, caster.EntityId);

    The simulation never reads the audience: the queue emits every command (the observer receives them all, with their audience), the presentation duration of an execution counts hidden commands too (the turn-based wait is the same for every team), and a hidden command changes nothing in gameplay. Only the launching commands are filtered: a stop or an update of a hidden instance reaches the backend with a handle it does not know, which has no effect (contract of IPresentationPlayer.Stop). The viewer and the filter are read when the frame processes the command. The persistent effects (Persistent or Attached mode) and looping sounds launched and not stopped yet are remembered, shown or hidden: changing ViewerTeamUuid stops those the new viewer does not see and starts those it now sees (same handle, at their anchor), and RefreshVisibility() does the same after a change of what CommandFilter hides (PersistentCount: how many are remembered). A one-shot, an animation or an indicator already played is not replayed. UnleashSkillManager.ResetPresentation creates a new system: set its viewer again.

    One screen, two teams in turn (hot seat): set ViewerTeamUuid to the team whose turn starts; the hidden marks of the other team disappear, those of this team come back.

    void OnTurnStarted(SkillTarget unit) => UnleashSkillManager.Presentation.ViewerTeamUuid = unit.TeamUuid;

    A hidden effect that must outlast the skill (a trap placed until it triggers): a persistent effect of a Play effect node stops with the execution that played it. Emit it from the game, under AudienceScope (example above), keep its handle and stop it yourself (StopEffect) when the trap triggers; the viewer changes apply to it. On a unit, a status does it with no code: its Loop Effect lasts as long as the status (Technical → Gameplay). Limit: in real-time mode, a module's body prefab is carried by its SkillPrefab (pooler), not by a command; it stays visible to everyone: give a hidden module a loop effect rather than a body prefab, or hide its SkillPrefab from your game.

    Stop everything¶

    The system only tracks the instances that follow an anchor. What a backend plays on its own (a one-shot effect or sound placed InWorld, a visual or an indicator in world space, a camera shake) is known to the backend alone. A backend that implements IPresentationStoppable (StopAll(): stop everything at once, the backend stays usable) is asked to stop it too; all the default backends implement it, the Cinemachine shaker included (it cancels only the impulses it emitted, not those of the game). The interface is optional: a backend of your own without it keeps working, only its anchored instances are stopped, through Stop(handle).

    Call What it does
    PresentationSystem.StopAll() Stops the tracked instances, the animations, everything the IPresentationStoppable backends play, drops the delayed commands and empties the queue. The backends and their pools stay
    PresentationSystem.Enabled = false (UnleashSkillManager.PresentationEnabled) StopAll(), then the queue ignores the commands (PresentationHandle.None) until it is enabled again
    UnleashSkillManager.ResetPresentation(system), with the current system StopAll() on it: the system stays in place
    UnleashSkillManager.ResetPresentation(other) or ResetPresentation() Shutdown() of the current system: StopAll(), then each backend that is IDisposable is released (pools destroyed). other replaces it; without an argument, a new system is created on the next access, from the active configuration

    None of them touches the visual of a real-time module, carried by the SkillPooler: it leaves with its module.

    Delayed commands and replay (turn-based)¶

    A command can carry a delay (PresentationCommand.Delay, presentation seconds): the system keeps it (ScheduledCount, ScheduledDuration) and runs it on time, in presentation time (sum of the Process steps). A command that targets an instance not yet played (stop) waits at least for it to be played. Disabling the presentation clears the queue.

    A node never writes the delay by hand: it is the queue's ambient delay (PresentationCommandBuffer.Delay), set for the duration of a scope by SkillExecution.PresentationAt(delay) (using), which also extends SkillExecution.PresentationDuration. In turn-based mode, every command emitted by the nodes of an execution (start, turn, step) pushes back the end of its presentation by its delay plus its own duration, read from its definition (one-shot effect: emission plus particle lifetime; sound: longest clip; shake; animation without a loop): PresentationDuration, and PresentationRemaining once the frame has started it, which IsTurnReady waits for. A StopAll ends that wait. SkillExecution.Defer keeps the delay of when it was queued: a continuation (result of a query on the selection) is presented with what started it. In real time, the delay stays 0.

    The projectile resolved on the selection (GameObjectModel.ResolveOnSelection) uses it: each target is distributed in a scope at its arrival time (distance / speed of the body at spawn), then ModuleVisualPresenter.OnReplayed emits SpawnModuleVisual, the effect and the loop sound on a travel anchor (PresentationAnchor.Travel(from, to, duration), position interpolated since the instance was played, gone at the end of the travel). The pooler does not instantiate its visual (GameObjectModel.InstantiatesVisual).

    An area or a beam in turn-based mode (GameObjectModel.PresentsVisualInTurns, carrier module whose logic advances in turns) has its visual played by the presentation too: SpawnModuleVisual in the world at the body's pose (per-axis scale PresentationCommand.AxisScale: the module's Scale box times its shape scale, as the pooler's in real-time mode; for an area, this box is not its shape: Radius, Width, Angle and growth are not applied to the visual), with the loop effect and sound, placed again when the body moves on a turn. Its end (expiration, stop of the visual and of the loop) is emitted in a scope delayed by ModuleVisualDefinition.TurnDisplayDuration after its last activation, so an instant area stays visible and PresentationDuration includes that display. An Attack in turns has its visual played the same way, without that extra display: its end is already replayed at the end of its recovery.

    Move an entity (replay)¶

    MoveEntity(entityId, from, to, duration, delay) shows an entity traveling from from to to (world space) in duration presentation seconds, after waiting delay seconds at from (plus the ambient delay). It is presentation only: the command touches neither the world nor the entity's position in it. The simulation (the Dash node, the game) places the entity; the presentation replays its move, so that a unit moved by a skill resolved at cast does not jump to its destination before the projectile that pushes it has arrived. With the presentation disabled, nothing is emitted.

    Its delay is not a scheduled delay: the command is played on the frame that processes it, and the visual waits at from during the delay, then moves in a straight line at constant speed. Its duration counts as its own duration (PresentationDurations): emitted by a node in turn-based mode, it pushes back PresentationDuration like any command. From the game, after the cast, SkillExecution.PresentEntityMove(entity, from, to, duration, delay) emits it and extends the presentation of that execution until the arrival (IsTurnReady waits for it):

    // The simulation has already placed the unit at its destination: show it moving there after the impact
if (caster.CastSlot(slot, out SkillExecution execution) == SkillCastResult.Success)
{
    float impact = execution.PresentationDuration;
    execution.PresentEntityMove(unit, previousPosition, unit.transform.position, 0.4f, impact);
}

    The IEntityMover backend (PresentationSystem.Movers) plays it. The default, TransformEntityMover, moves the entity's visual transform (VisualResolver; by default the transform of the first Animator below the root), then puts it back to its rest pose under the entity at the arrival, or on a StopAll. The root, read by the world, does not move. An entity without such a child is moved by its root, left at the destination at the end: the world reads that pose for the length of the move. Put the model under a child of the entity (it is usually where the Animator is) or set VisualResolver to keep the root still.

    PresentationDurations.OfDefinition(uuid, library) (or Of(definition), Of(command)) reads the own duration of a definition from code: one-shot effect, sound, shake, animation at its speed; 0 for what plays until stopped. To time an effect at the end of another, or the delay of a move, without a constant.

    Animation and gameplay¶

    Animation never drives gameplay. The data gameplay needs (phases in ticks, bone trajectory, root motion) is extracted in the editor from the clip (AnimationExtractedData, inspector of an AnimationDefinition) and read by the Attack module without playing the clip. An extraction is stale when the clip, its speed or the configuration's tick rate changed since: the inspector flags it, and the data must be extracted again.

    Extract from code¶

    AnimationExtraction (editor, UnleashSkill.Editor.Presentation) does what the Extract button does, with the settings saved in each definition (character, root bone, bones) and the configuration's tick rate:

    Method Extracts
    Extract(definition) One definition. The AnimationExtractionResult gives Success (false without a clip or at zero speed: nothing changed), PhasesFromMarkers and the Messages to display (no phase marker, bone not found, no character chosen)
    ExtractAll(library) / ExtractAll(definitions) Every animation of a PresentationLibrary, or of a list
    ExtractStale(library) / ExtractStale(definitions) Only the stale ones (IsStale(definition)); a definition never extracted is not stale, ExtractAll extracts it
    ConfiguredTickRate Tick rate the extraction uses

    The definitions are changed with Undo and marked dirty, not saved: call AssetDatabase.SaveAssets() after.

    // After a change of the tick rate, or clips downloaded again
List<AnimationExtractionResult> results = AnimationExtraction.ExtractStale(PresentationLibrary.Active);
AssetDatabase.SaveAssets();
foreach (AnimationExtractionResult result in results)
    if (!result.Success)
        Debug.LogWarning($"{result.Definition.name}: {string.Join(" ", result.Messages)}");

    The menu UnleashSkill > Animations > Re-extract stale animations does it for the active library and saves. On the command line (continuous integration), ExtractStaleFromCommandLine does the same, writes the messages as warnings and throws if an extraction fails, which makes Unity quit with the code 1:

    Unity -batchmode -quit -projectPath <project> -executeMethod UnleashSkill.Editor.Presentation.AnimationExtraction.ExtractStaleFromCommandLine

    Marking phases in the clip¶

    With Source on Markers (AnimationPhaseSource.Markers), each extraction reads the phases again from markers named UnleashPhase in the clip; Manual keeps the phases set on the timeline (converted if the tick rate of the configuration changes). The startup starts at tick 0; the markers give the start of the impact and the start of the recovery.

    Marker Read through Convention
    Curve AnimationUtility.GetEditorCurve(clip, EditorCurveBinding.FloatCurve("", typeof(Animator), "UnleashPhase")) 0 startup, 1 impact, 2 recovery
    Events AnimationUtility.GetAnimationEvents(clip), functionName = UnleashPhase stringParameter Active (or Impact) / Recovery, case ignored; empty: intParameter 1 / 2. The earliest event of each phase wins
    • The curve takes precedence: a clip that has the curve is read through it alone, its events are ignored.
    • Rounding: tick of a time in the clip = RoundToInt(time / Speed × TickRate) (nearest tick, at the speed of the definition, Mathf.RoundToInt: a half rounds to the even tick). The curve is evaluated at the time of each tick (tick / TickRate × Speed) and rounded to the nearest whole value: the impact starts at the first tick where it is 1 or more, the recovery at the first tick where it is 2 or more. A linear curve from 0 to 1 therefore switches halfway between its two keys: use constant (stepped) keys.
    • No impact marker: no phases from the markers (the previous ones are kept, a message says so). No recovery marker: the impact lasts until the end of the clip.
    • FBX imports in normalized time: in ModelImporterClipAnimation, events[].time and the keys of curves[].curve are normalized over the clip (0 = first frame, 1 = last frame), Unity's convention for import settings. The imported clip gives them back in seconds, which the extraction reads. A tool that writes the markers from code:
    using UnityEditor;
using UnityEngine;

// Editor script: marks the first clip of an FBX (times normalized: 0 = start of the clip, 1 = end)
var importer = (ModelImporter)AssetImporter.GetAtPath(path);
ModelImporterClipAnimation[] clips = importer.clipAnimations.Length > 0
    ? importer.clipAnimations
    : importer.defaultClipAnimations;

var phase = new AnimationCurve(new Keyframe(0f, 0f), new Keyframe(0.3f, 1f), new Keyframe(0.65f, 2f));
for (int i = 0; i < phase.length; i++)
    AnimationUtility.SetKeyRightTangentMode(phase, i, AnimationUtility.TangentMode.Constant); // steps
clips[0].curves = new[] { new ClipAnimationInfoCurve { name = "UnleashPhase", curve = phase } };

importer.clipAnimations = clips;
importer.SaveAndReimport();

    Events need an AnimationPhaseEventReceiver on the character in Play Mode (otherwise Unity logs AnimationEvent has no receiver on every playback); the curve does not.
