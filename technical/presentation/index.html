    Presentation¶

    User version: Presentation.

    Code: Assets/UnleashSkill/Runtime/Presentation/ (assembly UnleashSkill).

    Principle¶

    Nodes emit intentions; reusable definitions (assets) describe the content; a system materializes them after the simulation.

    nodes / modules ──► PresentationCommandBuffer ──(LateUpdate)──► PresentationSystem ──► backends
                    (UnleashSkillManager.PresentationCommands)       IEffectPlayer, ISoundPlayer, ICameraShaker,
                                                                     IEntityAnimator, IIndicatorPlayer

    Two rules: the presentation never modifies the simulation, and gameplay never holds a Unity presentation object (only UUIDs and handles). Disabled (server, tests, preview without visuals), the queue ignores commands and returns PresentationHandle.None: the fight does not change.

    Emit a command¶

    UnleashSkillManager.PresentationCommands (PresentationCommandBuffer):

    Method Command
    SpawnEffect(uuid, anchor, position, …) / StopEffect(handle) Effect (EffectDefinition)
    PlaySound(uuid, anchor, position, …) / StopSound(handle) Sound (SoundDefinition)
    CameraShake(uuid, position, intensity) Shake (CameraShakeDefinition)
    PlayAnimation(uuid, entityId, speed) / StopAnimation / SetAnimationSpeed Animation (AnimationDefinition)
    ShowIndicator(shape, anchor, …) / UpdateIndicator / HideIndicator Ground indicator (IndicatorShape)

    Anchor (PresentationAnchor): InWorld, OnEntity(entityId, bone), OnBody(bodyId) (interpolated position of the body). To choose a node's points (impact, received targets, caster, module body), PresentationPoints.Collect does the work shared by the Play effect / Play sound nodes.

    The handle is used to stop later: context.Execution.TrackPresentation(key, handle) tracks it in the execution, StopPresentation(key) stops it (Stop effect node), and Cancel / Cleanup stop everything tracked. A one-shot effect does not need to be tracked: it plays until the end.

    Model: PlaySoundModel.OnStart (checks commands.Enabled, emits per point, tracks the handle if the sound loops or has a key, then CompleteNodeInstance whatever happens).

    Library¶

    PresentationLibrary (single global asset, PresentationLibrary.Active): lists of effects, sounds, shakes, module visuals, animations. Each definition (PresentationDefinition) has a stable UUID; models store the UUID (string), never the Unity reference. Resolution: TryGet<T>(uuid, out definition), GetEffect, GetSound… Editing: Presentation section of the main menu.

    ModuleVisualDefinition describes a module's visual: body prefab (with SkillPrefab: pooled, interpolated, no logic) and launch, loop, impact and expiration effects / sounds (ModuleVisualPresenter). A module without a visual stays valid.

    System and backends¶

    PresentationSystem (UnleashSkillManager.Presentation) consumes the queue in LateUpdate (Process(world, deltaTime)), associates each handle with the live instance, follows anchors and entity time (hitstop: animation at speed 0).

    Interface Default (Backends/) Replace for
    IEffectPlayer ParticleEffectPlayer (pools per definition) VFX Graph (planned)
    ISoundPlayer AudioSourceSoundPlayer (pool of AudioSources) FMOD, Wwise
    ICameraShaker SimpleCameraShaker; Cinemachine 3 if present (UnleashSkill.Cinemachine, DefaultPresentationBackends.CameraShakerFactory) The game's camera
    IEntityAnimator PlayablesEntityAnimator (Playables on the Animator, blended with the Animator Controller) The game's animation system
    IIndicatorPlayer LineIndicatorPlayer (LineRenderer outline) Decals, shaders
    IModuleVisualPlayer ModuleVisualPlayer (body prefab of a ModuleVisualDefinition, pool per prefab, colliders disabled) Visual replayed separately

    DefaultPresentationBackends.Install(system, library) connects the defaults to the empty slots; a game assigns before (or replaces) a property of the system (Effects, Sounds, CameraShaker, Animator, Indicators, ModuleVisuals). The resolvers EntityResolver, EntityTimeScaleResolver, EntityCollector link entity identifiers to transforms.

    Delayed commands and replay (turn-based)¶

    A command can carry a delay (PresentationCommand.Delay, presentation seconds): the system keeps it (ScheduledCount, ScheduledDuration) and runs it on time, in presentation time (sum of the Process steps). A command that targets an instance not yet played (stop) waits at least for it to be played. Disabling the presentation clears the queue.

    A node never writes the delay by hand: it is the queue's ambient delay (PresentationCommandBuffer.Delay), set for the duration of a scope by SkillExecution.PresentationAt(delay) (using), which also extends SkillExecution.PresentationDuration. In turn-based mode, every command emitted by the nodes of an execution (start, turn, step) pushes back the end of its presentation by its delay plus its own duration, read from its definition (one-shot effect: emission plus particle lifetime; sound: longest clip; shake; animation without a loop): PresentationDuration, and PresentationRemaining once the frame has started it, which IsTurnReady waits for. A StopAll ends that wait. SkillExecution.Defer keeps the delay of when it was queued: a continuation (result of a query on the selection) is presented with what started it. In real time, the delay stays 0.

    The projectile resolved on the selection (GameObjectModel.ResolveOnSelection) uses it: each target is distributed in a scope at its arrival time (distance / speed of the body at spawn), then ModuleVisualPresenter.OnReplayed emits SpawnModuleVisual, the effect and the loop sound on a travel anchor (PresentationAnchor.Travel(from, to, duration), position interpolated since the instance was played, gone at the end of the travel). The pooler does not instantiate its visual (GameObjectModel.InstantiatesVisual).

    An area or a beam in turn-based mode (GameObjectModel.PresentsVisualInTurns, carrier module whose logic advances in turns) has its visual played by the presentation too: SpawnModuleVisual in the world at the body's pose (per-axis scale PresentationCommand.AxisScale: the module's box), with the loop effect and sound, placed again when the body moves on a turn. Its end (expiration, stop of the visual and of the loop) is emitted in a scope delayed by ModuleVisualDefinition.TurnDisplayDuration after its last activation, so an instant area stays visible and PresentationDuration includes that display. An Attack in turns has its visual played the same way, without that extra display: its end is already replayed at the end of its recovery.

    Animation and gameplay¶

    Animation never drives gameplay. The data gameplay needs (phases in ticks, bone trajectory, root motion) is extracted in the editor from the clip (AnimationClipExtractor, AnimationExtractedData, inspector of an AnimationDefinition) and read by the Attack module without playing the clip. A stale extraction is flagged (IsStale).

    Add a command type¶

    1. Value in PresentationCommandType, required fields in PresentationCommand (struct, no managed reference).
    2. Emission method in PresentationCommandBuffer.
    3. Handling in PresentationSystem.Process and backend interface in PresentationBackends.cs, default implementation in Backends/.
    4. EditMode tests on the emitted commands (PresentationCommandBuffer.Commands), Play Mode on the materialization.
