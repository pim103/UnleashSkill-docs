    Aim, anchors and directions¶

    All the targeting of a skill answers four questions. Each one has a single tool, the same on every node: when a node asks for a position, a direction or targets, it is always one of these four answers.

    Question Tool Decided
    Where is the player aiming? The Aim: a point, a direction, the pointed entity once, at cast time
    Where does this node start, and toward where? An Anchor and a Direction node setting
    Who is affected? The received targets, or a connected Target selection during the skill
    How does the body move? The Movement, or a Trajectory from the library module setting

    The Aim¶

    When the player casts the skill, the tool records where they aim: the aim point (in the play plane), the direction from the caster toward this point, and the pointed entity if there is one. This aim is frozen: if the player moves the mouse while the fireball flies, the fireball does not change its mind.

    • The Aim node shows an indicator, waits for the player to confirm, brings the point back within the skill's range, then replaces the aim of its branch. This is how you make a “click to place an area” skill.
    • Why freeze it? For the same aim, the skill always behaves the same way: the editor preview, turn-based mode and a server replay exactly the same cast. An AI or your code can give the aim themselves (see Cast a skill from code).

    Exception

    A channeled beam that follows the mouse reads the aim continuously. The node says so in its documentation; no other node does it.

    Anchor and Direction¶

    Each node that places something (a projectile, an area, an effect, the center of a fan) has an Anchor field. Each node that orients something has a Direction field. They are the same lists everywhere; a node only offers the values that make sense for it.

    Anchor The position of…
    Caster the one who casts the skill
    Aim point the aim
    Received target the first target received by the node
    Each received target once per target (effects, fan “on the targets”)
    Module body the projectile or the area that carries this node
    Impact point the exact place of the contact
    Named object a named object of the caster
    Direction Goes…
    Toward the aim point from the anchor toward the aim (default of new nodes)
    Caster forward where the caster is looking
    Toward the received target from the anchor toward the first target
    Away from the caster moving away from them (explosion, repulsion)
    Random at random, reproducible

    Follow the branch direction (checked by default): behind a Fork in a fan, each branch receives its own direction, which takes precedence over the field's. This is what sends three projectiles in a fan with a single Spell body.

    Who is affected¶

    A skill reads as a tree of branches. Each connection passes a list of received targets to the next node, and a node only works on the targets of its branch (details in Targets and branches).

    [Start] ─► [Spell body + Movement] ─► [On hit] ──(the target hit)──► [Simple damage]

    The projectile targets nobody: it moves forward. On hit activates on each entity met and opens a branch that only contains this entity. The Damage therefore strikes the target hit, once per contact.

    To choose other targets, use Target selection: a source (around the caster, around the aim point, my summons…) and criteria (team relation, entity type, status, stat, position, sort, count). The node is used in two ways.

    [Target selection] ──Targets──► [Heal]
 3 most wounded allies

    The node runs, searches, and passes the targets found through its Targets output (or No target if nothing is found).

    [Target selection] ┄┄Selection┄┄► [Area]
 enemies, lowest HP, 3

    Its Selection output (cyan port) connects to another node's Selection input. The node is not executed: it tells the other node how to choose. The same Selection can set several nodes. Choose the Provided by the consumer source so that it works on the candidates of the node it sets.

    Node set What the Selection changes
    Area among the entities in the area, keeps those that pass the criteria, sorted from the center (“the 3 most wounded in the area”)
    Chain on each bounce, chooses the next target around the previous one with these criteria and this sort
    Fork the chosen targets replace the received targets, for every pattern
    Summon the summon's target, once its attack behavior exists

    Without a connected Selection, each node keeps its usual behavior.

    Warning

    A Selection connected as a setting ignores its own flow inputs. Do not connect it in the flow as well.

    Examples¶

    Fireball: the Spell body appears on the Caster (anchor); its Movement pushes it Toward the aim point (direction); On hit passes the target hit to the Damage.

    [Start] ─► [Spell body] ─► [On hit] ─► [Simple damage]
               ▲ Movement: Toward the aim point

    Fan of three arrows: Fork (fan, 3, 30°) creates three branches, each with its direction; the same Spell body, whose Movement follows the branch direction, flies in all three.

    [Start] ─► [Fork ×3] ─► [Spell body] ─► [On hit] ─► [Simple damage]

    Meteor shower placed on click: Aim waits for confirmation, brings the point back within range and replaces the aim; the Area appears on the Aim point and the Damage hits the entities inside.

    [Start] ─► [Aim] ─► [Area] ──(entities in the area)──► [Simple damage]
                     anchor: Aim point

    Chain lightning that targets the weakest: without a Selection, Chain bounces on the closest; with a Selection as a setting (enemies, lowest HP), each bounce chooses the most wounded enemy in range.

    [Spell body] ─► [On hit] ─► [Chain] ─► [Simple damage]
                                ▲
      [Target selection] ┄┄┄┄┄┄┘ (Selection)

    Trajectories¶

    The Movement node moves a module forward (line, boomerang, wander, pursuit). To go further, the Trajectory node reads a definition from the library (main menu → Trajectories): a sequence of segments (line, curve toward a point, orbit, pursuit, return), computed in the aim frame (forward = movement direction, side = right). Each segment chooses what happens against a wall (stop, slide, bounce, next segment), up to a maximum number of blocks, whether it hits what it meets in flight or ignores obstacles, and can oscillate (sine wave on the side or in height). A curve can rise to an apex: in 3D, the height is simulated (a lobbed shot passes over an entity and hits an obstacle in the air); in 2D, only the visual rises. The Trajectories tab shows the path, with a time slider and adjustable direction and aim point. The Convert to definition button of a Movement creates the equivalent definition and replaces the node.

    Skills created before these settings¶

    The old fields (spawn point, Fork anchor, Movement direction, Chain filters) are converted on opening, without changing the skill's behavior. They stay hidden in the node's options.

    Before Now
    Main target, Branch target Anchor: Received target
    Aim point, Target point Anchor: Aim point
    Skill prefab parent, Parent module Anchor: Module body
    Forward caster Direction: Caster forward
    Chain filters and sort Target selection connected to Chain
