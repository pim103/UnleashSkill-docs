    Usage¶

    Chooses targets: candidates (the source), filters, a sort and a count.

    Two uses of the same node:

    • In the flow: it runs and fires the “Targets” output (one branch, or one per target) or “No target”.
    • As configuration: its “Selection” output connected to another node's “Selection” input (Chain, Fork, Area, Summon). The node is then never executed and its flow ports are ignored: the consumer reads its settings and applies them itself. The same Selection can configure several nodes.
    Consumer Candidates Settings used
    Chain its own: in range of the previous target filters and sort on each bounce; count ignored
    Fork those of the source (“provided by the consumer”: the received targets) all; one branch per target, capped by Fork Count
    Area the entities in the area, on each activation filters, sort, count (“the 3 most wounded”)
    Summon those of the source reserved for the AttackEnemies behavior (not implemented yet)

    The “provided by the consumer” source (ProvidedByConsumer) is the recommended value as configuration; in the flow, it behaves like “received targets”.
