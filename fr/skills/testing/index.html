    Tester un sort¶

    Trois façons, de la plus rapide à la plus complète.

    1. L'aperçu dans l'éditeur¶

    Bouton Aperçu de l'éditeur de graphe. Le sort se joue à côté du graphe, dans une scène isolée (un monde de simulation à part, qui ne touche pas à votre scène), sur un lanceur et des mannequins.

    Commande Effet
    ⏮ Relancer depuis le début
    ▶ Lecture / pause
    ⏭ Avancer d'un tick
    Vitesse Ralentir ou accélérer la lecture
    Cadrer Recentrer la caméra sur le lanceur et les cibles
    Mise en scène Nombre, disposition et équipe des mannequins, plan 2D ou 3D

    L'aperçu se relance à chaque modification du graphe. Les corps et les recherches du monde s'affichent en surimpression.

    Le menu Présentation a le même aperçu pour une définition seule (effet, son, animation, visuel de module).

    2. Dans une scène¶

    Ajoutez le composant SkillTester sur un lanceur de votre scène (voir Mettre en place une scène) ; le bouton Lier à la scène de l'éditeur de graphe met le sort ouvert dans son emplacement 0. En mode Play :

    • Espace lance l'emplacement 0, les touches 1 à 9 les emplacements 0 à 8 ;
    • l'inspecteur du SkillTester a les mêmes commandes (Lancer le sort, un bouton par emplacement), plus Recharger le graphe du sort, Arrêter tous les sorts actifs et, en mode tour par tour, Avancer le tour (un tour de table : le lanceur, puis chaque entité enregistrée).

    Placez des ennemis, des alliés et des murs autour du lanceur pour essayer le sort dans les situations de votre jeu.

    UnleashSkill → Add Skill Preview to Scene crée un objet Skill Preview (SkillPreviewController). Donnez-lui un Skill Graph : sans rien jouer, la vue Scene dessine la portée des modules du sort depuis l'objet (ou depuis son Caster Transform) et dans sa direction : point d'apparition des corps de module, zones, portée des rayons. L'inspecteur choisit ce qui est dessiné, et Rafraîchir l'aperçu redessine.

    3. Les tests automatiques¶

    Un sort n'est que des données : il se lance sans scène, dans un test EditMode du Unity Test Framework (Window → General → Test Runner), et ses effets se vérifient sur les stats des cibles. Les pièces du moteur sur lesquelles s'appuie un tel test (monde de simulation, entités inscrites sans collider, exécution sans présentation) sont décrites dans Technique → Monde de simulation et Cycle d'un cast.

    Un test complet¶

    Le sort testé ici, Firebolt, est un Corps de sort (Mouvement : vers l'avant, 10 m/s) dont l'Au contact (ennemi, 1 cible) inflige 10 dégâts à la stat health par un Dégâts Simple. L'assembly de test (.asmdef de vos tests EditMode) référence UnleashSkill.

    using System.Collections.Generic;
using NUnit.Framework;
using UnityEditor;
using UnityEngine;
using UnleashSkill;
using UnleashSkill.Configuration;
using UnleashSkill.Execution;
using UnleashSkill.PersistentDataModel;
using UnleashSkill.Simulation;
using UnleashSkill.SkillUtils;

public class FireboltTests
{
    const string Health = "health";
    const string Template = "test-template";

    SkillWorld world;
    UnleashSkillConfiguration previousConfiguration;
    readonly List<Object> created = new List<Object>();
    readonly List<SkillTarget> entities = new List<SkillTarget>();

    [SetUp]
    public void SetUp()
    {
        // 1. A world of its own, without scenery (a wall: World.AddBody on the Obstacle layer)
        world = new SkillWorld(new SimulationSettings { SceneryBackend = StaticSceneryBackend.None });
        UnleashSkillManager.ResetWorld(world);

        // 2. Active configuration: the stats and the stat template of the entities
        var configuration = Track(ScriptableObject.CreateInstance<UnleashSkillConfiguration>());
        var health = Track(ScriptableObject.CreateInstance<StatAsset>());
        health.Initialize(new CustomStat { uuid = Health, statsName = "Health", hasMaximumValue = true });
        configuration.StatAssets.Add(health);
        var template = new StatTemplate { uuid = Template, templateName = "Test" };
        template.floatStats[Health] = new StatInGame<float>
            { customStatUuid = Health, value = 100f, maxValue = 100f, originalValue = 100f };
        configuration.StatTemplates.Add(template);
        previousConfiguration = ConfigurationManager.ActiveConfiguration;
        ConfigurationManager.ActiveConfiguration = configuration;

        // 3. Pooler of the module bodies: in EditMode, AddComponent does not call Awake
        Track(new GameObject("SkillPooler")).AddComponent<SkillPooler>().Init();
    }

    [TearDown]
    public void TearDown()
    {
        foreach (SkillExecution execution in new List<SkillExecution>(UnleashSkillManager.ActiveSkillExecutions))
        {
            if (!execution.IsCompleted)
                execution.Cancel();
            execution.Cleanup();
            UnleashSkillManager.UnregisterActiveSkillExecution(execution);
        }
        foreach (SkillTarget entity in entities)
        {
            SkillEntityRegistry.Unregister(entity);
            entity.Stats?.StopRegeneration();
        }
        entities.Clear();
        foreach (Object obj in created)
            if (obj != null)
                Object.DestroyImmediate(obj);
        created.Clear();
        ConfigurationManager.ActiveConfiguration = previousConfiguration;
        UnleashSkillManager.ResetWorld(null);
    }

    [Test]
    public void Firebolt_HitsTheEnemyAhead_Deals10Damage()
    {
        SkillCaster caster = CreateEntity("players", Vector3.zero);           // faces +Z
        SkillCaster enemy = CreateEntity("monsters", new Vector3(0f, 0f, 5f));
        var skill = AssetDatabase.LoadAssetAtPath<SkillGraphModel>("Assets/Skills/Firebolt.asset");

        Assert.AreEqual(SkillCastResult.Success, caster.Cast(skill, out SkillExecution execution));
        RunUntilCompleted(execution);

        Assert.AreEqual(90f, enemy.Stats.GetStatValue(Health));
    }

    // Entity without a scene: Start and OnEnable do not run in EditMode
    SkillCaster CreateEntity(string team, Vector3 position)
    {
        var gameObject = Track(new GameObject(team));
        gameObject.transform.position = position;
        var entity = gameObject.AddComponent<SkillCaster>();
        entity.teamUuid = team;
        entity.ResetStats(Template);
        SkillEntityRegistry.Register(entity);
        entities.Add(entity);
        return entity;
    }

    // Without the manager's Update: the world advances one tick, then the execution does its frame
    void RunUntilCompleted(SkillExecution execution, int maxTicks = 1000)
    {
        for (int tick = 0; tick < maxTicks && !execution.IsCompleted; tick++)
        {
            world.Step();
            execution.Update();
        }
        Assert.IsTrue(execution.IsCompleted, "The execution did not end");
        UnleashSkillManager.UnregisterActiveSkillExecution(execution);
    }

    T Track<T>(T obj) where T : Object
    {
        created.Add(obj);
        return obj;
    }
}

    Ce que fait chaque étape :

    • Monde : UnleashSkillManager.ResetWorld(world) en fait le monde du moteur. Sans décor (StaticSceneryBackend.None), les colliders de la scène ouverte ne sont pas lus.
    • Configuration : les entités lisent leurs stats dans la configuration active : une construite par le test, comme ici, ou celle de votre projet (AssetDatabase.LoadAssetAtPath<UnleashSkillConfiguration>). Sans teams dans la configuration, deux teamUuid différents sont ennemis.
    • Pooler : un module (Corps de sort, Zone d'effet, Rayon…) prend son objet au SkillPooler. Dans une scène, l'UnleashSkillManager le crée ; dans un test, créez-le et appelez Init(). Sans pooler, le module écrit une erreur et se termine sans ses sorties.
    • Entités : Start et OnEnable ne s'exécutent pas en EditMode. ResetStats(template) donne les stats, SkillEntityRegistry.Register ajoute l'entité au monde. Sans collider, une entité est une capsule de 0,5 m de rayon et 2 m de haut.
    • Ticks : chaque world.Step() avance la simulation d'un tick (corps, touches, nodes persistants) ; execution.Update() constate ensuite la fin de l'exécution, comme le manager à chaque frame.
    • Nettoyage : entre deux tests, annulez les exécutions, retirez les entités du registre, détruisez les objets, rendez la configuration et le monde. Les statuts, recharges et régénérations lancés par un test restent suivis par le moteur jusqu'à leur fin : pour isoler complètement chaque test, ou tester pendant qu'une partie tourne en Play Mode, lancez le sort dans un SimulationSandbox (Technique → État statique et aperçu).

    Les valeurs attendues se lisent de préférence dans les nodes du sort (DamageSimpleModel.Damage…) plutôt qu'en dur dans le test : le test suit le réglage du sort.

    Lire les corps des modules d'une exécution¶

    Pour vérifier où vont les corps des modules d'un sort (directions d'un Diviser, point d'apparition, vitesse), lisez les corps encore en cours dans l'exécution : chaque module en cours a une instance dans SkillExecution.ActiveInstances, dont le RuntimeData est un GameObjectRuntimeData (UnleashSkill.Nodes.Modules) et le Body le corps simulé (ModuleBody).

    // Diviser (Spread, 5 branches sur 30°) → Corps de sort (Mouvement : vers l'avant, 10 m/s)
Assert.AreEqual(SkillCastResult.Success, caster.Cast(skill, out SkillExecution execution));
world.Step();

var angles = new List<float>();
foreach (ActiveNodeInstance instance in execution.ActiveInstances)
{
    if (instance.IsCompleted || !(instance.RuntimeData is GameObjectRuntimeData module) || !module.Body.IsAlive)
        continue;
    Vector3 direction = module.Body.Direction;      // vecteur unitaire
    Vector3 position = module.Body.WorldPosition;
    angles.Add(Vector3.SignedAngle(Vector3.forward, direction, Vector3.up));
}
angles.Sort();   // -15, -7.5, 0, 7.5, 15
    • WorldPosition et WorldVelocity (unités par seconde) sont la position et la vitesse du corps en Vector3, tant qu'il vit (IsAlive). Direction est la direction de sa vitesse, ou l'orientation du module quand il ne bouge pas (zone, rayon, corps pas encore déplacé).
    • Position, Velocity et Rotation sont les mêmes valeurs dans les types de Unity.Mathematics (float3, quaternion) : une assembly qui les lit ajoute Unity.Mathematics aux références de son .asmdef. Les accesseurs Vector3 ne demandent que UnleashSkill.
    • Un corps existe du démarrage du module à sa fin : lisez-le entre deux world.Step(), avant RunUntilCompleted.

    Pour comparer un même sort avec et sans son visuel, choisissez le Visual d'un Corps de sort par code : new GameObjectModel().WithVisual(definition) (ou l'UUID de la définition, null pour un corps invisible). La définition est cherchée dans la bibliothèque de présentation active (PresentationLibrary.Active) au démarrage du module ; une définition créée dans le test s'y ajoute par library.Add(definition).

    Murs et variantes d'un sort¶

    Un mur du test est un corps de la couche Obstacle ajouté au monde. Shape.Box(x, y, z) (demi-tailles en float), WorldPosition et WorldRotation (Vector3, Quaternion) ne demandent que UnleashSkill dans l'assembly de test. Shape.Box(float3) et les champs Position / Rotation sont les mêmes valeurs dans les types de Unity.Mathematics ; il n'y a pas de Shape.Box(Vector3), car une surcharge à côté de Box(float3) demanderait Unity.Mathematics pour compiler l'appel.

    using UnleashSkill.Simulation.Collision;

// Mur de 4 m de large et 0,5 m d'épaisseur, à 3 m devant le lanceur, tourné de 30°
world.AddBody(new Body
{
    Layer = SimulationLayers.Obstacle,
    Shape = Shape.Box(2f, 2f, 0.25f),   // demi-tailles
    WorldPosition = new Vector3(0f, 0f, 3f),
    WorldRotation = Quaternion.Euler(0f, 30f, 0f),
    Active = true
});
    • Que le mur arrête un corps de module dépend de la matrice des couches (Skill / Obstacle : Block par défaut) et du Blocked By Obstacles de l'Au contact qui écoute le corps.
    • Un corps laissé sans rotation n'est pas tourné. Shape.WithOffset(x, y, z) décale la forme dans le repère du corps.

    Pour essayer une variante d'un sort (arrêté par les obstacles, plus de cibles, re-touche), modifiez par code une copie de son graphe, jamais l'asset : WithHitPolicy et WithTargetFilter remplacent le Hit Policy et le Target Filter d'un Au contact (UnleashSkill.Nodes.Conditions).

    SkillGraphModel blocked = Object.Instantiate(skill);   // l'asset reste tel quel
var onHit = (OnHitModel) blocked.Nodes.Find(node => node is OnHitModel);
HitPolicy policy = onHit.HitPolicy;
onHit.WithHitPolicy(new HitPolicy(policy.MaxTargets, policy.Rehit, policy.RehitCooldown,
    ObstacleBlocking.Yes, policy.RequireLineOfSight));   // Blocked By Obstacles : Yes

Assert.AreEqual(SkillCastResult.Success, caster.Cast(blocked, out SkillExecution execution));

    Détruisez la copie à la fin du test (Object.DestroyImmediate, ou Track dans le test complet ci-dessus). D'autres nodes ont les mêmes méthodes pour la construction par code (AreaModel.WithLineOfSight, GameObjectModel.WithVisual…).

    Des tirages reproductibles¶

    Les tirages aléatoires d'une exécution viennent de son propre générateur (SkillExecution.Random) : Chance, Choix aléatoire, Vérifier condition par chance, tri aléatoire d'une Sélection de cibles ou d'un Enchaîner, Diviser en motif aléatoire, Random Angle d'un Diviser, Direction aléatoire, errance d'un Mouvement ou d'un segment Ligne, intervalle aléatoire d'un Délai, coups critiques, Random() dans une formule. Par défaut, sa graine vient de l'identifiant de l'exécution, propre à chaque lancement : deux lancements tirent des valeurs différentes.

    Pour rejouer les mêmes tirages (un test, un replay), fixez la graine avant le premier node, par les options du lancement :

    var options = new SkillCastOptions
{
    InitializeContext = context => context.Execution.SetRandomSeed(42)
};
skill.TryCompute(caster, out SkillExecution execution, options);

    Deux exécutions de même graine, du même graphe et dans la même situation tirent les mêmes valeurs. La présentation (secousses de caméra, effets) n'utilise pas ce générateur.
