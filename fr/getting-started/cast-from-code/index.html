    Lancer un sort par code¶

    Le SkillTester sert à essayer. Dans un vrai jeu, ce sont vos contrôles (joueur) ou votre IA (monstres) qui lancent les sorts, par l'API du SkillCaster.

    Lancer un sort¶

    using UnityEngine;
using UnleashSkill;
using UnleashSkill.Execution;

public class PlayerSkills : MonoBehaviour
{
    [SerializeField] private SkillCaster caster;
    [SerializeField] private SkillGraphModel fireball;

    void Update()
    {
        if (Input.GetKeyDown(KeyCode.Q))
        {
            SkillCastResult result = caster.Cast(fireball, out SkillExecution execution);
            if (result != SkillCastResult.Success)
                Debug.Log($"Lancement refusé : {result}");   // en recharge, pas assez de mana, étourdi…
        }
    }
}

    Input System

    Input.GetKeyDown appartient à l'ancien Input Manager : avec le seul package Input System actif (Project Settings → Player → Active Input Handling : Input System Package (New)), il lève une exception. Lisez alors la touche par l'Input System :

    using UnityEngine.InputSystem;

if (Keyboard.current != null && Keyboard.current.qKey.wasPressedThisFrame)
    caster.Cast(fireball, out SkillExecution execution);

    Les exemples de cette page utilisent Input ; le même remplacement s'y applique (wasReleasedThisFrame pour GetKeyUp).

    Cast vérifie tout avant de lancer : actions bloquées (étourdissement), temps de recharge, coût. Le résultat donne la raison d'un refus. Pour griser un bouton sans rien lancer, utilisez CanCast(graph).

    Par emplacements¶

    Avec un composant SkillSlots sur le lanceur, on lance par numéro d'emplacement. C'est la méthode recommandée : elle gère les combos, les passifs et les emplacements remplacés.

    Méthode Usage
    CastSlot(slot) Lance le sort de l'emplacement.
    PressSlot(slot) / ReleaseSlot(slot) Appui et relâchement d'une touche : nécessaires pour les sorts chargés (le sort part au relâchement) et maintenus (canalisation).
    CanCastSlot(slot) Vérifie sans lancer.
    CancelSlot(slot) Annule l'exécution lancée par la dernière pression.
    GetCooldownRemaining(graph) Temps restant avant relance (secondes, ou tours en tour par tour). 
    for (int slot = 0; slot < 4; slot++)
{
    if (Input.GetKeyDown(KeyCode.Alpha1 + slot)) caster.PressSlot(slot);
    if (Input.GetKeyUp(KeyCode.Alpha1 + slot))   caster.ReleaseSlot(slot);
}

    La visée¶

    Les sorts qui partent vers un point ou une cible lisent la visée du lanceur, que votre contrôleur remplit à chaque frame :

    PointedTarget aim = caster.PointedTarget;
aim.Position = hit.point;                       // point visé (Vector3.positiveInfinity : rien)
aim.Enemy = hit.collider.GetComponent<SkillTarget>();

    PointedTarget a aussi Ally (allié pointé), Spell (corps de module d'un autre sort pointé) et Selection (mode tour par tour, plus bas).

    La visée est figée au lancement (à la fin de l'incantation pour un sort qui en a une) : un projectile parti vers le point visé n'est plus influencé par la souris. Une IA ou un serveur peut donner la visée sans passer par PointedTarget :

    var options = new SkillCastOptions
{
    Aim = SkillAim.Toward(point, caster.transform.position, CollisionPlane.XZ, caster.transform.forward, cible)
};
graph.TryCompute(caster, out SkillExecution execution, options);

    Un sort qui contient un node Visée (ex-Ciblage) suit la souris jusqu'à la confirmation, puis fige ce point pour la suite du sort ; il attend une confirmation : appelez caster.ConfirmTargeting() au clic, caster.CancelTargeting() au clic droit (le coût est rendu). caster.IsAiming indique qu'une visée est en cours.

    Verrouiller votre contrôleur¶

    L'outil déplace une entité pendant un recul, une ruée ou la poussée d'une attaque, et verrouille son déplacement pendant un étourdissement, mais il ne pilote pas votre contrôleur. Votre contrôleur lit les verrous de l'entité et saute son propre déplacement tant qu'elle est verrouillée :

    using UnityEngine;
using UnleashSkill;

[RequireComponent(typeof(CharacterController))]
public class PlayerMovement : MonoBehaviour
{
    [SerializeField] private SkillCaster caster;
    [SerializeField] private float speed = 6f;
    private CharacterController controller;

    void Awake() => controller = GetComponent<CharacterController>();

    void Update()
    {
        Move(new Vector3(Input.GetAxisRaw("Horizontal"), 0f, Input.GetAxisRaw("Vertical")), Time.deltaTime);
    }

    public void Move(Vector3 input, float deltaTime)
    {
        // Recul, ruée, étourdissement, enracinement, poussée d'une attaque : le sort déplace l'entité (ou rien ne bouge), pas l'entrée
        if (caster.IsMovementLocked)
            return;

        controller.Move(Vector3.ClampMagnitude(input, 1f) * speed * deltaTime);
    }
}
    Propriété Vraie tant que
    IsMovementLocked un sort déplace l'entité (option Lock Controller During Forced Movement, jusqu'au tick qui suit le dernier déplacement), un statut la verrouille (Stunned, Rooted d'une configuration neuve), une esquive ou une phase d'attaque qui verrouille le déplacement est en cours.
    IsActionLocked l'entité ne peut plus lancer de sort (Stunned, phase d'attaque qui verrouille les actions) : Cast et CanCast refusent déjà (ActionLocked). Lisez-la pour griser la barre de sorts.

    L'événement OnLockChanged est levé au début et à la fin d'un verrou (animation du personnage étourdi, par exemple). Votre code peut verrouiller l'entité lui-même : caster.Lock(source, EntityLockFlags.Movement), puis caster.Unlock(source).

    Interrompre¶

    • caster.CancelSkill() interrompt tous les sorts en cours du lanceur, caster.CancelSkill(graph) ceux d'un sort.
    • À la mort ou à la désactivation du lanceur, ses sorts en cours sont annulés, sauf ceux réglés pour lui survivre (voir Paramètres d'un sort).

    Tour par tour¶

    En mode tour par tour (configuration, Paramètres généraux), les durées se comptent en tours : appelez AdvanceTurn() une fois par tour de chaque entité, par exemple à la fin de son tour. C'est le seul moment où ses effets à durée avancent :

    • Lanceur (caster.AdvanceTurn()) : ses sorts en cours (incantation, zone, rayon canalisé, Délai, Répéter, Timer), ses statuts, puis ses temps de recharge.
    • Autre entité (cible.AdvanceTurn(), un SkillTarget) : ses statuts. La brûlure posée par une Boule de feu avance au tour de la cible qui brûle, pas à celui du lanceur.

    Un champ de durée garde une seule valeur : la même se lit en secondes en temps réel et en tours en tour par tour, sans conversion au changement de mode. L'éditeur affiche l'unité selon le mode (« Duration (tours) »). Une durée est arrondie au tour supérieur (0,5 → 1 tour), une cadence est un nombre entier de tours (1 = à chaque tour). Les champs continus (croissance d'une zone, vitesse et portée du Mouvement) sont marqués visuel seulement : ils n'ont pas d'effet sur le jeu.

    Un sort se résout instantanément, dans l'appel qui le lance : pas de vol de projectile ni de détection dans l'espace. Ses cibles sont celles que le joueur a sélectionnées avant le lancement :

    caster.PointedTarget.Selection.Clear();
caster.PointedTarget.Selection.Add(cible);   // une ou plusieurs entités
caster.CastSlot(0);                          // dégâts, statuts… appliqués avant le retour

    Sans liste, l'ennemi visé (PointedTarget.Enemy), puis l'allié visé (PointedTarget.Ally), font office de sélection.

    Module En tour par tour
    Projectile, Corps de sort Touche directement les entités sélectionnées. Son Au contact garde son filtre (ennemi, allié) et son nombre de cibles : une Boule de feu à 1 cible touche la première sélectionnée.
    Zone d'effet Une activation au lancement sur les entités sélectionnées (où qu'elles soient). Avec une durée, une activation à chaque tour de sa cadence, sur les mêmes entités (celles du lancement), puis la zone se termine à la fin de sa durée en tours.
    Rayon Instant : un tir. Delayed : un tir après son délai en tours. Channeled : un tir au lancement puis un à chaque tour de sa cadence pendant sa durée en tours. Toujours sur les entités sélectionnées au lancement.
    Attaque Se résout dans le tour où elle est lancée : ses phases s'enchaînent aussitôt (Phase d'attaque entend chacune), l'impact touche une fois chaque entité sélectionnée, où qu'elle soit, puis l'attaque se termine. Les durées de ses phases ne règlent que la relecture ; le lanceur ne bouge pas.
    Invocation Sa durée de vie se compte en tours du lanceur : une invocation de 3 tours disparaît pendant le troisième AdvanceTurn() du lanceur. Son déplacement et son contact (Au contact) restent au tick du monde.
    Chain Rebondit seulement entre entités sélectionnées, à portée du rebond.
    Ciblage Ne vise pas : il fige la sélection du moment pour les modules qui suivent.
    Délai, Répéter, Timer Leur délai, leur intervalle et leur durée se comptent en tours du lanceur.
    Incantation Se compte en tours du lanceur (Paramètres du sort, « Incantation (tours) ») : une incantation de 2 tours lance le sort pendant le deuxième AdvanceTurn() du lanceur, sur la sélection de ce moment ; 0 : le sort se résout dans l'appel. La sortie Pendant l'incantation tourne entre-temps (ses Délais avancent aux mêmes tours), une interruption annule le sort et rend son coût. Une incantation chargée sans touche part à son minimum en tours. CastInTurns est vrai et CastRemaining est en tours, pour une barre d'incantation.
    Statuts Durée et période (comportement Périodique) en tours du porteur : une brûlure de 2 tours à période 1 fait un tick à chacun des deux tours de la cible, puis expire.

    Le sort reste actif tant qu'une zone, un rayon canalisé ou un délai n'est pas fini : il se termine pendant le AdvanceTurn() qui atteint la fin de sa durée. Le monde n'a pas besoin de tourner entre deux tours ; s'il tourne (pour le visuel), il ne fait pas avancer ces durées.

    Un mur (Bloquant) reste immobile en tour par tour ; sa durée de vie se compte en tours.

    Relecture visuelle. Le combat est résolu dans l'appel, mais sa présentation est rejouée dans le temps : le visuel d'un projectile vole de son point d'apparition jusqu'à sa cible à la vitesse de son Mouvement, et l'impact (effet, son, et tout ce que lancent ses nodes Au contact : dégâts affichés, statuts) est présenté à son arrivée. Avec plusieurs cibles (perçage), chacune est présentée à son heure d'arrivée et le visuel vole jusqu'à la plus lointaine. Un projectile sans mouvement présente tout au lancement. Un impact réglé « à l'arrêt » est joué sur le contact qui termine le projectile (son Au contact atteint son nombre de cibles), sinon sur la cible la plus lointaine. La durée totale est connue dès le retour du lancement : le dernier impact relu, plus la durée propre des effets qu'il lance (effet ponctuel, son, secousse, animation, lue dans la bibliothèque de présentation) :

    SkillExecution execution = …;                 // exécution lancée (déjà terminée côté jeu)
float attente = execution.PresentationDuration; // secondes jusqu'à la fin du dernier effet

    Sans présentation (Presentation Enabled décoché, voir Simulation), aucun visuel de module n'est créé et la durée vaut 0.

    Zones et rayons. Leur visuel est affiché au lancement et reste en place tant qu'ils durent (une zone qui suit son lanceur ou sa cible se déplace avec lui à chaque tour). Après sa dernière activation, il reste visible la Turn Display Duration de son Module Visual (1 seconde par défaut), puis sa fin est présentée (effet et son d'expiration, visuel retiré). Une zone ou un rayon instantanés, résolus dans l'appel du lancement, sont ainsi visibles cette durée, comptée dans PresentationDuration.

    Attendre avant le tour suivant. Votre gestionnaire de tours n'a pas à calculer cette attente : l'exécution dit quand le tour suivant peut commencer, selon le réglage Turn wait (configuration, Paramètres généraux ; un sort peut le remplacer dans ses Paramètres du sort) :

    Turn wait IsTurnReady devient vrai
    Presentation (par défaut) Une fois la logique du lancement résolue et sa présentation jouée (PresentationRemaining à 0).
    Execution Une fois la logique du lancement résolue, sans attendre les effets.
    None Tout de suite.

    La logique est résolue (IsTurnLogicResolved) quand l'exécution est terminée, ou qu'elle n'attend plus que des tours : une incantation, une zone, un rayon canalisé, un Délai compté en tours ne retiennent pas le tour ; une visée, une ruée ou un module encore compté en secondes (Attaque) le retiennent.

    caster.CastSlot(0);
SkillExecution execution = …;
execution.TurnReady += e => gestionnaireDeTours.TourSuivant(); // levé une fois, après la frame qui rend le tour prêt

    TurnReady est levé par la frame de présentation du manager (présentation désactivée comprise), dès la première frame après le lancement pour un sort prêt tout de suite. Après AdvanceTurn(), ce que le tour lance (sorties d'un Délai échu) est attendu de la même façon et TurnReady est levé de nouveau. Vous pouvez aussi interroger IsTurnReady.

    Faire mourir une entité¶

    Une stat réglée pour « tuer à zéro » (les PV) fait mourir l'entité. Le jeu peut aussi la tuer lui-même avec TriggerEntityDeath(). Par défaut, un SkillCaster mort annule ses sorts et se désactive ; redéfinissez OnEntityDeath() pour changer ce comportement (animation de mort, ragdoll…).
