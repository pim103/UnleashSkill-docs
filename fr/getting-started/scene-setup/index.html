    Mettre en place une scène¶

    Une scène qui lance des sorts a besoin de trois choses : une configuration, un manager et des entités (lanceurs et cibles). Cette page construit pas à pas une scène de test : un joueur et un ennemi face à face.

    1. Vérifier la configuration¶

    La configuration (UnleashSkillConfiguration) contient toutes les données du jeu : stats, teams, types d'entité, statuts… Les nodes y piochent leurs valeurs dans des listes.

    • À la première ouverture, l'éditeur a créé une configuration par défaut dans Assets/UnleashSkillData/UnleashSkillConfiguration.asset (voir Installation) : UnleashSkill → Main Menu la charge automatiquement.
    • Charger une configuration en choisit une autre, Créer une configuration part d'une configuration vide. Ou : clic droit dans la fenêtre Project → Create → UnleashSkill → Configuration.

    La configuration chargée est la configuration active de l'éditeur : toutes les listes déroulantes des nodes et des inspecteurs la lisent. Elle est conservée après une recompilation ou un redémarrage de Unity (la dernière chargée, sinon celle du projet). Chaque section est détaillée dans Configuration.

    2. Ajouter le manager¶

    1. Créez une nouvelle scène (File → New Scene, modèle Basic) et enregistrez-la.
    2. Créez un GameObject vide (GameObject → Create Empty), nommé UnleashSkill.
    3. Ajoutez-lui le composant UnleashSkillManager.

    C'est le point central de l'outil en jeu : il possède le monde de simulation, les exécutions de sorts en cours, la réserve de visuels et le système de présentation. À l'ajout du composant, ses champs sont remplis avec les données du projet :

    Champ Rôle
    Default Configuration Configuration chargée au lancement du jeu. Obligatoire : sans elle, les nodes qui lisent une stat ou un type ne trouvent rien.
    Presentation Library Bibliothèque d'effets, de sons, de tremblements, de visuels de module et d'animations. Vide : celle du dossier des données (Presentation/PresentationLibrary.asset), lue par l'éditeur et donnée au manager par le build.
    Trajectory Library Bibliothèque des trajectoires lues par le node Trajectoire. Même règle : vide, celle du dossier des données (TrajectoryLibrary.asset).
    Original Prefab Facultatif. Objet de base des visuels de sort, copié pour chaque corps de sort. Vide : un objet vide intégré.

    Un manager par scène.

    Rien n'est à remplir à la main pour un build : chaque scène construite donne à son manager les bibliothèques du projet qui lui manquent (la scène du projet n'est pas modifiée). Si le projet n'en a aucune, le build l'écrit dans la console, et le manager le redit au lancement du jeu. Un manager créé par code en jeu n'est pas complété : placez-le dans la scène, ou réglez PresentationLibrary.Active et TrajectoryLibrary.Active après l'avoir créé.

    3. Créer les entités¶

    Toute entité qui lance des sorts ou en reçoit (joueur, monstre, mannequin, invocation) porte le composant SkillCaster.

    1. Le joueur : GameObject → 3D Object → Capsule, nommée Player, en position (0, 1, 0). Ajoutez le composant SkillCaster. À l'ajout, il reçoit la première team, le premier type d'entité et le premier template de stats de la configuration active ; avec la configuration par défaut :
      • Entity Type : Character ;
      • Team : Player ;
      • Stat Template : Default.
    2. L'ennemi : une autre capsule nommée Enemy, en position (0, 1, 8), soit 8 mètres devant le joueur (son axe bleu, forward). Ajoutez un SkillCaster et passez sa team à Enemy (type Character, template Default).

    Un champ vide

    L'inspecteur signale une Team, un Entity Type ou un Stat Template vide. Deux entités sans team sont alliées : un sort filtré sur les ennemis (Au contact sur Enemy) ne les touche jamais. Un SkillCaster ajouté par code ne reçoit rien : réglez ses champs vous-même.

    L'inspecteur d'un SkillCaster propose :

    Réglage Rôle
    Entity Type Type de l'entité (Joueur, Monstre…), lu par les filtres « Type d'entité ».
    Team Équipe. Deux entités de la même team sont alliées ; un sort a la team de son lanceur.
    Stat Template Template de stats de départ (HP, mana…).
    Is Targetable Décoché : l'entité n'est jamais choisie comme cible.
    Lock Controller During Forced Movement Bloque votre contrôleur de personnage pendant un déplacement imposé par un sort (voir plus bas).
    Sliders d'interface Barres d'interface à mettre à jour pour les stats qui en ont une.

    Quand sa vie (HP) atteint zéro, un SkillCaster meurt : il annule ses sorts et son GameObject est désactivé.

    Formes touchables (hurtbox)¶

    Les sorts touchent les entités par leurs hurtboxes, des formes simples (sphère, capsule, boîte) inscrites dans le monde de simulation. Sans réglage, une entité reçoit une capsule déduite de son collider ou de son renderer : les capsules de cette scène n'ont besoin de rien d'autre. Pour la régler, ajoutez le composant Hurtbox (menu UnleashSkill/Hurtbox) : une ou plusieurs formes, et un tag facultatif (tête, point faible) transmis avec les impacts.

    Les colliders Unity ne servent pas aux sorts

    Les sorts ne lisent ni Physics ni les colliders des entités : tout passe par le monde de simulation. Un collider reste utile à votre contrôleur de personnage et au décor statique.

    Déplacements imposés par un sort¶

    Un recul, une ruée ou une attraction déplace l'entité par le composant qu'elle a : CharacterController d'abord, sinon Rigidbody, sinon directement le transform. Pendant un déplacement imposé, le contrôle du joueur est bloqué (option Lock Controller During Forced Movement du SkillCaster).

    Emplacements de sort¶

    Pour lancer des sorts par touches (emplacement 1, 2, 3…), le lanceur a un composant SkillSlots qui contient ses sorts. Voir Emplacements, passifs et combos.

    4. Tester sans code¶

    Ajoutez le composant SkillTester sur Player (il ajoute SkillSlots avec lui). En mode Play, il lance l'emplacement 0 avec Espace et les emplacements 0 à 8 avec les touches 1 à 9 : de quoi essayer vos sorts avant de les brancher sur vos propres commandes (Lancer un sort par code). Le bouton Lier à la scène de l'éditeur de graphe met le sort ouvert dans l'emplacement 0 du SkillTester de la scène. Sans SkillTester dans la scène, il propose d'en créer un : un objet Skill Tester à l'origine, avec un SkillCaster (team, type et template de la configuration active) et le SkillTester, plus un objet Skill Controller avec l'UnleashSkillManager si la scène n'en a pas. Placez-le et vérifiez sa team avant de jouer.
