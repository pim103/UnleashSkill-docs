    État statique et aperçu¶

    Pourquoi c'est important¶

    Le moteur lit beaucoup d'états par des statiques : UnleashSkillManager.World, la présentation, les exécutions actives, SkillEntityRegistry, les steppers (statuts, blocages, combos, recharges, régénération), SpellInstanceRegistry, les attaques et esquives en cours de chaque lanceur, SkillPooler, le pool des murs, UnityEngine.Random. C'est simple et rapide : une partie tourne par processus.

    Mais l'aperçu de l'éditeur (Editor/Preview/SkillPreviewSession) simule un sort pendant qu'un autre monde peut exister (le jeu en Play, les tests). Il le fait dans un SimulationSandbox (Simulation/SimulationSandbox.cs) : le temps d'une portée, chaque statique du moteur est échangée avec celle du bac à sable, puis rendue.

    Simuler dans un bac à sable¶

    var world = new SkillWorld(new SimulationSettings { SceneryBackend = StaticSceneryBackend.None });
var sandbox = new SimulationSandbox(world, presentation: null, seed: 0);
var created = new List<GameObject>();

using (sandbox.Enter())
{
    // Here, UnleashSkillManager.World, SkillEntityRegistry, SkillPooler… are the sandbox's

    // The sandbox has no pooler (the game's is swapped out): one for the module bodies, in EditMode without Awake
    var pooler = new GameObject("SkillPooler");
    created.Add(pooler);
    pooler.AddComponent<SkillPooler>().Init();

    SkillCaster caster = CreateEntity("players", Vector3.zero, created);
    SkillCaster enemy = CreateEntity("monsters", new Vector3(0f, 0f, 5f), created);

    caster.Cast(skill, out SkillExecution execution);
    for (int tick = 0; tick < 1000 && !execution.IsCompleted; tick++)
    {
        world.Step();
        execution.Update();
    }
}
// Out of scope: the game gets its state back intact

// Cancels what remains, removes the entities from the registry, then destroys the objects inside the scope
sandbox.Dispose(() =>
{
    foreach (GameObject gameObject in created)
        Object.DestroyImmediate(gameObject);
});

static SkillCaster CreateEntity(string team, Vector3 position, List<GameObject> created)
{
    var gameObject = new GameObject(team);
    created.Add(gameObject);
    gameObject.transform.position = position;
    var entity = gameObject.AddComponent<SkillCaster>();
    entity.teamUuid = team;
    entity.ResetStats("test-template");        // Start does not run in EditMode
    SkillEntityRegistry.Register(entity);      // nor does OnEnable: registered in the sandbox's registry
    return entity;
}

    Tout ce qui touche à la simulation du bac à sable (placer une entité, lancer, avancer d'un tick, détruire ses objets) se fait dans une portée. Le bac à sable appelle les écouteurs d'étape du moteur sur son propre monde.

    • Pooler : un bac à sable commence sans SkillPooler : un module (Corps de sort, Zone d'effet, Rayon…) en demande un, créé et initialisé (Init()) dans la portée. Sans lui, le module écrit une erreur et se termine sans ses sorties.
    • Entités : hors Play Mode, Start et OnEnable ne s'exécutent pas : teamUuid, ResetStats(template) (template de la configuration active) et SkillEntityRegistry.Register, dans la portée.
    • Configuration : le bac à sable lit la configuration active (ConfigurationManager.ActiveConfiguration), qu'il n'échange pas.
    • Nettoyage : Dispose(destroyObjects) annule les exécutions encore actives, retire les entités du registre du bac à sable, arrête sa présentation, puis appelle destroyObjects dans la portée.
    • Exécutions terminées : sans l'Update du manager, une exécution terminée reste dans ActiveSkillExecutions (sandbox.Executions) jusqu'à UnleashSkillManager.UnregisterActiveSkillExecution ou Dispose (Diagnostiquer et mesurer).
    • Redémarrage : UnleashSkillManager.ResetWorld() dans une portée annule les exécutions du bac à sable et recrée aussitôt son monde, avec une copie des réglages du monde remplacé, son décor, son autorité et ses gestionnaires d'avertissements et d'exceptions (jamais les réglages de la configuration, ni son décor) ; sandbox.World rend alors le nouveau monde. Pour tester un redémarrage avec un monde à soi, appeler ResetWorld(world) avec un monde sans décor.
    • Graine : le seed du constructeur est celui d'UnityEngine.Random dans la portée. Les tirages d'une exécution ont leur propre graine, fixée par SkillExecution.SetRandomSeed (Sorts → Tester un sort).

    L'échange couvre : monde, présentation, exécutions actives (et les événements ExecutionStarted / ExecutionEnded : l'aperçu ne prévient pas les abonnés du jeu), SkillEntityRegistry, les steppers des statuts, blocages, combos, recharges et régénération, SpellInstanceRegistry, les attaques et esquives en cours de chaque lanceur (AttackCancellation), les murs d'entité, SkillPooler, UnityEngine.Random.

    La langue de l'éditeur (Localizer) est aussi un état statique, mais elle n'est pas lue pendant un tick : la simulation n'en dépend jamais.

    L'état d'un add-on¶

    La liste des états échangés est interne au moteur : un add-on ne peut pas y ajouter le sien. Un add-on garde donc son état par monde sur le SkillWorld (une instance de son écouteur d'étape, ou un dictionnaire indexé par monde), jamais dans un statique lu pendant un tick. Sinon, l'aperçu écrit dans l'état du jeu (ou l'inverse) : entités fantômes, statuts qui avancent deux fois, tests qui fuient de l'un à l'autre.

    Un objet que l'add-on crée sans parent pendant la simulation (un GameObject racine) passe par SimulationSandbox.AdoptCreated(gameObject) : dans un bac à sable, l'aperçu le range dans sa scène et le détruit avec lui ; hors bac à sable, rien ne se passe.

    Recommencer une partie¶

    Hors aperçu, UnleashSkillManager.ResetWorld() (monde recréé à la demande) ou ResetWorld(world) (monde fourni, sans décor pour un test Play Mode) et ResetPresentation(...) remettent le moteur dans un état connu. Ils ne touchent pas à ce que porte chaque entité. Pour recommencer une partie sans recharger la scène (fin de partie, nouvel essai), appeler dans cet ordre :

    1. UnleashSkillManager.ResetWorld() : annule toutes les exécutions actives (sorts lancés, passifs, sorts qui survivent à leur lanceur ; ExecutionEnded pour chacune), puis remplace le monde. WorldChanged est levé : les abonnés du jeu se réabonnent au nouveau bus (Événements).
    2. UnleashSkillManager.ResetPresentation() : arrête les effets, sons et tremblements en cours, libère les backends ; la présentation est recréée au prochain accès, d'après la configuration active.
    3. caster.ResetEntity() sur chaque lanceur qui reste dans la scène : stats recréées d'après son template, statuts, verrous et cooldowns retirés, vivant à nouveau (un lanceur désactivé par sa mort est réactivé), passifs relancés (ResetWorld les a terminés).
    4. Le jeu remet ce qui lui appartient : positions, entités qu'il a fait apparaître (détruites ou rendues à ses pools), tags, emplacements (SkillSlots.EndAllReplacements), visée (AimDirectionOverride, PointedTarget).
