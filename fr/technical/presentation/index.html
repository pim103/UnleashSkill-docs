    Présentation¶

    Version utilisateur : Présentation.

    Code : Assets/UnleashSkill/Runtime/Presentation/ (assembly UnleashSkill).

    Principe¶

    Les nodes émettent des intentions ; des définitions réutilisables (assets) décrivent le contenu ; un système les matérialise après la simulation.

    nodes / modules ──► PresentationCommandBuffer ──(LateUpdate)──► PresentationSystem ──► backends
                    (UnleashSkillManager.PresentationCommands)       IEffectPlayer, ISoundPlayer, ICameraShaker,
                                                                     IEntityAnimator, IIndicatorPlayer

    Deux règles : la présentation ne modifie jamais la simulation, et le gameplay ne tient jamais d'objet Unity de présentation (seulement des UUID et des handles). Désactivée (serveur, tests, aperçu sans visuel), la file ignore les commandes et rend PresentationHandle.None : le combat ne change pas.

    Émettre une commande¶

    UnleashSkillManager.PresentationCommands (PresentationCommandBuffer) :

    Méthode Commande
    SpawnEffect(uuid, anchor, position, …) / StopEffect(handle) Effet (EffectDefinition)
    PlaySound(uuid, anchor, position, …) / StopSound(handle) Son (SoundDefinition)
    CameraShake(uuid, position, intensity) Tremblement (CameraShakeDefinition)
    PlayAnimation(uuid, entityId, speed) / StopAnimation / SetAnimationSpeed Animation (AnimationDefinition)
    ShowIndicator(shape, anchor, …) / UpdateIndicator / HideIndicator Indicateur au sol (IndicatorShape)
    MoveEntity(entityId, from, to, duration, delay) Déplacement du visuel d'une entité, présentation seule (Déplacer une entité)

    Les indicateurs sont des formes continues (IndicatorShapeKind : cercle, anneau, cône, rectangle, ligne, tracé), pensées pour le temps réel : une forme, une teinte. Ce sont des commandes de présentation : présentation désactivée, rien ne s'affiche. Dans un jeu sur une grille, la portée et la zone en cases sont à l'interface de votre jeu, pas à ShowIndicator.

    Un tracé (IndicatorShapeKind.Path, IndicatorShape.ForPath(path, color, plane)) est une polyligne : les points d'un IndicatorPath, dans le repère local de la commande, dessinés pleins jusqu'à DashedFrom, puis en pointillé. C'est la trajectoire prévue du node Visée. Le tracé est une référence lue quand la présentation exécute la commande : gardez vos propres instances et n'en modifiez pas une avant la frame de présentation suivante (la Visée en alterne deux). Le backend par défaut (LineIndicatorPlayer) dessine le pointillé avec une texture de tirets répétée ; LineIndicatorPlayer.BuildPath et BuildDashes donnent les mêmes lignes à votre propre backend.

    // Trajectoire prévue d'une définition, coupée au premier obstacle, affichée en tracé
var points = new List<TrajectoryPreviewPoint>();
TrajectoryPreview.Sample(definition, start, forward, aimPoint,
    new TrajectoryPreviewSettings { Caster = caster, Plane = plane, Step = world.TickDuration }, points);
cut.Submit(world, points, bodyShape, rotation, filter);   // TrajectoryObstacleCut, gardé d'un tick à l'autre
cut.Apply(points);                                         // dernier balayage répondu : un tick de retard
TrajectoryPreview.ToIndicatorPath(points, start, path);
commands.UpdateIndicator(handle, IndicatorShape.ForPath(path, color, plane), start, quaternion.identity);

    TrajectoryPreview.Sample est pure (ni monde, ni tick, jamais un tirage de l'exécution) : elle joue la définition avec le TrajectoryRunner du jeu, si bien que sans obstacle les positions prévues sont les positions simulées. Un point est Uncertain à partir de la première Poursuite, du premier Retour ou de la première Ligne qui erre. TrajectoryObstacleCut balaie le monde le long de la polyligne (ModuleQuery.Sweep, au plus MaxSweeps cordes droites), jamais une requête physique ; un nouveau lot part quand le précédent a répondu. Le rejeu du tour par tour peut échantillonner une trajectoire de la même façon pour animer un visuel.

    Ancrage (PresentationAnchor) : InWorld, OnEntity(entityId, os), OnBody(bodyId) (position interpolée du corps). Pour choisir les points d'un node (impact, cibles reçues, lanceur, corps du module), PresentationPoints.Collect fait le travail commun aux nodes Jouer effet / Jouer son.

    Travel(from, to, duration) déplace l'instance en ligne droite de from à to (espace monde), tournée vers l'arrivée. Il n'est pas réservé au rejeu du tour par tour : un node peut aussi l'émettre en temps réel, pour tout ce qui va d'un point à un autre sans corps dans le monde (un arc électrique entre deux cibles, une traînée vers le lanceur). La durée se compte en temps de présentation (somme des pas de Process, le temps de la frame ; ni le tick de la simulation ni les zones de temps du monde ne s'y appliquent), depuis le moment où l'instance est jouée, après son délai si elle en a un. À l'arrivée, l'ancrage disparaît et l'instance est arrêtée comme celle dont l'entité a disparu : un effet de particules cesse d'émettre, puis finit quand ses particules sont terminées ; un son en boucle s'arrête. Un effet ponctuel plus court que le trajet finit de lui-même avant.

    // Effet qui voyage de la cible précédente à la cible courante en 0,1 s (temps réel)
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
if (commands.Enabled)
    commands.SpawnEffect(trailUuid, PresentationAnchor.Travel(from, to, 0.1f), float3.zero, quaternion.identity, 1f,
        caster.EntityId);

    Recette : un effet qui voyage d'un point à un autre¶

    Sans code, le node Jouer effet le fait : cocher Travel, choisir l'arrivée avec Emit At et le départ avec Travel From (une commande Travel par point d'émission, départ résolu une fois). Derrière un Enchaîner, Travel From = Rebond précédent dessine un trait de chaque cible à la suivante : la branche de chaque rebond porte son indice, l'entité et le point d'où il part (SkillExecutionContext.ChainBounceIndexKey, ChainPreviousTargetKey, ChainPreviousPointKey), lus par l'ancre SkillAnchorSource.PreviousBounce (SkillAnchor.TryGetPreviousBounce). Sans Enchaîner en amont, l'ancre retombe sur le lanceur et l'analyse du flux avertit (W118, GraphFlowCodes.PreviousBounceNeverReceived).

    Depuis un node à vous, lire les deux points dans la branche, puis émettre la commande :

    // Dans OnStart d'un node derrière un Enchaîner : trait du rebond précédent à la cible reçue
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
SkillTarget target = context.GetPrimaryTarget();
if (commands.Enabled && target != null && SkillAnchor.TryGetPreviousBounce(context, out Vector3 from))
    commands.SpawnEffect(trailUuid, PresentationAnchor.Travel(from, target.transform.position, 0.1f),
        float3.zero, quaternion.identity, 1f, caster.EntityId, target.EntityId);
context.Execution.CompleteNodeInstance(this, caster);
    • L'effet : lui donner de quoi rester visible en chemin (un Trail Renderer, des particules simulées en espace monde) ; sa propre position n'est que la tête du trajet.
    • Durée : en temps de présentation, un hitstop ou une zone de temps ne le ralentit donc pas ; 0 place l'instance à l'arrivée et la termine aussitôt.
    • Gameplay : rien ne lit le trajet, et présentation désactivée, aucune commande n'est émise. Un trait qui doit toucher quelque chose est un module avec un corps (un projectile), pas une présentation.

    Un rayon dessiné jusqu'au mur est l'autre visuel à deux points : un module Rayon dont le visuel a Stretch To Length (ModuleVisualDefinition.StretchToLength) reçoit en Z de l'échelle de son prefab de corps la longueur effective de son dernier tir (GameObjectRuntimeData.PresentedLength : jusqu'au premier obstacle qui l'arrête, sinon sa portée), appliquée à chaque frame par le pooler en temps réel et par SpawnModuleVisual (AxisScale) en tour par tour. Modéliser le prefab long d'un mètre selon +Z depuis son pivot. Un visuel à vous peut lire GameObjectRuntimeData.VisualScale.

    Le handle sert à arrêter plus tard : context.Execution.TrackPresentation(clé, handle) le suit dans l'exécution, StopPresentation(clé) l'arrête (node Arrêter effet), et Cancel / Cleanup arrêtent tout ce qui est suivi. Un effet ponctuel n'a pas besoin d'être suivi : il joue jusqu'au bout.

    Modèle : PlaySoundModel.OnStart (vérifie commands.Enabled, émet par point, suit le handle si le son boucle ou a une clé, puis CompleteNodeInstance quoi qu'il arrive).

    Bibliothèque¶

    PresentationLibrary (asset unique et global, PresentationLibrary.Active) : listes d'effets, sons, tremblements, visuels de module, animations. Chaque définition (PresentationDefinition) a un UUID stable ; les models stockent l'UUID (chaîne), jamais la référence Unity. Résolution : TryGet<T>(uuid, out définition), GetEffect, GetSound… Édition : section Présentation du menu principal.

    Depuis un graphe construit par code. Un graphe désigne une définition par son UUID. Deux façons de l'obtenir, à la construction :

    PresentationLibrary library = PresentationLibrary.Active;

// Par le nom d'un asset de la bibliothèque : exact, le premier du type (un nom n'est pas unique). Null s'il n'y en a pas
var visual = library.FindByName<ModuleVisualDefinition>("Fireball");
var body = new GameObjectModel().WithVisual(visual);

// Avec un UUID choisi par le jeu, comme les identifiants des teams, stats et statuts
var impact = PresentationDefinition.Create<EffectDefinition>("my-game.fireball.impact", "Fireball impact");
library.Add(impact);   // false si l'UUID est pris

    Une définition est résolue dans la bibliothèque active au démarrage du module : celle créée par code doit y être à ce moment. Create fait une définition en mémoire : elle n'est pas enregistrée avec le projet, et le jeu la recrée à chaque lancement. FindByName parcourt les listes : à appeler en construisant le graphe, pas à chaque tick.

    ModuleVisualDefinition décrit le visuel d'un module : prefab du corps (avec SkillPrefab : poolé, interpolé, sans logique) et effets / sons de lancement, de boucle, d'impact et d'expiration (ModuleVisualPresenter). Un module sans visuel reste valide. Qui porte le prefab du corps dépend du mode : en temps réel, le SkillPrefab du module, pris au SkillPooler (compteurs : SkillPooler.Current.ActiveVisualCount…) ; en tour par tour, pour un module rejoué par la présentation (résolu sur la sélection, zone ou rayon en tours), l'IModuleVisualPlayer (ModuleVisualPlayer.ActiveCount, qui reste à 0 en temps réel). Voir Diagnostiquer et mesurer.

    Système et backends¶

    PresentationSystem (UnleashSkillManager.Presentation) consomme la file dans LateUpdate (Process(world, deltaTime)), associe chaque handle à l'instance vivante, suit les ancrages et le temps des entités (hitstop : animation à vitesse 0).

    Interface Défaut (Backends/) Remplacer pour
    IEffectPlayer ParticleEffectPlayer (pools par définition) VFX Graph (prévu)
    ISoundPlayer AudioSourceSoundPlayer (pool d'AudioSource) FMOD, Wwise
    ICameraShaker SimpleCameraShaker ; Cinemachine 3 si présent (UnleashSkill.Cinemachine, DefaultPresentationBackends.CameraShakerFactory) Caméra du jeu
    IEntityAnimator PlayablesEntityAnimator (Playables sur l'Animator, mélangé à l'Animator Controller) Système d'animation du jeu
    IIndicatorPlayer LineIndicatorPlayer (contour LineRenderer) Décalques, shaders
    IModuleVisualPlayer ModuleVisualPlayer (prefab du corps d'une ModuleVisualDefinition, pool par prefab, colliders désactivés) Visuel relu à part
    IEntityMover TransformEntityMover (transform du visuel de l'entité, la racine reste immobile) La présentation des déplacements du jeu (chemin, saut)

    DefaultPresentationBackends.Install(system, library) branche les défauts sur les emplacements vides ; un jeu affecte avant (ou remplace) une propriété du système (Effects, Sounds, CameraShaker, Animator, Indicators, ModuleVisuals, Movers). Les résolveurs EntityResolver, EntityTimeScaleResolver, EntityCollector relient les identifiants d'entité aux transforms.

    Effets cachés (visibilité par équipe)¶

    Un piège, une unité invisible : un effet montré à une équipe et pas à l'autre. Les nodes Jouer effet, Jouer son et Tremblement caméra ont un champ Visible To (PresentationVisibility) : Tout le monde (défaut), Équipe du lanceur (seulement les spectateurs de l'équipe du lanceur), Autres équipes. Un visuel de module (ModuleVisualDefinition.VisibleTo, section Visibility) restreint de même toutes ses commandes : prefab du corps joué par la présentation (mode tour par tour), lancement, boucle, impact, expiration. La règle est rapportée à l'équipe du lanceur (SkillTarget.TeamUuid), lue quand le node s'exécute.

    La visibilité voyage avec la commande (PresentationCommand.Audience, un PresentationAudience : visibilité et UUID d'équipe), et le filtre s'applique quand elle est jouée :

    Où Quoi
    PresentationSystem.ViewerTeamUuid UUID d'équipe du joueur local. Une commande de lancement dont le public ne le comprend pas est ignorée (jamais jouée, jamais mise en attente). Null ou vide (défaut) : le spectateur voit tout (spectateur, relecture, solo)
    PresentationSystem.CommandFilter Filtre du jeu, après le public (Func<PresentationCommand, bool>, faux = ignorée) : effets et animations d'une unité invisible (SourceEntityId, TargetEntityId), brouillard de guerre
    PresentationCommand.IsVisibleTo(teamUuid) Même règle, pour ce qui réplique les commandes : un serveur n'envoie à chaque client que ce que voit son équipe
    PresentationCommandBuffer.Audience / AudienceScope(audience) (using) Public ambiant de la file, donné à chaque commande émise dans la portée dont le public propre est tout le monde : ce qu'utilisent les nodes. Une commande à vous peut aussi poser Audience elle-même 
    // Joueur local : les pièges des autres équipes ne s'affichent pas
UnleashSkillManager.Presentation.ViewerTeamUuid = localPlayer.TeamUuid;

// Un effet à vous, montré seulement à l'équipe du lanceur
PresentationCommandBuffer commands = UnleashSkillManager.PresentationCommands;
using (commands.AudienceScope(PresentationAudience.For(PresentationVisibility.CasterTeam, caster.TeamUuid)))
    commands.SpawnEffect(markUuid, PresentationAnchor.InWorld, point, quaternion.identity, 1f, caster.EntityId);

    La simulation ne lit jamais le public : la file émet toutes les commandes (l'observateur les reçoit toutes, avec leur public), la durée de présentation d'une exécution compte aussi les commandes cachées (l'attente du tour par tour est la même pour toutes les équipes), et une commande cachée ne change rien au gameplay. Seules les commandes de lancement sont filtrées : un arrêt ou une mise à jour d'une instance cachée arrive au backend avec un handle qu'il ne connaît pas, sans effet (contrat de IPresentationPlayer.Stop). Le spectateur et le filtre sont lus quand la frame traite la commande : les changer n'arrête pas ce qui joue déjà. UnleashSkillManager.ResetPresentation crée un nouveau système : lui redonner son spectateur. Limite : en mode temps réel, le prefab du corps d'un module est porté par son SkillPrefab (pooler), pas par une commande ; il reste visible de tous : donner à un module caché un effet de boucle plutôt qu'un prefab de corps, ou masquer son SkillPrefab depuis le jeu.

    Tout arrêter¶

    Le système ne suit que les instances qui suivent un ancrage. Ce qu'un backend joue de lui-même (effet ou son ponctuel posé InWorld, visuel ou indicateur dans le monde, secousse de caméra) n'est connu que du backend. Un backend qui implémente IPresentationStoppable (StopAll() : tout arrêter aussitôt, le backend reste utilisable) est appelé pour l'arrêter aussi ; tous les backends par défaut l'implémentent, shaker Cinemachine compris (il n'annule que les impulsions qu'il a émises, pas celles du jeu). L'interface est facultative : un backend à vous qui ne l'a pas continue de marcher, seules ses instances ancrées sont arrêtées, par Stop(handle).

    Appel Effet
    PresentationSystem.StopAll() Arrête les instances suivies, les animations, tout ce que jouent les backends IPresentationStoppable, abandonne les commandes à délai et vide la file. Les backends et leurs pools restent
    PresentationSystem.Enabled = false (UnleashSkillManager.PresentationEnabled) StopAll(), puis la file ignore les commandes (PresentationHandle.None) jusqu'à la réactivation
    UnleashSkillManager.ResetPresentation(système), avec le système courant StopAll() sur lui : le système reste en place
    UnleashSkillManager.ResetPresentation(autre) ou ResetPresentation() Shutdown() du système courant : StopAll(), puis chaque backend IDisposable est libéré (pools détruits). autre le remplace ; sans argument, un nouveau système est créé au prochain accès, d'après la configuration active

    Aucun ne touche au visuel d'un module en temps réel, porté par le SkillPooler : il part avec son module.

    Commandes à délai et relecture (tour par tour)¶

    Une commande peut porter un délai (PresentationCommand.Delay, secondes de présentation) : le système la garde (ScheduledCount, ScheduledDuration) et l'exécute à son heure, en temps de présentation (somme des pas de Process). Une commande qui vise une instance pas encore lancée (arrêt) attend au moins son lancement. Désactiver la présentation vide l'attente.

    Le délai n'est jamais écrit à la main par un node : c'est le délai ambiant de la file (PresentationCommandBuffer.Delay), posé le temps d'une portée par SkillExecution.PresentationAt(délai) (using), qui étend aussi SkillExecution.PresentationDuration. En tour par tour, chaque commande émise par les nodes d'une exécution (démarrage, tour, pas) repousse la fin de sa présentation de son délai plus sa durée propre, lue dans sa définition (effet ponctuel : émission plus durée de vie des particules ; son : clip le plus long ; secousse ; animation sans boucle) : PresentationDuration, et PresentationRemaining une fois lancée par la frame, qu'attend IsTurnReady. Un StopAll met fin à cette attente. SkillExecution.Defer garde le délai de son dépôt : une continuation (résultat de requête sur la sélection) est présentée avec ce qui l'a lancée. En temps réel, le délai reste 0.

    Le projectile résolu sur la sélection (GameObjectModel.ResolveOnSelection) l'utilise : chaque cible est distribuée dans une portée à son heure d'arrivée (distance / vitesse du corps à l'apparition), puis ModuleVisualPresenter.OnReplayed émet SpawnModuleVisual, l'effet et le son de boucle sur un ancrage trajet (PresentationAnchor.Travel(départ, arrivée, durée), position interpolée depuis le lancement de l'instance, disparu à la fin du trajet). Le pooler n'instancie pas son visuel (GameObjectModel.InstantiatesVisual).

    Une zone ou un rayon en tour par tour (GameObjectModel.PresentsVisualInTurns, module porteur dont la logique avance en tours) ont aussi leur visuel joué par la présentation : SpawnModuleVisual dans le monde à la pose du corps (échelle par axe PresentationCommand.AxisScale : la boîte Scale du module multipliée par son échelle de forme, comme celle du pooler en temps réel ; pour une zone, cette boîte n'est pas sa forme : Radius, Width, Angle et la croissance ne s'appliquent pas au visuel), avec l'effet et le son de boucle, replacés quand le corps bouge à un tour. Leur fin (expiration, arrêt du visuel et de la boucle) est émise dans une portée retardée de ModuleVisualDefinition.TurnDisplayDuration après leur dernière activation : une zone instantanée reste visible, et PresentationDuration compte cet affichage. Une Attaque en tours a son visuel joué de la même façon, sans cet affichage en plus : sa fin est déjà relue à la fin de sa récupération.

    Déplacer une entité (relecture)¶

    MoveEntity(entityId, from, to, duration, delay) montre une entité qui va de from à to (repère du monde) en duration secondes de présentation, après avoir attendu delay secondes en from (plus le délai ambiant). C'est de la présentation seule : la commande ne touche ni le monde ni la position de l'entité dans celui-ci. La simulation (le node Dash, le jeu) place l'entité ; la présentation relit son déplacement, pour qu'une unité déplacée par un sort résolu au lancement ne saute pas à sa destination avant l'arrivée du projectile qui la pousse. Présentation désactivée : rien n'est émis.

    Son délai n'est pas un délai programmé : la commande est jouée par la frame qui la traite, et le visuel attend en from pendant le délai, puis avance en ligne droite à vitesse constante. Sa durée compte comme sa durée propre (PresentationDurations) : émise par un node en tour par tour, elle repousse PresentationDuration comme toute commande. Depuis le jeu, après le lancement, SkillExecution.PresentEntityMove(entity, from, to, duration, delay) l'émet et étend la présentation de cette exécution jusqu'à l'arrivée (IsTurnReady l'attend) :

    // La simulation a déjà placé l'unité à sa destination : la montrer y aller après l'impact
if (caster.CastSlot(slot, out SkillExecution execution) == SkillCastResult.Success)
{
    float impact = execution.PresentationDuration;
    execution.PresentEntityMove(unit, previousPosition, unit.transform.position, 0.4f, impact);
}

    Le backend IEntityMover (PresentationSystem.Movers) la joue. Par défaut, TransformEntityMover déplace le transform du visuel de l'entité (VisualResolver ; par défaut le transform du premier Animator sous la racine), puis le rend à sa pose de repos sous l'entité à l'arrivée, ou à un StopAll. La racine, lue par le monde, ne bouge pas. Une entité sans un tel enfant est déplacée par sa racine, laissée à la destination à la fin : le monde lit cette pose le temps du déplacement. Mettre le modèle sous un enfant de l'entité (là où est d'habitude l'Animator) ou régler VisualResolver garde la racine immobile.

    PresentationDurations.OfDefinition(uuid, library) (ou Of(definition), Of(command)) lit depuis le code la durée propre d'une définition : effet ponctuel, son, secousse, animation à sa vitesse ; 0 pour ce qui joue jusqu'à l'arrêt. Pour caler un effet sur la fin d'un autre, ou le delay d'un déplacement, sans constante.

    Animation et gameplay¶

    L'animation ne pilote jamais le gameplay. Les données dont le gameplay a besoin (phases en ticks, trajectoire d'os, root motion) sont extraites dans l'éditeur depuis le clip (AnimationClipExtractor, AnimationExtractedData, inspecteur d'une AnimationDefinition) et lues par le module Attaque sans jouer le clip. Une extraction périmée est signalée (IsStale).

    Ajouter un type de commande¶

    1. Valeur dans PresentationCommandType, champs nécessaires dans PresentationCommand (struct, sans référence managée).
    2. Méthode d'émission dans PresentationCommandBuffer.
    3. Traitement dans PresentationSystem.Process et interface de backend dans PresentationBackends.cs, implémentation par défaut dans Backends/.
    4. Tests EditMode sur les commandes émises (PresentationCommandBuffer.Commands), PlayMode sur la matérialisation.
