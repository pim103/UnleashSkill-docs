    Écrire un node¶

    Model et editor node¶

    Fichier Dossier Assembly Rôle
    [Nom]Model.cs Runtime/Nodes/[Catégorie]/ UnleashSkill Données sérialisées et logique runtime
    [Nom]EditorNode.cs Editor/Graph/Nodes/[Catégorie]/ UnleashSkill.Editor UI dans le graphe

    L'editor node est facultatif : EditorNodeFactory cherche la classe qui dérive de DefaultEditorNode<TModel> pour le type exact du model, sinon il crée un DefaultEditorNode<NodeModel>, qui affiche les champs [ExposedProperty]. La convention du projet reste d'en écrire un (même vide, comme KillEditorNode) ; il devient utile pour un dessin propre (CustomDraw), des ports nommés ou des champs conditionnels.

    Le model ne contient aucun code editor ([SerializeField] oui ; PropertyField, EditorGUILayout non), n'instancie rien (new MonoBehaviour, Instantiate), ne fait aucune requête Physics.*, ne lit jamais Time.deltaTime.

    Attributs¶

    • [NodeInfo("Displayed title", "Category/Displayed title", NodeType.Action)] : titre, chemin dans le menu de création, type (Module, Trigger, Conditional, Support, Action). Une classe [Obsolete] est masquée du menu mais reste ouvrable. Titre et menu s'écrivent en anglais ; l'éditeur les traduit (chaque segment du menu à part) avec les tables de Editor/Localization/.
    • [ExposedProperty] + [SerializeField] + [Tooltip] sur chaque champ réglable. Le tooltip est repris tel quel dans la référence des nodes.
    • Attributs d'affichage (Runtime/Attributes/) : [FoldedOption] (option repliée), [HideIf] / [ShowIf] (champ conditionnel : masqué ou seul affiché quand un champ ou une propriété du model a l'une des valeurs, [ShowIf(nameof(shape), AreaShape.Rectangle, AreaShape.Line)] ; plusieurs conditions se combinent, le champ est masqué si l'une le masque ; résolution commune FieldVisibility, lue par l'éditeur de nodes, l'inspecteur et la référence générée), UUID choisis dans une liste (UuidAttributes.cs, [PresentationDefinitionUuid]), [SimulationLayerName], [UnityLayer], [AnimationBone].
    • Un champ numérique réglable est un ValueSource (fixe, stat, valeur d'exécution, distance, stacks, valeur d'événement, formule), évalué avec Evaluate(caster, context, cible).

    Ports¶

    InitPortType() remplit InputPortTypes et OutputPortTypes (une entrée par port, dans l'ordre) :

    PortType Couleur Usage
    Module Bleu Flux entre modules (Projectile → OnHit)
    Trigger Vert Déclenchement d'actions (OnHit → Dégâts)
    Condition Orange Filtre (Type d'entité, Chance)
    Support Violet Modificateur (Délai, Fork, Répéter, behaviors d'un module)
    Selection Cyan Configuration, pas de flux : sortie « Sélection » du node Sélection de cibles, entrée « Sélection » d'un node qui choisit des cibles (Chain, Fork, Zone, Invocation)

    Un node qui choisit des cibles prend un port Sélection, pas ses propres filtres. Il ajoute InputPortTypes.Add(PortType.Selection) à la fin de ses entrées et lit la Sélection branchée avec TargetSelection.ConnectedTo(this, context) (null : son comportement propre). Il applique les critères à ses propres candidats avec selection.Criteria.Select(candidats, caster, context, centre), ou demande ceux de la source avec selection.CollectCandidates(…) (immédiat, ou requête du monde dont le résultat arrive au tick suivant). Le moteur n'exécute jamais un node dont la sortie Sélection est branchée (SkillGraphModel.IsConfigurationNode), et une connexion Sélection n'est pas une sortie de flux.

    Un node déclare ce qu'il lit et transforme. L'éditeur affiche sur chaque connexion ce qu'elle transporte et signale un node qui lit ce qu'il ne recevra jamais ; il le déduit de deux déclarations du node, lues par GraphFlowAnalysis sans rien exécuter :

    • DescribeFlow(FlowState input, int outputPosition, GraphFlowAnalysis analysis) : ce qu'émet la sortie à outputPosition quand le node reçoit input. Par défaut un passage tel quel ; null pour une sortie de configuration. FlowState est immuable : WithTargets(FlowTargets.ModuleHits, this), WithoutTargets(), WithAim(FlowAim.Targeting, this), WithBranchDirection(this), WithParentBody(this). À redéfinir par un node qui remplace les cibles de ses branches (écouteur, déclencheur, Sélection, Diviser), écrit le point visé, une direction de branche ou un corps.
    • ReadsTargets, ReadsAimPoint, ReadsParentBody : ce que le node lit. Par défaut, déduit de ses champs SkillAnchor / SkillDirection exposés et affichés (ancre « cible reçue » ou « chaque cible reçue », « point visé », « corps du module »). Un node qui agit sur les cibles reçues (dégâts, statut sur la cible) redéfinit ReadsTargets, selon son réglage s'il peut viser le lanceur : public override bool ReadsTargets => base.ReadsTargets || holder == StatusHolderTarget.ReceivedTargets;.

    Avertissements (GraphFlowCodes, repris par le validateur) : W112 agit sur les cibles reçues sans en recevoir (Dégâts derrière le Start), W113 lit le corps du module sans module en amont (écouteur, ancre), W114 Sélection branchée à la fois en configuration et dans le flux, W115 boucle de nodes qui lancent tous leurs sorties pendant leur démarrage (le moteur l'arrête, voir Cycle d'un cast) : un node qui ne les lance que plus tard (écouteur, délai supérieur à 0) redéfinit StartsOutputsDuringStart, selon son réglage au besoin (public override bool StartsOutputsDuringStart => fireImmediately;) ; W116 Au contact de Max Targets 1 sous un module porteur qui dure (Zone d'effet ou Rayon canalisé avec une Duration, Invocation) : sa première cible termine le module. Vocabulaire affiché : cibles reçues, cible de l'événement, point visé, direction de branche, corps du module.

    Plusieurs sorties du même type se distinguent par leur rang : ExecuteChainedNodes(this, caster, context, PortType.Trigger, 1) lance la deuxième sortie Trigger. GetOutputPortLabel(position) nomme une sortie (« Vrai », « Faux »). Un aiguillage (Chance, Vérifier condition) se termine avec CompleteNodeInstanceWithoutOutputs, puis lance la seule sortie choisie.

    Les quatre formes de node¶

    Forme OnStart Fin Exemples
    Instantané Agit, puis CompleteNodeInstance(this, caster), retourne null Immédiate Dégâts, Appliquer statut, Jouer son
    Échec / condition fausse CompleteNodeInstanceWithoutOutputs(this, caster), retourne null Immédiate, sans sorties Condition de stat non remplie, aucune cible
    Persistant Retourne un objet runtimeData CompleteNodeInstance(this, caster, runtimeData) depuis OnSimulationStep Délai, Répéter, Timer
    Écouteur Retourne un runtimeData, s'abonne ExecuteChainedNodes à chaque événement ; se termine sans sorties à la fin de sa durée Sur événement, OnHit, À chaque tick

    Jamais return null sans avoir complété l'instance : la chaîne serait bloquée (signalé dans l'éditeur et en Development Build).

    Une exception levée par un node n'annule que son exécution (voir Cycle d'un cast) : ne pas la rattraper pour la cacher. Une erreur de configuration qui se répéterait à chaque lancement (stat inconnue, pas de configuration) passe par LogConfigurationErrorOnce(message), signalée une fois par node.

    Cycle d'une instance :

    Méthode Appelée Usage
    OnStart(caster, context) Au démarrage, instance déjà enregistrée Logique, retour du runtimeData
    OnSimulationStep(caster, context, runtimeData, clock) À chaque tick du monde (étape 6b), pas au tick de démarrage Compter le temps, échéances
    OnTurnAdvanced(caster, context, runtimeData) Tour par tour : à chaque AdvanceTurn du lanceur, pas au tour de démarrage Compter le temps en tours
    OnRuntime(caster, context, runtimeData) Chaque frame Visuel seulement
    OnEnd(caster, context, runtimeData) Fin normale (si le node l'appelle), annulation, nettoyage Se désabonner, arrêter la présentation, marquer fini

    OnEnd peut être appelé par Cancel ou Cleanup sans que le node ait fini : le runtimeData doit pouvoir être marqué terminé (un indicateur IsFinished, comme dans l'exemple ci-dessous).

    Le temps¶

    Un node persistant hors module avance dans OnSimulationStep avec clock.DeltaTimeFor(entité), l'entité qui porte l'effet :

    • le lanceur pour Délai, Répéter, À chaque tick, Timer, les écouteurs, l'incantation ;
    • la cible pour un DoT, un buff, un tag, une immunité (en pratique, ce sont des statuts, qui avancent seuls dans le StatusStepper).

    Ce pas inclut l'échelle globale, le hitstop global, le temps propre de l'entité (hitstop et échelle par entité) et les zones de temps où elle se trouve. Les échéances se comparent avec SimulationClock.Reached(écoulé, durée) (tolérance d'arrondi : 1/60 ajouté 60 fois donne 0,99999…).

    Tour par tour : un champ de durée garde sa valeur, lue en tours. Au démarrage, si TurnTime.IsActive, convertissez-la (TurnTime.Duration : arrondie au tour supérieur ; TurnTime.Period : cadence entière ≥ 1), retenez-le dans le runtimeData (InTurns), et avancez d'un tour (1f) dans OnTurnAdvanced au lieu de OnSimulationStep, qui ne fait alors rien. Marquez le champ [TurnAware] (TurnUnit.Duration, Period ou VisualOnly) : l'éditeur affiche son unité selon le mode. Un module redéfinit OnBodyTurn (sa durée de vie en tours est comptée par GameObjectModel) ; son OnBodyStep ne tourne plus, sauf s'il redéfinit StepsBodyInTurns pour garder un pas au tick qui ne compte pas le temps (déplacement, présence : SummonModel). Exemple : DelayModel.

    Un node dont l'instance avance encore au tick du monde en tour par tour (un déplacement, un délai compté en secondes) redéfinit HoldsTurn(runtimeData) : tant qu'il rend vrai, le tour de l'exécution n'est pas prêt (SkillExecution.IsTurnLogicResolved, IsTurnReady). Faux par défaut : une instance qui attend des tours, un listener ou un effet durable ne retiennent pas le tour.

    Exemple complet : node persistant¶

    Un « Compte à rebours » qui attend une durée réglable (stat ou formule possibles), au temps du lanceur, puis lance ses sorties si sa branche a encore une cible vivante, et échoue sinon.

    using UnityEngine;
using UnleashSkill.Execution;
using UnleashSkill.Nodes.Attributes;
using UnleashSkill.Simulation;

namespace UnleashSkill.Nodes.Supports
{
    /// <summary>État d'une instance : pur, testable en EditMode sans monde.</summary>
    public class CountdownRuntimeData
    {
        public float Duration { get; }
        public float Elapsed { get; private set; }
        public bool IsFinished { get; set; }   // fin normale, ou annulation (OnEnd)

        public CountdownRuntimeData(float duration) => Duration = duration;

        public bool Advance(float deltaTime)
        {
            Elapsed += Mathf.Max(0f, deltaTime);   // 0 pendant un hitstop
            return SimulationClock.Reached(Elapsed, Duration);
        }
    }

    [NodeInfo("Compte à rebours", "Support/Compte à rebours", NodeType.Support)]
    [System.Serializable]
    public class CountdownModel : NodeModel
    {
        [ExposedProperty]
        [SerializeField]
        [Tooltip("Durée en secondes, au temps du lanceur (hitstop et zones de temps compris)")]
        private ValueSource duration = new ValueSource(2f);

        public ValueSource Duration => duration;

        protected override void InitPortType()
        {
            InputPortTypes.Add(PortType.Trigger);
            OutputPortTypes.Add(PortType.Trigger);
        }

        public override object OnStart(SkillCaster caster, SkillExecutionContext context)
        {
            if (context?.Execution == null)
                return null;   // hors exécution (test isolé) : rien à compléter

            // Évaluée une fois, au départ, avec la première cible de la branche
            float seconds = Mathf.Max(0f, duration.Evaluate(caster, context, context.GetPrimaryTarget()));
            if (seconds <= 0f)
            {
                Finish(caster, context, null);   // durée nulle : se comporte comme un node instantané
                return null;
            }

            return new CountdownRuntimeData(seconds);
        }

        public override void OnSimulationStep(SkillCaster caster, SkillExecutionContext context, object runtimeData, SimulationClock clock)
        {
            if (!(runtimeData is CountdownRuntimeData data) || data.IsFinished)
                return;

            // Le lanceur porte l'attente : son pas, pas celui du monde
            if (!data.Advance(clock.DeltaTimeFor(caster)))
                return;

            data.IsFinished = true;
            Finish(caster, context, data);
        }

        private void Finish(SkillCaster caster, SkillExecutionContext context, CountdownRuntimeData data)
        {
            // Lit les cibles de SA branche, jamais celles d'une autre
            bool hasTarget = context.Targets.Exists(target => target != null && target.isActiveAndEnabled);

            // Plusieurs comptes à rebours du même node peuvent tourner (Répéter → Compte à rebours) :
            // compléter par runtimeData quand il y en a un
            if (hasTarget)
            {
                if (data != null) context.Execution.CompleteNodeInstance(this, caster, data);
                else context.Execution.CompleteNodeInstance(this, caster);
            }
            else
            {
                if (data != null) context.Execution.CompleteNodeInstanceWithoutOutputs(this, data);
                else context.Execution.CompleteNodeInstanceWithoutOutputs(this, caster);
            }
        }

        public override void OnEnd(SkillCaster caster, SkillExecutionContext context, object runtimeData)
        {
            // Appelé aussi par Cancel / Cleanup : ne plus jamais lancer les sorties après
            if (runtimeData is CountdownRuntimeData data)
                data.IsFinished = true;
        }
    }
}

    Points à retenir : CompleteNodeInstance lance les sorties avec le contexte de l'instance (chaque node chaîné reçoit une copie de la branche) ; aucune référence à Time ; l'état vit dans le runtimeData, pas dans les champs du model (le model est partagé par toutes les exécutions du sort).

    Editor node correspondant (Editor/Graph/Nodes/Supports/CountdownEditorNode.cs) :

    using UnityEditor;
using UnleashSkill.Editor.Graph;
using UnleashSkill.Nodes.Supports;

namespace UnleashSkill.Editor.Graph.Nodes.Supports
{
    public class CountdownEditorNode : DefaultEditorNode<CountdownModel>
    {
        public CountdownEditorNode(CountdownModel model, SerializedObject skillGraphObject) : base(model, skillGraphObject)
        {
        }
    }
}

    Écouteurs¶

    Un node à événements :

    • s'abonne dans OnStart (bus du monde : UnleashSkillManager.World.Events.Subscribe(eventUuid, handler), ou ModuleBody.Subscribe pour les impacts d'un module) et retourne son runtimeData ;
    • à chaque événement, crée une branche dédiée (context.CreateBranch()), y ajoute la cible de l'événement, puis ExecuteChainedNodes(this, caster, branche) ;
    • compte sa durée dans OnSimulationStep au pas du lanceur, puis se désabonne et se termine avec CompleteNodeInstanceWithoutOutputs ;
    • se désabonne aussi dans OnEnd (annulation).

    Modèle à suivre : OnGameEventModel (anti-boucle par AddSourceListener / HasSourceListener, nombre max, recharge interne).

    Modules¶

    Un module (Projectile, Zone, Rayon, Invocation, Attaque…) dérive de GameObjectModel :

    • il a un corps simulé (ModuleBody, créé par Spawn(SimulatedBodyDesc)), balayé par le monde ; un module qui détecte lui-même (Zone, Rayon) a un corps porteur (Intangible) et dépose des requêtes ;
    • sa logique avance dans OnBodyStep(caster, context, runtimeData, deltaTime) (étape 2 du tick, pas du corps) ; OnModuleRuntime (chaque frame) est réservé au visuel ;
    • ses sorties sont des écouteurs (OnHit, OnExpire) lancés dès le départ (LaunchOutputs), après quoi il se termine avec CompleteNodeInstanceWithoutOutputs pour ne pas les relancer ;
    • la position vit dans le corps (ModuleBody.Position, MoveTo), jamais dans le transform du SkillPrefab (visuel seul) ;
    • les behaviors branchés en Support (Mouvement, Grossissement) deviennent des IBodyBehavior ;
    • un déplacement de corps passe par une définition de trajectoire (TrajectoryDefinition : segments Ligne, Courbe, Orbite, Poursuite, Retour, dans le repère de la visée) exécutée par TrajectoryRunner, jamais un nouveau behavior de mouvement : à chaque tick, le segment courant calcule le déplacement voulu et le runner fixe la vitesse du corps (balayé par le monde, jamais MoveTo), au pas du corps × échelle de la définition, oscillations ajoutées, glissement et rebond appliqués. Un nouveau segment dérive de TrajectorySegment (données, [Serializable] ; la règle de blocage, son nombre maximal de blocages et les oscillations sont hérités) et rend son état de vol (TrajectorySegmentRun.Step) ; il redéfinit OnBounce s'il tient sa propre direction, OnFrameTranslated s'il vise un point fixe en monde (déplacement forcé). Une hauteur le long de la normale du plan passe par TrajectoryRunner.Rise(delta), qui ajoute le déplacement en 3D et ne décale que le visuel en 2D (SimulatesHeight) ; les règles en vol (Hits In Flight, Ignores Obstacles) sont héritées et appliquées par le runner. Une définition réutilisable va dans la TrajectoryLibrary (node Trajectoire), lue par ConfigurationData.GetTrajectory.

    Crochets de GameObjectModel : CreateRuntimeData, OnSpawned, LaunchOutputs, OnBodyStep, OnModuleRuntime, et les propriétés UsesSimulatedBody, HasIntangibleBody, FollowsCasterTime, HasOwnLifetime. Détections : Monde de simulation.

    Présentation¶

    Un node n'instancie rien et ne tient ni ParticleSystem, ni AudioSource, ni Animator : il émet une commande (voir Présentation). Le gameplay ne dépend jamais du handle rendu.

    Textes affichés dans l'éditeur¶

    Les textes d'un node (titre, menu, tooltips, [Header], libellés de sortie) s'écrivent en anglais dans le model, et se traduisent à l'affichage depuis les tables de Editor/Localization/ (NodeText, EditorLocalization). Tout autre texte affiché par l'éditeur (editor node, drawer, fenêtre) passe par Tr("…") ou TrFormat("… {0}", valeur) (using static UnleashSkill.Localization.Localizer;), avec ses traductions dans une table .po inscrite auprès du Localizer (voir Points d'extension). Les logs et les exceptions restent en anglais, sans Tr.

    Checklist d'un nouveau node¶

    1. Model dans une assembly runtime qui référence UnleashSkill, editor node (si celui par défaut ne suffit pas) dans une assembly éditeur qui référence UnleashSkill.Editor.
    2. Des tests de ses ports et de son comportement : un model s'instancie sans MonoBehaviour, en EditMode.
    3. Un état lu pendant un tick ? Le garder par monde, jamais dans un statique (l'état d'un add-on).
    4. Textes en anglais, leurs traductions dans une table .po inscrite auprès du Localizer (titre, segments de menu, tooltips, libellés de sortie).
    5. Une position ou une direction réglable : un champ SkillAnchor / SkillDirection (sources limitées par [AnchorSources] / [DirectionSources]), résolu par Resolve, jamais un nouvel enum ni une lecture de caster.PointedTarget (lire context.Aim). Son défaut est l'initialiseur du champ, le même pour un node créé dans l'éditeur, construit par code ou lu depuis un JSON.
    6. Ce qu'il lit et transforme : DescribeFlow s'il change les cibles, le point visé, la direction de branche ou le corps de ses sorties, ReadsTargets s'il agit sur les cibles reçues (voir Ports) ; tooltips au vocabulaire « cibles reçues », jamais « cibles de la branche ».
    7. Remplacement d'un ancien node : la classe de l'ancien model passe en [Obsolete] (SearchNodeProvider la retire alors du menu de création), jamais supprimée tant que des assets l'utilisent.
