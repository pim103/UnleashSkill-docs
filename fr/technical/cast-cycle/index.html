    Cycle d'un cast¶

    Version utilisateur : Exécution d'un sort. Ici, le chemin dans le code.

    Vue d'ensemble¶

    SkillCaster / SkillSlots / jeu
        │
        ▼
SkillGraphModel.TryCompute(caster, out execution, options)
        │  CheckCast : graphe valide, blocages, cooldown, coût
        │  new SkillExecution(graph, caster)       ← contexte racine
        │  PayCost, StartCooldown
        │  UnleashSkillManager.RegisterActiveSkillExecution
        ├── incantation ? execution.BeginCast / BeginChargedCast
        │                 (sortie « Pendant l'incantation » du Start, branche IsCastPhase)
        └── sinon       : GameEvents.RaiseSkillCast, puis ExecuteNodeAndChain(StartNode)

Chaque tick du monde (étape 6b)                  Chaque frame (Update du manager)
  ExecutionStepper → execution.Step(clock)         execution.Update()
    incantation, maintien                            node.OnRuntime (visuel seulement)
    node.OnSimulationStep(…, clock)                  AreAllNodesCompleted → IsCompleted
                                                     → execution.Cleanup(), retirée

    Lancement : SkillGraphModel.TryCompute¶

    TryCompute(caster, out execution, options) (Runtime/Execution/SkillGraphModel.cs) :

    1. CheckCast rend un SkillCastResult : InvalidGraph (pas exactement un StartNode, un node dont le type n'existe plus, ou un graphe d'avant la première version ; vérifié avant le coût et le cooldown, signalé une fois par sort), ActionLocked, SkillBlocked (statut qui bloque un tag du sort), AttackInProgress (attaque en phase non annulable), OnCooldown, InsufficientResource. Seul Success lance.
    2. Une nouvelle action annule les attaques du lanceur encore annulables (AttackCancellation.CancelAttacks).
    3. new SkillExecution(this, caster) crée l'exécution et son contexte racine. SkillCastOptions.InitializeContext peut y écrire avant le départ (cible imposée, valeurs).
    4. Coût prélevé et recharge démarrée au lancement, donc au début de l'incantation (rendus si elle est annulée : RefundLaunch).
    5. L'exécution est enregistrée dans le manager, puis démarre : directement, ou par l'incantation.

    SkillCastOptions couvre les cas spéciaux par ses drapeaux (PayCost, CheckCooldown, StartCooldown, CheckLocks, Passive) : ForPassive() (emplacement passif : ni coût, ni recharge, ni blocage), relance gratuite, sort lancé par un autre sort (CastSkillModel). Compute(caster) est un raccourci qui ignore la raison d'un refus.

    Démarrer un node : le moteur ne lance jamais les outputs¶

    ExecuteNodeAndChain (privé) enregistre l'instance puis appelle OnStart, rien d'autre :

    var instance = new ActiveNodeInstance(node, null, caster, context);
instance.StartTick = UnleashSkillManager.TickInProgress;
execution.AddActiveInstance(instance);          // avant OnStart : un node instantané peut se compléter dedans
execution.BeginNodeStart();
try { instance.RuntimeData = node.OnStart(caster, context); }
catch (Exception exception) { execution.Fail(exception, instance); }   // voir Erreurs plus bas
finally { execution.EndNodeStart(); }   // fin du démarrage le plus externe : actions différées (SkillExecution.Defer)

    Les actions différées servent à la résolution instantanée du tour par tour : une requête sur la sélection rend son résultat après l'OnStart qui l'a déposée, jamais pendant. En tour par tour, TryCompute termine l'exécution sans attendre de tick si tous ses nodes le sont (CompleteIfResolved).

    C'est le node qui lance ses sorties :

    Appel (SkillExecution) Effet
    CompleteNodeInstance(node, caster) Termine l'instance la plus récente du node et lance toutes ses sorties
    CompleteNodeInstance(node, caster, runtimeData) Idem, pour l'instance précise qui porte ce runtimeData (plusieurs instances simultanées du même node)
    CompleteNodeInstanceWithoutOutputs(node, caster) / (node, runtimeData) Termine sans lancer : échec, condition fausse, module dont les outputs sont des listeners
    ExecuteChainedNodes(node, caster, context) Lance les sorties sans terminer : un écouteur, à chaque événement
    ExecuteChainedNodes(node, caster, context, portType, rank) Lance une seule sortie (vrai / faux d'une condition)
    ExecuteChainedNodes(node, caster, context, filter) Lance les sorties dont le port passe le filtre (le Start écarte « Pendant l'incantation »)

    Un node qui ne fait ni l'un ni l'autre bloque la chaîne : son instance reste active et l'exécution ne se termine jamais.

    Branches : SkillExecutionContext¶

    À chaque lancement de sorties, chaque node chaîné reçoit sourceContext.CreateBranch() :

    Copié par branche (la fille hérite, les sœurs ne se voient pas) Commun à toute l'exécution (SharedState)
    Targets Caster, Execution
    MainSkillPrefab, MainBody Données SetData / GetData
    ImpactPoint, ImpactNormal, Aim (visée) StartTime
    Données de branche SetBranchData / GetBranchData

    Données de branche nommées : BranchDirection (Fork Spread / Circle, lue par les modules et le Mouvement), BranchSpawnPoint, BranchDamageMultiplier (multiplié par Fork, Chain, Multiplier les dégâts ; appliqué par les nodes de dégâts), BranchMarks (marques comme « Critique », posées par Marquer la branche), IsCastPhase, SpellTargets (sorts ciblés), les listeners sources (anti-boucle des écouteurs).

    Visée (SkillAim, context.Aim) : figée par l'exécution au lancement (fin de l'incantation comprise) depuis caster.PointedTarget, ou donnée par l'appelant (SkillCastOptions.Aim, SkillExecution.SetAim : IA, code, serveur). Elle porte le point visé (Point, nul si rien n'est visé), la direction du lanceur vers ce point (Direction), l'entité pointée (Entity) et la position du lanceur (Origin). La Visée (Ciblage) remplace celle de sa branche (SetAimPoint).

    Ancres et directions : une position configurée sur un node est un SkillAnchor (lanceur, point visé, cible reçue, chaque cible reçue, corps du module, point d'impact, objet nommé ; décalage dans le repère de la visée, portée max), une direction un SkillDirection (vers le point visé, avant du lanceur, vers la cible reçue, depuis le lanceur, aléatoire ; direction de branche prioritaire, décalage d'angle). Une seule résolution : SkillAnchor.Resolve / TryResolve, SkillDirection.Resolve(caster, context, ancre). Le champ limite les sources proposées par [AnchorSources] / [DirectionSources]. Une direction vaut par défaut « vers le point visé », pour un node créé dans l'éditeur comme pour un node construit par code.

    Règles :

    • Un node ne lit jamais caster.PointedTarget : il lit context.Aim. Seuls la Visée et le rayon canalisé (option « Suivre la visée vivante ») relisent la souris, par SkillAim.Live.
    • Une position ou une direction configurée sur un node est un SkillAnchor / SkillDirection, jamais un nouvel enum.
    • Un node lit et filtre les cibles de son contexte, jamais celles d'une autre branche.
    • Lancer ses sorties avec le contexte reçu (ExecuteChainedNodes(this, caster, context)).
    • Un node à événements ajoute la cible de l'événement à une branche dédiée (context.CreateBranch()), pas à son propre contexte (sinon les cibles s'accumulent d'un événement à l'autre).
    • Un module écrit son prefab et son corps dans sa branche (context.MainSkillPrefab, MainBody), que reçoivent ses listeners.
    • SetData sert aux variables du sort (Stocker une valeur) et aux valeurs communes. Une donnée propre à une branche va dans SetBranchData.

    Pendant l'exécution¶

    • Tick du monde (SkillWorld, étape 6b) : ExecutionStepper appelle execution.Step(clock) sur chaque exécution active. Step fait avancer l'incantation et le maintien au pas du lanceur, puis appelle OnSimulationStep sur chaque instance active qui n'a pas démarré pendant ce tick (StartTick). C'est là que comptent les nodes persistants hors module.
    • Tour (tour par tour, SkillCaster.AdvanceTurn) : execution.AdvanceTurn() fait avancer d'un tour une incantation démarrée en tour par tour (CastInTurns ; le tick du monde ne la fait plus avancer) et lance le sort au tour qui atteint sa durée, puis appelle OnTurnAdvanced sur chaque instance active qui n'a pas démarré pendant ce tour.
    • Corps de module : avancés à l'étape 2 du tick (OnBodyStep, voir Écrire un node).
    • Frame (UnleashSkillManager.Update) : execution.Update() appelle OnRuntime (visuel uniquement), puis marque l'exécution terminée si toutes ses instances le sont et qu'elle n'incante plus.

    Fin d'exécution¶

    AreAllNodesCompleted() : aucune instance active. Les écouteurs (Sur événement, À chaque tick), les modules en vol et les nodes persistants la maintiennent en vie. Une exécution terminée est nettoyée (Cleanup : OnEnd des instances restantes, arrêt de la présentation suivie) et retirée au même Update.

    Les effets posés sur une cible (statut, brûlure) vivent dans le StatusContainer de la cible, pas dans l'exécution : la Fireball se termine à l'impact, la brûlure continue.

    Annulation¶

    SkillExecution.Cancel() :

    1. Marque IsCanceled ; pendant l'incantation, rend le coût et remet la recharge à zéro (RefundLaunch), de même pendant une visée.
    2. Marque toutes les instances terminées, puis appelle leur OnEnd, la plus récente d'abord (les listeners avant leur module).
    3. Arrête la présentation suivie (StopAllPresentation).

    Après Cancel, un CompleteNodeInstance ou ExecuteChainedNodes tardif (callback) est ignoré, et ExecuteNodeAndChain ne démarre plus rien.

    Qui annule :

    Appel Cas
    SkillCaster.CancelSkill(graph) / UnleashSkillManager.CancelSkillExecutions Le jeu interrompt une aura, une canalisation
    SkillCaster.CancelSlot(slot) Annulation par emplacement
    SkillCaster.CancelSkillsOnDeath() Mort ou désactivation du lanceur ; épargne les sorts dont CancelOnCasterDeath est faux (les passifs sont toujours annulés)
    SkillExecution.Interrupt() Incantation interrompue (coup reçu, étourdissement selon InterruptionMode)
    CancelTargeting() Visée annulée : le node Ciblage lit la demande (ConsumeTargetingCancel), rend le coût et se termine sans sorties (ce n'est pas un Cancel)

    Hold() / Release() n'annulent rien : ils changent IsHeld, que les nodes concernés lisent à leur pas (Beam stopOnRelease, charge).

    Les effets déjà appliqués restent ; les modules retirent leur corps dans leur OnEnd.

    Erreurs : exceptions et boucles¶

    Une exception levée par un node annule son exécution, et elle seule. Le moteur la rattrape autour de chaque appel du code des nodes : OnStart (dans ExecuteNodeAndChain), OnSimulationStep, OnTurnAdvanced et OnRuntime (par instance), le pas du corps d'un module, ses impacts et ses écouteurs (ModuleBody), le résultat d'une requête d'un node, une action différée, un écouteur de Sur événement. Il :

    1. la signale (Debug.LogException, le sort en contexte) ;
    2. termine l'instance fautive sans sorties ;
    3. annule l'exécution (Cancel), qui garde la première exception dans SkillExecution.Fault.

    Les autres exécutions, la suite du tick (statuts, cooldowns, régénération, combos, blocages, déplacements, historique) et le gestionnaire de tours continuent : TurnReady est toujours levé, une exécution annulée étant terminée. Une exception levée par un OnEnd pendant une annulation est signalée et n'empêche pas les autres instances de se terminer.

    Le monde isole de même ses propres écouteurs (IBodyStepListener, IQueryListener, IBodyHitListener, IWorldStepListener) : une exception va à SkillWorld.ExceptionHandler (Debug.LogException par défaut) et le tick continue avec l'écouteur suivant. Les abonnés de GameEventBus, ExecutionStarted, ExecutionEnded et TurnReady sont appelés un à un : celui qui lève est signalé, les autres sont appelés.

    Une boucle de nodes instantanés est arrêtée. Un node qui lance ses sorties pendant son propre OnStart (node instantané, Délai de 0, premier tir d'un Répéter) imbrique les démarrages : une boucle de tels nodes ne finirait jamais. Au-delà de SkillGraphModel.MaxStartDepth (256) démarrages imbriqués, tous sorts confondus (Lancer un sort), le moteur signale une erreur, refuse tout démarrage jusqu'au retour du plus externe, et annule les exécutions concernées. L'analyse de flux prévient avant : W115 sur chaque node de la boucle (NodeModel.StartsOutputsDuringStart), et l'éditeur refuse de relier un node à lui-même.

    Un node qui ne se termine jamais (il ne rend aucun runtimeData sans appeler CompleteNodeInstance) garde son exécution en vie pour toujours : dans l'éditeur et en Development Build, l'exécution le signale une fois après SkillExecution.StuckInstanceDelay secondes.
