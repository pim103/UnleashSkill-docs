    Architecture¶

    Assemblies¶

    Tout le framework est sous Assets/UnleashSkill/, seul dossier de l'asset.

    Assembly Plateforme Dossier Rôle
    UnleashSkill Toutes Assets/UnleashSkill/Runtime/ Models des nodes, moteur d'exécution, simulation, présentation, configuration
    UnleashSkill.Editor Editor Assets/UnleashSkill/Editor/ Fenêtre du graphe (GraphView), editor nodes, menu principal, inspecteurs, aperçu
    UnleashSkill.Cinemachine Toutes Runtime/Presentation/Cinemachine/ Tremblement par Cinemachine, compilé seulement si le package Cinemachine 3 est présent (versionDefines → UNLEASHSKILL_CINEMACHINE, defineConstraints)

    Dépendances : UnleashSkill.Editor → UnleashSkill. Packages requis : Burst, Mathematics, uGUI. Packages optionnels, détectés par les versionDefines de l'asmdef : Addressables (UNLEASHSKILL_ADDRESSABLES, SkillGraphLoader), Input System (UNLEASHSKILL_INPUT_SYSTEM, SkillTester), Cinemachine 3 (UNLEASHSKILL_CINEMACHINE, assembly à part). Une référence d'asmdef vers un package absent est ignorée par Unity : le code qui l'utilise est sous son define. Aucun pipeline de rendu requis. Votre code référence UnleashSkill (et UnleashSkill.Editor pour du code éditeur) depuis son asmdef.

    Aucune dépendance editor dans le runtime : un usage de UnityEditor dans UnleashSkill est entouré de #if UNITY_EDITOR.

    Aucun chemin Assets/... en dur dans le framework : l'asset peut être déplacé dans le projet de l'utilisateur.

    • Les fichiers de l'interface (uxml, uss de Editor/UI/) se trouvent par GUID : UnleashSkillEditorAssets. Les tables de traduction (Editor/Localization/*.po) se trouvent par le GUID de leur dossier (EditorLocalization.TablesFolderGuid).
    • Les données de l'utilisateur vont dans le dossier des données, UnleashSkillDataFolder.Path : réglage du projet (Project Settings → UnleashSkill, fichier ProjectSettings/UnleashSkillSettings.json), Assets/UnleashSkillData par défaut. La bibliothèque de présentation est dans son sous-dossier Presentation/ (PresentationLibrary.DefaultFolder).

    Namespaces¶

    Les namespaces suivent les dossiers, sous la racine UnleashSkill :

    Dossier Namespace
    Runtime/Core/ UnleashSkill (manager, lanceur, cibles, UnleashSkillVersion, DataFormat) ; sous-dossiers : UnleashSkill.Conditions, .ListenerData, .PersistentDataModel, .SkillUtils, .Stats, .Utils, .Weapons (SkillPrefab/ reste dans UnleashSkill)
    Runtime/Execution/ UnleashSkill.Execution (NodeModel, SkillGraphModel, SkillExecution, contexte, NodeType, PortType)
    Runtime/Nodes/[Catégorie]/ UnleashSkill.Nodes.[Catégorie] (Actions, Behaviors, Conditions, Modules, Supports, Triggers, Utils), plus UnleashSkill.Nodes.Attributes et UnleashSkill.Nodes.Targeting
    Runtime/Simulation/ UnleashSkill.Simulation (décor compris), UnleashSkill.Simulation.Collision
    Runtime/Presentation/ UnleashSkill.Presentation (backends et Cinemachine compris)
    Runtime/Configuration/ UnleashSkill.Configuration
    Runtime/Localization/ UnleashSkill.Localization (Localizer, LocalizationTable, NodeText)
    Runtime/Preview/ UnleashSkill.Preview
    Editor/[Dossier]/ UnleashSkill.Editor.[Dossier] : Graph (fenêtre, EditorNode), Graph.Nodes.[Catégorie] (editor nodes), Graph.Ports, Inspectors, Localization, Migration, Presentation, Preview, PropertyDrawers, UI, Windows, Windows.Modern

    Un type dont un model a besoin (enum, struct) va dans Runtime/, jamais dans Editor/.

    Dans un namespace UnleashSkill.*, un nom simple qui est aussi un namespace frère (Execution, Simulation, Presentation, Editor…) désigne le namespace : qualifier le membre (context.Execution) ou le type (UnityEditor.Editor). L'API publique n'a donc aucun type nommé comme un namespace du framework, ni comme un type courant d'UnityEngine (d'où SimulationProfileStage, et non SimulationStage). Ce qui est public, interne, et les points d'extension : Points d'extension.

    Où vit quoi¶

    Assets/UnleashSkill/Runtime/ :

    Dossier Contenu
    Core/ UnleashSkillManager (singleton global), SkillCaster, SkillTarget, SkillSlots, combos ; Stats/ (EntityStats), SkillUtils/ (SkillPooler), SkillPrefab/, Conditions/, Weapons/, PersistentDataModel/
    Execution/ NodeModel, SkillGraphModel, SkillExecution, SkillExecutionContext, ValueSource, ValueFormula, StartNode, NodeType, PortType, SkillGraphLoader…
    Nodes/[Catégorie]/ Un model par node : Actions, Behaviors, Conditions, Modules, Supports, Triggers, Utils ; Targeting/ (visée, ancres, directions, sélection) ; Attributes/ (NodeInfo, ExposedProperty…)
    Simulation/ SkillWorld, horloge, entités, statuts, pipeline de dégâts, événements, SimulationSandbox ; Collision/ (noyau, CollisionKernel Burst) ; Scenery/ (décor statique : Physics 3D, 2D, aucun)
    Presentation/ Commandes, bibliothèque, définitions, PresentationSystem ; Backends/ : implémentations par défaut
    Configuration/ UnleashSkillConfiguration, ConfigurationManager, ConfigurationData, UnleashSkillDataFolder, définitions configurables (statuts, événements, réactions…)
    Localization/ Langue de l'interface : Localizer (langue courante, Tr), tables gettext, textes des nodes
    Preview/ Aperçu (SkillPreviewManager, SkillPreviewEntity), SkillTester

    Assets/UnleashSkill/Editor/ :

    Dossier Contenu
    Graph/ Fenêtre du graphe (NodeEditor), NodeGraphView, EditorNode, DefaultEditorNode ; Nodes/[Catégorie]/ : editor nodes ; Ports/
    UI/ uxml, uss ; UnleashSkillEditorAssets
    Localization/ Tables de traduction (fr.po), chargement des tables, page Preferences → UnleashSkill
    Windows/ Menu principal (UnleashSkillMainMenu), panneaux de configuration (Modern/), page Project Settings, données par défaut d'un projet neuf (UnleashSkillDefaultData)
    Presentation/, Preview/, PropertyDrawers/, Inspectors/, Migration/ Édition de la présentation, aperçu dans l'éditeur, drawers, inspecteurs (SkillCaster, SkillTester), menus de migration

    Objets centraux¶

    Objet Rôle
    UnleashSkillManager Singleton de scène et façade statique : monde (World), présentation (Presentation, PresentationCommands), exécutions actives, données legacy
    SkillGraphModel Le sort : nodes, connexions ([SerializeReference]), réglages (coût, recharge, incantation, tags). Point d'entrée TryCompute
    SkillExecution Un lancement : instances actives, aléatoire (ExecutionRandom), incantation, annulation
    SkillExecutionContext Une branche de l'exécution : cibles, visée (Aim), données de branche, accès aux données partagées
    SkillAim, SkillAnchor, SkillDirection Visée figée au lancement ; vocabulaire unique des positions et des directions des nodes (Runtime/Nodes/Targeting/)
    SkillWorld Monde de simulation à pas fixe
    PresentationSystem Consomme les commandes de présentation après la simulation
    Localizer Langue de l'interface : source anglaise dans le code, autres langues par des tables, changées sans recompilation

    Ce qui est sérialisé avec le nom d'assembly¶

    Le nom UnleashSkill est écrit dans les données :

    • les graphes (.asset de sort) stockent leurs nodes par [SerializeReference], avec type: {class: …, ns: …, asm: UnleashSkill} ;
    • les comportements de statut (StatusDefinition.behaviors) sont aussi des [SerializeReference].

    Conséquences :

    • Ne jamais renommer l'assembly UnleashSkill, ni déplacer un type sérialisé (model, comportement, struct de champ) vers une autre assembly.
    • Renommer ou déplacer une classe sérialisée par référence (sous-type de NodeModel ou de StatusBehavior) : ajouter [MovedFrom(true, sourceNamespace: "…", sourceClassName: "…")] (UnityEngine.Scripting.APIUpdating) avec l'ancien nom, et ne jamais le retirer dans la même majeure.
    • Une donnée dont la forme change passe par le numéro de format (voir Données).
    • Les rid des références d'un .asset écrit à la main doivent tenir dans un int64 signé (voir Données).
