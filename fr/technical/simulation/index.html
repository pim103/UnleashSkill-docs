    Monde de simulation¶

    Version utilisateur : Monde de simulation.

    Code : Assets/UnleashSkill/Runtime/Simulation/ (assembly UnleashSkill). Le noyau Simulation/Collision/ est du C# pur, au format Burst (structs blittables, tableaux, pas de référence managée dans les données). Pour garder possible un serveur .NET pur, le nouveau code de Simulation/ n'importe pas UnityEngine quand il peut l'éviter.

    Règle d'or¶

    La simulation ne lit jamais la scène, sauf le décor statique (par son backend) et la pose des entités au début du tick. Tout le reste est de la donnée : aucune requête Physics.* dans un node, aucun transform de SkillPrefab lu pour la logique.

    Le tick¶

    SkillWorld est possédé par UnleashSkillManager.World, créé à la première demande avec une copie des SimulationSettings de la configuration active (World.Settings changé par code ne touche jamais l'asset : Où changer un réglage). UnleashSkillManager.Update appelle World.Update(Time.deltaTime) : un accumulateur (FixedStepClock) joue zéro, un ou plusieurs ticks (TickRate, 60 par défaut), plafonnés par MaxTicksPerFrame (les ticks en trop sont abandonnés : le jeu ralentit, DroppedTicks). World.Step() joue exactement un tick (tests).

    Ordre d'un tick (SkillWorld.Step, commentaires numérotés dans le code) :

    1.  Instantané N : pose des entités (hurtboxes), échelle de temps de chaque corps, hitstop
2a. Étapes de simulation des corps (IBodyStepListener : OnBodyStep des modules, behaviors) ; requêtes déposées
2b. Balayages N → N+1 des corps simulés
3-4 Grille reconstruite (couches interrogées seulement), lot exécuté : balayages puis requêtes, contre corps et décor
5a. Résolution des corps simulés (HitPolicy), dans l'ordre des identifiants
5b. Résolution des requêtes ponctuelles, dans l'ordre de dépôt
6.  Continuations des requêtes (ModuleQuery), puis impacts distribués (OnHit…)
6b. Écouteurs d'étape (IWorldStepListener) : exécutions (OnSimulationStep), statuts, blocages, combos, recharges, régénération
7.  Déplacements : une demande par entité (la plus prioritaire), appliquée par son IMovementDriver → pose N+1
8.  Instantané poussé dans BodyHistory
(frame) Le visuel interpole entre les deux derniers états (InterpolationAlpha)

    Contrats à respecter :

    • Pendant un tick, les entités sont immobiles pour la collision (pose relevée à l'étape 1).
    • Les déplacements demandés pendant le tick N (RequestMovement : dash, knockback, attraction) sont résolus à l'étape 7 : une seule demande s'applique par entité, par priorité, sans cumul ; Block (root, stun) gagne sauf contre Forced. La pose réellement atteinte par le Rigidbody ou le CharacterController fait foi.
    • Un node lancé pendant un tick attend le tick suivant pour son premier OnSimulationStep.
    • Résultats triés par temps d'impact (ou distance), puis par identifiant : c'est une spécification de gameplay, couverte par des tests.

    Corps et entités¶

    Élément Code Notes
    Forme Shape (Sphere, Capsule, Box ; requêtes : Ray, Cone, Ring) Décalage local possible
    Corps Body dans BodyStore (SoA, identifiants stables BodyId) Identité : OwnerEntityId, SourceExecutionId, Team (UUID haché)
    Corps simulé AddSimulatedBody(SimulatedBodyDesc) Vitesse, HitPolicy, filtre, listener ; Intangible (porteur), Blocker (mur)
    Entité ISimulationEntity, implémentée par SkillTarget ; SkillEntityRegistry Enregistrée à l'activation ; ses Hurtbox deviennent des corps (capsule par défaut déduite des bounds)
    Déplacement IMovementDriver (CharacterController, sinon Rigidbody, sinon transform) Remplaçable par SkillTarget.MovementDriver
    Décor statique IStaticScenery : PhysicsScenery3D, PhysicsScenery2D, aucun Couches Unity de SceneryLayers ; un seul lot par tick. Le balayage d'un corps porte la normale du plan (SceneryQuery.PlaneNormal) : un backend 3D n'arrête un corps qui longe le plan que là où le décor croise sa hauteur
    Obstacle dynamique Corps de couche Obstacle Mur (support Bloquant), bouclier

    Côté module, ModuleBody enveloppe le corps : Spawn, Position, MoveTo, SetDirection, SetShape, Subscribe(IModuleHitListener), Remove. La forme d'un module est sa boîte Scale, approchée par une capsule (BoxApproximation). Position, Velocity et Rotation sont des types de Unity.Mathematics ; un jeu qui ne référence pas ce package lit WorldPosition, WorldVelocity et Direction (Vector3, voir Sorts → Tester un sort). De même, un corps statique (un mur de test, AddBody) se pose avec Shape.Box(x, y, z), Body.WorldPosition et Body.WorldRotation (float, Vector3, Quaternion ; voir Murs et variantes d'un sort).

    Règles de touche : HitPolicy¶

    Sérialisée dans les nodes (OnHit, modules) :

    Champ Effet
    maxTargets Perçage : 1 = projectile classique, 0 = illimité (toujours borné par DefaultMaxCandidates)
    rehit (Once, EveryTick, Cooldown) + rehitCooldown Retouche d'une même cible (délai en temps du corps)
    blockedByObstacles (Inherit, Yes, No) Surcharge de la matrice des couches pour les obstacles
    requireLineOfSight Rien n'est touché derrière un obstacle

    Détection et résolution sont séparées : le noyau trouve les candidats et leurs temps d'impact, la HitPolicy décide (perçage, retouche, blocage). Une cible refusée par le filtre d'un listener (AcceptsHit) est traversée sans compter.

    Couches¶

    SimulationLayers : Entity (0), Skill (1), Obstacle (2), TimeZone (3), puis jusqu'à 28 couches personnalisées. LayerMatrix (configuration, menu Simulation) donne pour chaque paire Ignore, Touch (événement) ou Block (arrête un balayage). Les filtres de requête (SimulationFilter.ForSkill(lanceur, exécution, team)) écartent le lanceur, la même exécution, ou les alliés (tir ami).

    Requêtes ponctuelles¶

    Pour une détection hors corps (zone instantanée, rayon, rebond de Chain) :

    // Dans le runtimeData : une continuation par instance
var query = new ModuleQuery(caster: caster, context: context, onResult: (world, hits) =>
{
    // Appelé pendant le tick qui exécute la requête (étape 6) ; hits n'est valide qu'ici
    var targets = new List<SkillTarget>();
    ModuleTargeting.CollectTargets(hits, caster, filter, targets);
    // ... remplir une branche, lancer les sorties, ou copier ce qu'il faut garder
});
query.Overlap(world, shape, position, rotation, ModuleTargeting.QueryFilter(caster, context, ignoreCaster: false));
    • Créer la ModuleQuery avec le lanceur et la branche (new ModuleQuery(handler, caster, context)) pour qu'elle marche aussi en tour par tour : elle ne va alors pas au monde, mais rend un contact par entité sélectionnée (TurnBasedSelection ; une règle qui demande la ligne de vue, HitPolicy.RequireLineOfSight, ne garde que celles vues depuis l'origine de la requête, testées contre le décor et les obstacles comme en temps réel), avec une continuation différée à la fin du démarrage (SkillExecution.Defer). Avec followsSelection: false (new ModuleQuery(handler, caster, context, followsSelection: false)), elle passe toujours par le monde, même en tour par tour (contact d'une entité invoquée, boîte de coup d'une attaque, Sélection de cibles). Créée avec le lanceur et la branche, une exception levée par sa continuation annule l'exécution ; le constructeur sans lanceur (hors de toute exécution) la laisse au monde (SkillWorld.ExceptionHandler).
    • ModuleQuery.Overlap, Sweep, Raycast déposent dans le lot ; Pending compte les résultats en attente (un module se termine quand tout est revenu).
    • Déposée pendant l'étape 2 (OnBodyStep), la requête est exécutée dans ce tick ; déposée ailleurs (un OnStart hors tick), elle l'est au tick suivant. Une continuation ne peut pas redéposer pour le même tick.
    • Le QueryHandle et ses résultats ne valent que pendant la continuation : tampons recyclés au tick suivant.
    • ModuleTargeting.CollectTargets convertit les impacts en SkillTarget du registre : ciblables, vivants, filtre de team, coupés au premier blocage.

    Le temps¶

    Notion API
    Pas du monde world.DeltaTime = durée du tick × échelle globale (0 pendant un hitstop global)
    Échelle globale GlobalTimeScale ; TickGlobalScale = échelle du tick en cours
    Hitstop global ApplyHitstop(ticks) : gèle tout, y compris les déplacements (gardés pour le premier tick dégelé)
    Temps propre d'une entité ApplyHitstop(entité, ticks), SetEntityTimeScale(entité, échelle), ResetEntityTime
    Hitstop d'un corps ApplyHitstop(bodyId, ticks)
    Zones de temps AddTimeZone(forme, position, rotation, échelle) ; les échelles superposées se multiplient ; échantillonnées au début du tick
    Horloge des effets SimulationClock : DeltaTime, DeltaTimeFor(entité), Reached(écoulé, durée), Fixed(dt) pour les tests

    DeltaTimeFor(entité) = pas du tick × temps propre × zones de l'entité ; pour une entité portée par un corps (instance de sort), c'est le pas de ce corps. Un corps simulé avance à son propre pas (GetBodyDeltaTime), reçu par OnBodyStep.

    Performance et Burst¶

    Choix de performance :

    • Grille des corps ciblables (GridInsertion.QueriedLayers) : seules les couches qu'une requête du lot accepte sont insérées, reconstruites à chaque tick.
    • Burst sur le chemin chaud (CollisionKernel : grille, phase large, tests de formes, filtre, tri), en appel direct synchrone, mode flottant strict. Un seul code : managé si SimulationSettings.UseBurst est faux ou si la compilation Burst de l'éditeur est coupée. Pas de jobs parallèles.
    • Restent managés : préparation des balayages, résolution des HitPolicy, distribution, zones de temps.
    • SimulationProfile relève le temps de chaque étape d'un tick, pour le profilage dans un build (Diagnostiquer et mesurer).

    Débogage¶

    • SimulationSettings.Debug : warnings (ticks abandonnés, candidats tronqués) et SimulationTrace (tampon circulaire : tick, requête, candidats, impact retenu, règle appliquée).
    • SimulationSettings.Gizmos : corps, dernières requêtes, balayages et impacts dans la vue Scène (SkillWorldGizmos).

    Pour les activer pendant une partie, changer UnleashSkillManager.World.Settings : une copie, la configuration reste telle quelle. Compteurs, profil et ce que garde ResetWorld() : Diagnostiquer et mesurer.

    Points d'extension réseau¶

    ISkillAuthority (LocalAuthority par défaut) décide des impacts ; BodyHistory garde N instantanés pour la lag compensation. Rien n'est branché dans l'asset de base : ce sont les points d'entrée d'une couche réseau (asset dépendant).
