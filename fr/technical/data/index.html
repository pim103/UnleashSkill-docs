    Données¶

    Version utilisateur : Configuration.

    Configuration active¶

    • UnleashSkillConfiguration (Runtime/Configuration/UnleashSkillConfiguration.cs, ScriptableObject) contient tout ce qui est configurable : stats (StatAssets), types de dégâts, teams, tags, types d'entité, templates de stats, réactions et profils de réaction, marques de branche, statuts et catégories, événements libres, tags de sort, réglages de simulation (Simulation), GameplayMode.
    • ConfigurationManager.ActiveConfiguration (statique) est la configuration lue par le moteur. En jeu, UnleashSkillManager charge sa defaultConfiguration à l'initialisation ; sans elle, la configuration active est remise à nul (comme dans un build) : aucune donnée configurée. Dans l'éditeur, c'est celle choisie dans le menu principal (à défaut, celle du projet : la première configuration du dossier des données, sinon du projet, qui remplit aussi la defaultConfiguration d'un manager ajouté à la main dans l'éditeur : UnleashSkillDefaultData.AssignProjectData, sur ObjectFactory.componentWasAdded ; pas par Reset(), que Unity appelle aussi pour un AddComponent par code).
    • Données par défaut (Editor/Windows/UnleashSkillDefaultData.cs) : à la première ouverture de l'éditeur (une fois par session, pas en mode batch), un projet sans aucune configuration en reçoit une dans le dossier des données (UnleashSkillConfiguration.asset : teams Player et Enemy, type Character, stats HP, Mana, Attack sous Stats/, template Default) ; sans bibliothèque de présentation, une vide est créée sous Presentation/ ; sans bibliothèque de trajectoires, une vide est créée (TrajectoryLibrary.asset). Rien n'est écrasé.
    • PresentationLibrary.Active et TrajectoryLibrary.Active (globales, partagées par toutes les configurations) sont affectées par le manager ; nulles, l'éditeur prend la bibliothèque du dossier des données (UnleashSkillDefaultData.ProjectPresentationLibrary / ProjectTrajectoryLibrary). Le build donne ces mêmes bibliothèques aux managers de scène dont le champ est vide (UnleashSkillBuildLibraries, IProcessSceneWithReport, copie construite seulement) et avertit si le projet n'en a pas ; un manager qui démarre sans bibliothèque avertit.

    Les graphes de sorts dans un build¶

    • Un graphe référencé par un champ sérialisé (un champ SkillGraphModel de votre script, les emplacements d'un SkillCaster) est inclus dans le build par Unity comme tout asset référencé : rien à faire.
    • Un graphe cherché par son nom passe par SkillGraphLoader (SkillGraphLoader.Instance.GetSkillGraph(nom), GetAllGraphs()), qui charge tous les graphes à son démarrage :
      • sans le package Addressables : les graphes des dossiers Resources (Resources.LoadAll), d'un coup ;
      • avec Addressables installé, le chargeur bascule sur les graphes qui portent le label Addressables SkillGraph, chargés de façon asynchrone (IsLoaded passe à vrai à la fin). Les dossiers Resources ne sont plus lus : installer Addressables dans un projet qui gardait ses graphes dans Resources vide le chargeur, jusqu'à ce que les graphes soient marqués Addressables avec le label SkillGraph (et le contenu Addressables construit).
    • La configuration et les bibliothèques de présentation et de trajectoires sont référencées par le UnleashSkillManager de la scène (voir plus haut), jamais chargées par un chemin.

    Lire une donnée : ConfigurationData¶

    Toujours passer par ConfigurationData (Runtime/Configuration/ConfigurationData.cs) : GetTeam, GetEntityType, GetStat, GetStats, GetDamageType, GetTag, GetStatTemplate, GetReaction(s), GetBranchMark(s), GetEvent(s) (natifs compris), GetSkillTag(s), GetStatus(es), GetStatusCategory(ies), GetReactionProfile.

    • La configuration active est la seule source : un UUID absent de la configuration rend null.
    • Sans configuration active : null et listes vides, sauf les valeurs par défaut du code (formule de dégâts, réactions, marques, statuts et catégories, événements natifs).
    • La base JSON legacy et UnleashSkillManager.GetDataByUuid sont retirées.

    Comparer par UUID¶

    Les models et les données stockent des UUID (chaînes), pas des références :

    • teams : SkillTarget.TeamUuid, SkillTarget.SameTeam(a, b) (un SkillPrefab a la team de son lanceur) ;
    • types d'entité : EntityType.InheritsFrom(typeUuid, wantedUuid, getType) (hiérarchie comprise) ;
    • résoudre l'objet (Team, EntityType, CustomStat) seulement pour lire ses propriétés.

    Dans un model, un champ d'UUID est décoré pour que l'éditeur affiche une liste ([DamageTypeUuid], [GameEventUuid]…, dans Runtime/Attributes/). Les définitions de présentation suivent la même règle (UUID de la PresentationLibrary).

    Les noms des données par défaut du code (statuts, catégories, réactions, marques, étapes de la formule de dégâts, événements natifs) sont en anglais depuis la 1.0. Les données déjà créées dans une configuration gardent leurs noms : seules les nouvelles configurations reçoivent les noms anglais.

    UUID fixes : les natifs d'événement (event-hit…) et quelques statuts d'une configuration neuve (StatusDefinition.StunnedUuid = status-stunned, référencé par la réaction Étourdissement) sont des constantes du code. Ne jamais les changer.

    Migrations¶

    Le projet migre sans casser les assets existants :

    • [Obsolete] sur les anciennes signatures et les anciens nodes : jamais supprimés tant que la migration n'est pas complète. Les classes de model obsolètes sont masquées du menu de création, mais s'ouvrent encore.
    • Étape de migration : un champ dont la forme change est converti par une étape du format des données (ci-dessous), jamais par un indicateur rangé à côté du champ : un node construit par code ou lu depuis un JSON (JsonUtility) reçoit les mêmes valeurs qu'un node chargé depuis un asset.
    • Champ sérialisé renommé : [FormerlySerializedAs("ancienNom")] (attribut Unity, pas encore utilisé dans le projet), ou garder l'ancien nom et migrer à la lecture.
    • Type sérialisé ([SerializeReference]) : ne pas changer son assembly ; un nom ou un namespace changé prend un [MovedFrom] (voir Architecture).

    Format des données¶

    SkillGraphModel, UnleashSkillConfiguration, PresentationLibrary et TrajectoryLibrary portent un numéro de format (formatVersion, caché dans l'inspecteur ; CurrentFormatVersion dans le code). Un asset créé en mémoire prend le format courant.

    • À l'ouverture (OnEnable), UpgradeFormat() applique les étapes de migration une à une jusqu'au format du code (DataFormat.Upgrade), puis marque l'asset modifié : il est réécrit à la prochaine sauvegarde, ou tout de suite par UnleashSkill → Migration → Data format.
    • Format plus récent que le code (asset d'une version plus récente d'UnleashSkill) : avertissement dans la console, aucune migration, jamais réécrit : tout enregistrement (Ctrl+S, Save Project, AssetDatabase.SaveAssets) l'exclut, si bien que ses champs inconnus sont gardés ; le Node Editor affiche un tel graphe désactivé (lecture seule).
    • Graphe de sort plus ancien que SkillGraphModel.MinimumFormatVersion (données d'avant la première version) : erreur dans la console, aucune migration, aucune écriture (DataFormatStatus.Unsupported) ; le sort ne se lance pas (InvalidGraph) et le Node Editor l'affiche en lecture seule. Une configuration ou une bibliothèque au format 0 (enregistrée avant l'existence du numéro de format) a les mêmes champs qu'au format 1 : elle est chargée et passée au format 1.
    • Identifiants des nodes : un node dont l'identifiant manque ou est déjà pris par un autre node du graphe (deux versions d'un graphe fusionnées) en reçoit un nouveau au chargement, avec un avertissement ; les connexions restent sur le premier node de cet identifiant (SkillGraphModel.RepairNodeIds).
    • Une étape ne touche que les données de l'asset (pas d'API de l'éditeur : elle peut s'exécuter pendant un chargement) et doit rester correcte sur un asset neuf (créé en mémoire, puis mis au format courant).
    Asset Format courant
    SkillGraphModel 2 (plus ancien format lu : 2)
    UnleashSkillConfiguration, PresentationLibrary, TrajectoryLibrary 1

    Un nouveau format ajoute son étape dans l'UpgradeFormat de l'asset.

    Nodes hors asset. Un node n'a aucun défaut propre à l'éditeur : le menu de création du Node Editor, un node construit par code (new AreaModel()) et un node lu par JsonUtility (les champs absents gardent la valeur de leur initialiseur) sont identiques. Une direction vaut par défaut « vers le point visé », qui se replie sur l'avant du lanceur sans point visé.

    La version de l'asset et de l'API publique est UnleashSkillVersion (SemVer) : Current, ApiVersion, et IsApiCompatible(version) pour un asset dépendant.

    Tables de traduction¶

    Les textes de l'interface ne sont pas des données des sorts : le texte anglais est écrit dans le code, les autres langues sont des fichiers gettext de Editor/Localization/ (fr.po), lus par EditorLocalization et enregistrés auprès du Localizer.

    • Un msgid est le texte anglais exact du code (échappements décodés) ; msgctxt distingue deux sens d'un même texte (event pour les noms d'événements natifs) ; msgstr est la traduction. Un texte anglais modifié perd sa traduction jusqu'à la mise à jour de la table.
    • Les textes formatés utilisent des repères {0}, {1} (TrFormat), gardés dans la traduction.
    • La langue est une préférence de l'éditeur par utilisateur (EditorPrefs, clé UnleashSkill.Language) ; en build, sans table, les textes restent en anglais.

    Assets écrits à la main¶

    Un sort est un .asset YAML, qui peut être écrit ou modifié à la main (génération, fusion). Les nodes y sont des references.RefIds :

    references:
  version: 2
  RefIds:
  - rid: 8500000000000010001
    type: {class: DamageSimpleModel, ns: UnleashSkill.Nodes.Actions, asm: UnleashSkill}

    rid sous l'int64 signé

    Chaque rid doit rester sous 9 223 372 036 854 775 807. Utiliser des préfixes en 85…, 87…, 88… (19 chiffres), jamais 93… ou plus : l'éditeur plante à l'import (StringToIntCheckedSInt32), à chaque relance, sans message clair. En cas de plantage au démarrage, lire %LOCALAPPDATA%/Unity/Editor/Editor.log (« Failed to convert … in file … »).

    Après une modification à la main : ouvrir le sort dans le Node Editor et le tester dans l'aperçu.
